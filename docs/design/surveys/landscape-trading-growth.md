# Landscape survey: trading agents and growth (marketing / sales / social) agents

Purpose: inform the TRADING sector and the GROWTH sector (marketing, sales, social media, comms) of the aos-kernel agent fleet without violating CLAUDE.md invariants (policy gate on every tool call, default deny, `irreversible` => human, tainted runs cannot write without a human, agents never hold credentials, ephemeral agents bounded by their template, the model never makes an access-control decision).

Date: 2026-09-20. Scope: web survey plus one local reference clone (`refs/eliza`, already surveyed in `survey/eliza.md`; only the wallet/trade gate is re-cited here).

# Part A. Crypto / stock trading agents

## A1. TradingAgents (TauricResearch)

**What it is.** "TradingAgents is a multi-agent trading framework that mirrors the dynamics of real-world trading firms." Apache-2.0. CONFIRMED https://github.com/TauricResearch/TradingAgents

**Roles / pipeline.** Analyst team (Fundamentals, Sentiment, News, Technical) -> Researcher team ("both bullish and bearish researchers who critically assess the insights provided by the Analyst Team") -> Trader agent -> Risk Management ("evaluates portfolio risk continuously") -> Portfolio Manager ("approves/rejects transaction proposals"). Providers: OpenAI, Google, Anthropic, xAI, DeepSeek, Qwen, GLM, MiniMax, OpenRouter, Mistral, Kimi/Moonshot, Groq, NVIDIA NIM, Ollama, Azure OpenAI, AWS Bedrock. CONFIRMED (README).

**Safety and risk controls.** No live execution: "Orders are sent to a simulated exchange"; "designed for research purposes ... not intended as financial, investment, or trading advice." Changelog notes "Alpha Vantage look-ahead filtering" and "look-ahead / point-in-time fixes" (v0.3.1, v0.4.0), i.e. they had look-ahead leakage in earlier versions and had to patch it. Data: SEC EDGAR "as filed", Yahoo Finance, FRED, Alpha Vantage, StockTwits, Reddit. CONFIRMED (README). Paper: arXiv 2412.20138 (egress-blocked; INFERRED (snippet)).

**Execution model.** Decision-only pipeline; the LLM roles debate and a PM role signs off, but nothing places orders. CONFIRMED.

**Take.** The bull/bear adversarial pair and the separate "risk" and "approve/reject" roles are a clean *research* topology: analysts produce claims with sources, an adversary attacks them, a risk role scores exposure, and a final role produces a recommendation. This maps onto aos-kernel as ephemeral `scout` (analyst) + `checker` (bear) runs under a standing `trading-research` agent that ends at a *recommendation event*, never at an order.
**Leave.** Treating the LLM "Portfolio Manager approves/rejects" as an access-control decision. In aos-kernel the PM role can only emit a proposal; approval is the human via the control plane (invariant 3). Also: their look-ahead patches are a warning that any backtest built from LLM-visible data leaks unless point-in-time is enforced in the data layer.

## A2. ai-hedge-fund (virattt)

**What it is.** "An AI Hedge Fund Team", MIT, ~51.7k stars (INFERRED (snippet) https://www.kucoin.com/news/flash/ai-hedge-fund-buffett-and-munger-agents-go-open-source-on-github). README: "This project is for **educational and research purposes only**", "Not intended for real trading or investment", "Note: the system does not actually make any trades." Investor agents are "pluggable, backtestable 'alpha models'"; needs "A Financial Datasets API key, for prices, fundamentals, and earnings." CONFIRMED https://github.com/virattt/ai-hedge-fund

**Roles / pipeline (VISION.md).** Research Analysts = "Alpha models — LLM investor agents _and_ quant models" (personas: "Warren Buffett, Charlie Munger, Peter Lynch, Stanley Druckenmiller, …" as "stylized approximations"); Portfolio Manager converts views to target positions; **Chief Risk Officer** = "Risk model that enforces hard limits analysts cannot override"; CIO/Capital Allocator; Trading Desk; Back Office ledger of "positions, P&L, and every decision." CONFIRMED https://github.com/virattt/ai-hedge-fund/blob/main/VISION.md

**Safety and risk controls.** The single most transferable sentence in this whole survey: "**The LLM never touches the trade.** Language models form _views_ and _narrate_ decisions. Deterministic code sizes positions and places orders." Plus "Paper before real, always. Live trading is opt-in and off by default." CONFIRMED (VISION.md).

**Take.** (1) LLM = view + narration; deterministic code = sizing + order. (2) A risk layer "analysts cannot override" is exactly the kernel policy gate + hard budget caps; in aos-kernel it is implemented in TypeScript, not in a prompt. (3) Back-office ledger of "every decision" = our hash-chained event log; each persona verdict should be an event with its sources.
**Leave.** Persona role-play as a source of alpha (see A10: no evidence it works out of sample). Use personas, if at all, as diversity of *questions asked*, not as signal.

## A3. FinRL (AI4Finance-Foundation)

**What it is.** "the first open-source framework for financial reinforcement learning", MIT. Three layers: Market Environments (Gym-style), DRL Agents (A2C, DDPG, PPO, SAC, TD3), Financial Applications (stock trading, crypto, portfolio allocation). "Basic Alpaca support" for paper/live; FinRL-X advertised as "Full multi-account integration + risk controls". Disclaimer: "Nothing herein constitutes financial advice or a recommendation to trade real money." CONFIRMED https://github.com/AI4Finance-Foundation/FinRL . Alpaca paper-trading deployment tutorial: INFERRED (snippet) https://alpaca.markets/learn/data-scientists-approach-algorithmic-trading-using-deep-reinforcement-learning

**Take.** The env/agent/app separation and the "paper-trading endpoint first" deployment path. Not an LLM system; relevant only as the shape of a *non-LLM* strategy runner that a `trading-ops` agent could supervise (start/stop/read PnL) without ever being the strategy.
**Leave.** DRL strategies themselves; out of scope for a single-operator kernel and the same backtest-bias caveats apply.

## A4. Hummingbot

**What it is.** Open-source market-making / arbitrage bot framework. Kill switch: "Automatically stops the bot when it reaches a certain performance threshold, which can be either positive or negative." Params `kill_switch_enabled`, `kill_switch_rate` ("negative values represent losses, e.g., -5 = 5% loss"); triggers on the performance calculation "even without new trades occurring"; on trigger the client prints "Kill switch triggered" / "Stopping the bot...". CONFIRMED https://github.com/CoinAlpha/hummingbot-docs/blob/master/content/features/kill-switch.mdx (legacy docs mirror). Current docs: `config kill_switch_mode`, `kill_switch_mode.kill_switch_rate`; `stop` "stops the running strategy and cancels all active orders"; `paper_trade` mode with preset balances, "Exchange APIs are not required to run the bot on paper_trade". INFERRED (snippet) https://hummingbot.org/client/global-configs/kill-switch/ , https://hummingbot.org/client/global-configs/paper-trade/ , https://hummingbot.org/client/start-stop/

**Take.** A kill switch that is *mark-to-market* (fires on price moves, not only on new fills), configured as data and owned by the runtime, not the strategy. Also: paper mode that needs no exchange key at all.
**Leave.** Note the kill switch *stops* the bot; whether it flattens is a separate decision (see A12 on kill switch semantics).

## A5. freqtrade

**What it is.** Open-source crypto bot with strategy plugins. `dry_run`: "the bot does not engage your money. It only runs a live simulation without creating trades on the exchange"; in dry-run "only Read-Only operations (i.e. operations that do not alter account state) on the exchange are performed"; `dry_run_wallet` simulated balance; `max_open_trades` mandatory; `stake_amount`; `tradable_balance_ratio` default 0.99; docs recommend "starting the bot in the Dry-run mode". CONFIRMED https://github.com/freqtrade/freqtrade/blob/develop/docs/configuration.md

**Protections (circuit breakers).** `StoplossGuard` "Stop trading if a certain amount of stoploss occurred within a certain time window"; `MaxDrawdown` "Stop trading if max-drawdown is reached"; `LowProfitPairs` "Lock pairs with low profits"; `CooldownPeriod` "Don't enter a trade right after selling a trade". Parameters `lookback_period[_candles]`, `stop_duration[_candles]`, `trade_limit`; each can be configured multiple times. "Protections are supported by backtesting and hyperopt, but must be explicitly enabled by using the `--enable-protections` flag." CONFIRMED https://github.com/freqtrade/freqtrade/blob/develop/docs/includes/protections.md

**Take.** The protections vocabulary is a ready-made schema for a kernel-side `trading` policy: consecutive-stop guard, max-drawdown halt, per-symbol lockout, cooldown after exit. The "must be explicitly enabled in backtest" note is itself a lesson: backtests that omit the live guards overstate results.
**Leave.** Strategy-file-defines-its-own-stoploss; in our design limits live in config the agent cannot edit.

**What it is.** "Free open source crypto trading bot to automate AI, Grid, DCA and TradingView strategies on Binance, Hyperliquid and 15+ exchanges", GPL-3.0-or-later. "risk-free paper trading", built-in backtesting, ChatGPT/Ollama "AI trading bot" mode, TradingView webhook automation. Disclaimer: "USE THE SOFTWARE AT YOUR OWN RISK"; "start by running a trading bot in simulation mode and do not engage money before you understand how it works." CONFIRMED https://github.com/Drakkar-Software/OctoBot

**Leave.** "ChatGPT predictions" as strategy; no published out-of-sample evidence.

## A7. Jesse

**What it is.** "advanced crypto trading framework" (MIT). Backtest "without look-ahead bias", paper trading, live trading (plugin), Telegram/Slack/Discord notifications, and "a local Model Context Protocol (MCP) server" for AI assistants to help with strategy development and backtesting. Disclaimer: "This software is for educational purposes only." CONFIRMED https://github.com/jesse-ai/jesse

**Take.** The MCP-server-for-backtesting pattern: the LLM assists *research* (write strategy, run backtest, read metrics) through an MCP surface, while live trading is a separately-installed plugin. For aos-kernel, a backtest MCP server would be classified in `tool-views.yaml` as `read`/`write-sandbox`, and the live-trading tools as a distinct server with `irreversible` submit tools.

## A8. elizaOS `plugin-wallet` (local clone, DeFi / trading gate)

**What it is.** Wallet plugin with EVM + Solana swaps/bridges/LP, pump.fun buys, x402 micropayments, and steward-backed `TRADE_ORDER` for Hyperliquid/Polymarket. Backends: "`local` — raw EOA private keys from environment variables or the OS keychain" or "`steward` — multi-tenant Steward signing service". CONFIRMED `eliza/plugins/plugin-wallet/README.md` lines 48-60.

**Safety.** "All write operations default to `mode=prepare` (stages the transaction but does not sign or send). The agent asks the user to confirm before submitting. `dryRun=true` returns metadata without signing. `mode=simulate` ... needs only the wallet's public key, never a private key, so it cannot authorize or lead to a live submission and it skips the confirmation gate entirely." CONFIRMED README line 19. Spend caps: `X402_GLOBAL_DAILY_LIMIT`, `X402_PER_REQUEST_MAX` (README lines 77-78). Trade confirmation "binds one idempotency key to a logical order before the user sees the first confirmation prompt", TTL 5 min (`src/security/trade-confirmation.ts` lines 1-17). Injection guard blocks "Wallet transfers, swaps, bridges, pump.fun buys, governance votes, liquidity operations, and trade orders ... suspected prompt injection in untrusted channel content" (`src/security/wallet-context-safety.ts` line 154, GHSA-gh63-5vpj-39qp). CONFIRMED. The attack that motivated it: Patlan et al., "Real AI Agents with Fake Memories" (arXiv 2503.16248) memory-injection against ElizaOS (INFERRED (snippet), see `survey/eliza.md`).

**Take.** Three-mode verbs (`simulate` needs no key and skips the gate; `prepare` stages; `submit` requires confirmation), idempotency key minted *before* the confirmation prompt, daily + per-request caps, and injection guard that denies the whole write class when a message is from an untrusted channel. All four map one-to-one onto our tool-view risk classes plus taint.
**Leave.** `local` backend with raw private keys in env/keychain of the agent process (violates invariant 2); memory shared across sessions without provenance (the CrAIBench attack surface).

Season 1.5 ran on US equities and ended Dec 3, 2025; "As of August 6, 2026 the site's own banner still says the models are no longer running"; no Season 2 posted. INFERRED (snippet) https://www.iweaver.ai/blog/alpha-arena-ai-trading-season-1-results/ , https://finance.biggo.com/news/5BSX_Z0BaoGGrU-ID27J , https://protos.com/llm-crypto-trading-contest-finds-llms-cant-trade-crypto/ , https://www.traderank.ai/blog/alpha-arena-alternatives-2026 , https://www.euclideanai.com/blog/llm-crypto-trading

## A10. What the evidence says LLM trading agents are good at, and not

**Not alpha generation (out of sample).**
* FINSABER (KDD 2026, Li, Kim, Cucuringu, Ma): "most evaluations of LLM timing-based investing strategies are conducted on narrow timeframes and limited stock universes, overstating effectiveness due to survivorship and data-snooping biases"; with "20 years of multi-source data ... 100+ symbols" and mitigation of "survivorship, look-ahead, and data-snooping biases", "previously reported LLM advantages deteriorate significantly"; "LLM strategies are overly conservative in bull markets, underperforming passive benchmarks, and overly aggressive in bear markets, incurring heavy losses." INFERRED (snippet) https://arxiv.org/abs/2505.07078 ; code CONFIRMED exists at https://github.com/waylonli/FINSABER (README has no results).
* Bias survey (arXiv 2602.14233): "Look-ahead bias, survivorship bias, narrative bias, objective bias, and cost bias are recurring problems in financial LLM systems ... yet no single bias is discussed in more than 28 percent of studies reviewed from 2023 to 2025." INFERRED (snippet) https://arxiv.org/html/2602.14233v1
* Training-window contamination: "A state-of-the-art LLM with a 2025 cutoff has already seen how NVIDIA, Microsoft, and Netflix moved during 2010–2020, so any backtest overlapping the training window inherits an additional bias that lives inside the model's weights and is invisible to data-pipeline audits." INFERRED (snippet) https://paperswithbacktest.com/course/look-ahead-bias-llm-trading . Corollary for us: only post-cutoff, paper-traded, forward evaluation counts.
* Backtrader-Bench (arXiv 2608.11232): on separately mined questions "half the models falling to roughly random-chance level (25%)" without tools. INFERRED (snippet) https://arxiv.org/html/2608.11232
* Production record, DXRG "What LLM Trading Agents Actually Do in Production" (arXiv 2609.05663, Sept 2026): two fleets (DX Terminal Pro, 3,505 vaults, Feb 26 - Mar 18 2026; DXAP, 500-599 agents on Hyperliquid perps, Jun 8 - Aug 15 2026; "231,638 finalized turns and 14,596 fills"). Findings: "A risk slider explains leverage (+0.425 per level)"; "a nine-row leaderboard rendered in the prompt routes 46.5% of all trade entries"; "Median leverage is 5.0x in every volatility sextile across a 5.7x volatility spread" (sizing is volatility-blind); "43.2% of positions touched +300 bps of open profit within 24h; 49.3% of those still closed negative; median capture was 2.0%"; "a fixed 2%/4% bracket beat every discretionary exit we measured, +39.0 bps per position"; three frontier models "tied on decision quality" but "choice consistency differed sharply (35% vs 90%+ flip rate)". CONFIRMED https://github.com/ProjectDXAI/continuous-record-llm-trading-agents ; "The DXAP fleet is not profitable and trails a matched Hyperliquid retail benchmark (41% vs. 50% roundtrip win rate)" INFERRED (snippet) https://arxiv.org/abs/2609.05663
* Agent Market Arena, "When Agents Trade" (arXiv 2510.11695): live crypto + stock benchmark, agents InvestorAgent / TradeAgent / HedgeFundAgent / DeepFundAgent over GPT-4o, GPT-4.1, Claude-3.5-haiku, Claude-sonnet-4, Gemini-2.0-flash; "agent frameworks display markedly distinct behavioral patterns ... whereas model backbones contribute less to outcome variation." INFERRED (snippet) https://arxiv.org/abs/2510.11695

**Good at (supported).**
* Research synthesis with sources: the entire TradingAgents / ai-hedge-fund value is the analyst layer (EDGAR filings, news, macro) turned into a structured, cited brief (A1, A2, CONFIRMED). GPT-Researcher's "Aggregate over 20 sources for objective conclusions" is the same skill (B1, CONFIRMED).
* Event monitoring and classification: TradingAgents' News Analyst "monitors global news and macroeconomic indicators, interpreting the impact of events" (CONFIRMED README) is a classification task, which LLMs do reliably; Agent Market Arena uses "expert-checked news" as an input, not an output (INFERRED (snippet)).
* Strategy-development assistance through an MCP surface: Jesse's local MCP server for "strategy development and backtesting" (CONFIRMED A7).
* Operating-layer design matters more than prompt text: DXRG shows the slider, the leaderboard rendering, and a mechanical bracket dominate outcomes (CONFIRMED). Translation: put risk in deterministic kernel code and rendered state; do not expect prompt wording to hold a limit.

**Design conclusion for the fleet.** A `trading` sector whose agents (a) research and monitor, (b) propose, (c) run and supervise *deterministic* strategies in paper mode by default, and (d) never hold a key and never call a live `submit_order` tool without `irreversible` human approval, is consistent with all the evidence above. An LLM that "trades" discretionary size and exits is not.

## A12. Risk-control patterns serious systems use

* **Paper first, opt-in live.** ai-hedge-fund "Paper before real, always. Live trading is opt-in and off by default" (CONFIRMED A2); freqtrade dry-run does only read-only exchange calls (CONFIRMED A5); Hummingbot paper mode needs no key (INFERRED A4); Hyperliquid `--testnet` (CONFIRMED A11).
* **Trade-only keys, withdrawal disabled, IP allowlist.** Coinbase "never enable 'Transfer' or 'Withdraw' permissions for trading bots" (INFERRED (snippet) https://dev.to/hamd_writer_8c77d9c88c188/how-to-use-binance-coinbase-apis-for-automated-crypto-trading-complete-step-by-step-guide-2jj); Binance minimum = read + trade + IP whitelist (INFERRED A11); Hyperliquid API wallets structurally cannot withdraw (CONFIRMED A11); IBKR Trusted IPs + Read-Only default (INFERRED A11). In aos-kernel the key lives in the pmmcp vault and is injected only at the egress proxy (invariant 2), so the IP allowlist is the proxy's egress IP.
* **Pre-trade limits in the runtime, not the strategy.** IBKR precautionary settings (size, value, % off market) (INFERRED A11); FIA "Best Practices for Automated Trading Risk Controls and System Safeguards" (2024) names "projected position limits, a daily-loss rule, duplicate checks, trading windows, and an order-count limit" (INFERRED (snippet) https://www.fia.org/sites/default/files/2024-07/FIA_WP_AUTOMATED%20TRADING%20RISK%20CONTROLS_FINAL_0.pdf); freqtrade `max_open_trades`, `stake_amount`, `tradable_balance_ratio` (CONFIRMED A5); eliza `X402_GLOBAL_DAILY_LIMIT` / `X402_PER_REQUEST_MAX` (CONFIRMED A8).
* **Circuit breakers.** freqtrade StoplossGuard / MaxDrawdown / CooldownPeriod / LowProfitPairs (CONFIRMED A5); Hummingbot mark-to-market kill switch (CONFIRMED A4); "Daily loss limits ... typically set at 2% to 3% of your account balance, and if this threshold is hit, trading halts automatically for the day" (INFERRED (snippet) https://www.botspot.trade/guides/algorithmic-trading-risk-management).
* **Kill switch semantics.** "Kill switches block all new order placement, including exit requests, and persist across restarts, though they are not an automatic flattening action and you need to plan separately how to inspect and manage existing positions" (INFERRED (snippet) https://skills.himanshujangir.com/skills/execution-algorithm-kill-switch-integration/). Hummingbot `stop` "cancels all active orders" (INFERRED A4). Design: kill = (1) persist a `trading.halted` event, (2) cancel open orders, (3) *do not* auto-flatten unless a separate human-set policy says so; a human un-halts via the control plane.
* **Order idempotency.** Mint the client order id in the kernel *before* the approval prompt (eliza `trade-confirmation.ts`, CONFIRMED A8); Coinbase returns the existing order on duplicate id (INFERRED A11); Alpaca 422s (INFERRED A11); on an ambiguous response "query ... by `client_order_id` to confirm the order's absence before sending again" (INFERRED (snippet) https://skills.himanshujangir.com/skills/coinbase-advanced-trade-api-migration/). Per-run collision bug seen in the wild: "give client_order_id a per-run time component to stop same-day collisions" (CONFIRMED title, https://github.com/AustinWinstanley/trading-bot/pull/39).
* **Reconciliation.** "A submitted order is not a completed trade; you must monitor acknowledgements, fills, partial fills, rejections, cancellations, expirations, and replacements, and compare internal state with broker open orders, positions, balances, and buying power ... reconnects and missed messages require periodic reconciliation against broker state." INFERRED (snippet) https://blog.traderspost.io/article/stop-loss-strategies-algorithmic-trading (via search summary). Design: a scheduled `reconcile` run (read-only tools) diffs venue state vs. the event-log projection and emits `trading.drift` events; drift above a threshold trips the halt.
* **LLM never sizes or exits discretionarily.** ai-hedge-fund's "deterministic code sizes positions" (CONFIRMED A2) and DXRG's "a fixed 2%/4% bracket beat every discretionary exit we measured" (CONFIRMED A10).

## A13. Regulatory notes for a single US operator (not legal advice; cite and verify)

* **Pattern day trader (PDT).** Historic rule: "four or more day trades within a rolling five-business-day window" in a margin account required "$25,000" minimum equity. Multiple sources report FINRA eliminated the $25,000 minimum and the PDT designation, SEC approval April 14, 2026 (SR-FINRA-2025-017, order 34-105226), effective **June 4, 2026**, leaving the ordinary "$2,000 minimum equity balance pursuant to existing margin rules" and day-trading margin requirements. INFERRED (snippet) https://www.finra.org/rules-guidance/notices/26-10 , https://www.sec.gov/files/rules/sro/finra/2026/34-105226.pdf , https://us.etrade.com/knowledge/library/margin/pattern-day-trading-rule-change , https://tradezero.com/en-us/blog/the-usd25-000-day-trading-minimum-is-gone-here-s-what-it-means-for-you . All primary pages egress-blocked; the operator must read Regulatory Notice 26-10 before relying on this. Practical: a cash account never had PDT exposure but has settlement (T+1) constraints; a margin account still has day-trade buying-power limits and Alpaca-style "insufficient day trading buying power" rejections (INFERRED (snippet) A11).
* **Wash sales (IRC §1091).** Loss disallowed if the same or "substantially identical" security is bought within 30 days before or after the sale (61-day window); disallowed loss is added to basis; "substantially identical" is not defined by statute. IRS Publication 550 is the reference. INFERRED (snippet) https://www.investor.gov/introduction-investing/investing-basics/glossary/wash-sales , https://www.fidelity.com/learning-center/personal-finance/wash-sales-rules-tax , https://nationaltaxtools.com/guides/wash-sale-rule/
* **Crypto and wash sales.** "the wash sale rule does not apply to cryptocurrency for 2025 or 2026, as the IRS treats crypto as property, not a security" and proposals to extend it "were NOT included in the final law" (INFERRED (snippet) https://reedcorp.tax/helpful-guides/crypto/crypto-wash-sale-rule/ , https://fraimcpa.com/wash-sale-rule-crypto-stocks/). Could change; the kernel should carry a `wash_sale_tracking` flag per asset class rather than hard-code it.
* **Design consequence.** A `tax-ledger` projection (every fill as an event with lot ids) is cheap to build now and hard to reconstruct later; the `reconcile` run should flag any equities sell-at-loss followed by a buy of the same symbol inside 30 days as a `trading.wash_sale_risk` event so the human sees it before approving.

* **CAN-SPAM (FTC guide).** Requirements: no false/misleading header information; no deceptive subject lines; identify the message as an ad; "a valid physical postal address"; a clear opt-out mechanism; "honor opt-out requests within 10 business days"; you are liable even when you hire someone else to send. 1. **Agent process holds the signing key or exchange key.** Gajesh2007/ai-trading-agent "a private key associated with an agent wallet" (CONFIRMED A11); eliza `local` backend "raw EOA private keys from environment variables or the OS keychain" (CONFIRMED A8). Violates invariant 2.

4. **Backtests inside the model's training window or without live guards.** FINSABER (INFERRED A10); bias survey "no single bias is discussed in more than 28 percent of studies" (INFERRED A10); freqtrade protections off by default in backtest (CONFIRMED A5); TradingAgents' own look-ahead patches (CONFIRMED A1).

10. **Auto-reply, follow/unfollow, like/repost automation for growth.** X rules (INFERRED B6).
11. **Sending outbound mail with no approval step, no suppression list, or from a cold domain.** OpenOutreach "No explicit approval workflow" (CONFIRMED B4); CAN-SPAM and Google/Yahoo thresholds (INFERRED B7).
