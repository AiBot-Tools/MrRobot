## What it is

Agent Canvas is a self-hosted "developer control center" web UI (and Electron app) that drives one or more **OpenHands Agent Servers** (REST + WebSocket, Python, in `software-agent-sdk`) and an optional **Automation Server** (cron/webhook-triggered agent runs, in `OpenHands/automation`). It can run the built-in OpenHands agent or, via the **Agent Client Protocol (ACP)**, spawn Claude Code / Codex / Gemini CLI as subprocesses (`docs/ACP_AGENTS.md`). It is **not** the coding-agent engine; it is the shell + local-stack launcher over that engine. CONFIRMED.

## Orchestration model

* **Conversation = unit of work.** One agent per conversation; the UI starts it with a settings payload. Execution status enum: `idle | running | paused | waiting_for_confirmation | finished | error | stuck` (`src/types/agent-server/core/base/common.ts` `ExecutionStatus`). CONFIRMED.
* **Delegation = child conversations**, not in-process sub-agents. The UI registers a *client tool* `launch_child_conversation` whose description tells the model: child runs independently, cannot see the parent's history, task brief must be self-contained, one call per task, `target=local|cloud`, `isolation=worktree|shared` (worktree default = own git worktree + branch cut from default branch). Parent id recorded via `parent_conversation_id`. Result arrives asynchronously as a follow-up message (`src/api/launch-child-conversation-client-tool.ts`; `agent-server-adapter.ts` `parent_conversation_id`). CONFIRMED.
* **Client tools**: the UI can register tools whose executor is a server-side no-op and whose effect is performed by the frontend watching the event stream (`tools/canvas_ui_tool.py` docstring; `client_tools` in the start payload). Schema is cached per tool *name* for the server's lifetime and re-registration with a different schema is rejected (`ClientToolSchemaConflictError`, adapter comment). CONFIRMED.
* **Automations** (scheduled/event runs): trigger `type` cron/schedule/event with `source`, `on` patterns, JMESPath `filter`; per-automation `agent_profile_id`, `timeout` (default 600 s), `plugins`; run states `PENDING/RUNNING/COMPLETED/FAILED/CANCELLED/SKIPPED`; finish-tool response with `status: success|partial_success|blocked|failed|unknown` + `outcome_summary`; **automatic disablement after consecutive failures / permanent config faults with `disabled_reason` + structured `disabled_detail`** (`src/types/automation.ts`). CONFIRMED.
* **`/goal` loop**: an objective is re-audited by a judge each round producing `GoalVerdict {score, complete, missing}` until `complete`, `capped` (max_iterations) or `interrupted`; streamed as `ConversationStateUpdateEvent key:"goal"` (`conversation-state-event.ts`). CONFIRMED (type + UI); judge implementation is in the SDK (INFERRED).
* **Agent profiles**: named, saved bundles of model + tools + selected secrets, seeded `default` profile mirrors global settings; `agent_profile_id` and inline `agent_settings` are mutually exclusive at launch (`src/api/agent-profiles-service/agent-profiles-service.api.ts`; `src/types/automation.ts` "Saved agent profile controlling model, tools, and selected secrets"). CONFIRMED.
* **Stuck detection** and **max_iterations** and **max_budget_per_task** are launch/global settings; accumulated cost/tokens per usage id are streamed in `stats` (`conversation-state-event.ts`, `settings.ts`). CONFIRMED.

## Agent roster / roles found

There is **no roster**. The system is single-agent-per-conversation with pluggable *agent kinds*:

* `agent_kind: "openhands"` – built-in LLM agent (`src/types/settings.ts` `AgentKind`).
* `agent_kind: "acp"` – external subprocess: Claude Code (`npx -y @agentclientprotocol/claude-agent-acp`), Codex (`codex-acp`), Gemini CLI (`--acp`), or Custom (`docs/ACP_AGENTS.md`; `src/constants/acp-providers.ts`).
* Roles emerge only from **agent profiles** (model+tools+secrets) and **skills** (prompt fragments with `triggers`, `category`, `disable_model_invocation`, `is_agentskills_format`; scopes project/personal/public; `.agents/skills/`, `.openhands/skills/`, legacy `.openhands/microagents/`) (`src/types/settings.ts` `SkillInfo`, `src/utils/skill-scope.ts`). CONFIRMED.
* The repo's own dev skills: `.agents/skills/custom-codereview-guide.md` (review bot rules: APPROVE or COMMENT only, never REQUEST_CHANGES; do not approve prompt/tool/eval-affecting changes without human + lightweight evals), `release.md`, `pr-design-doc/SKILL.md`. CONFIRMED.

## Memory model

* **Working memory = the conversation event log**, condensed by a **condenser** that emits `Condensation{forgotten_event_ids, summary, summary_offset}`; the LLM "View" is the event list minus forgotten ids plus the summary inserted at the offset. Condenser has its own LLM usage id / cost line (`condensation-event.ts`, `conversation-state-event.ts` `UsageToMetrics`). CONFIRMED.
* **Long-term memory = skills files** (knowledge type; keyword `triggers`) loaded from user/project dirs at conversation start; public catalog is a build-time snapshot from `@openhands/extensions` (`src/api/skills-service.ts`). No vector store, no cross-conversation memory in this repo. CONFIRMED.
* Conversation metadata persisted client-side (`src/api/conversation-metadata-store.ts`) and on the server under `~/.openhands/agent-canvas/conversations` (`config/defaults.json` paths). CONFIRMED.

## Tool / plugin / MCP model

* Built-in tools mirrored in `src/types/agent-server/core/base/action.ts`: `ExecuteBash`/`Terminal`, `FileEditor` (view/create/str_replace/insert/undo_edit), `Think`, `Finish`, `MCPToolAction`, browser tool set (`VITE_ENABLE_BROWSER_TOOLS`), task tracker (`TaskItem`). CONFIRMED.
* **MCP**: per-backend `mcp_config` map keyed by stable server id; transports stdio/http; `auth.strategy: "oauth2"` with server-side OAuth start/status flow; health probing (`src/api/mcp-service/`, `src/api/mcp-health/`). Secrets in MCP config round-trip as **Fernet tokens** when settings are fetched with `X-Expose-Secrets: encrypted`, and a **display-only redaction sentinel** is never sent back as mutation data (`specs/mcp-settings.md` MCP-001..003, `src/api/mcp-service/mcp-redacted-credentials.ts`). CONFIRMED.
* **Hooks**: `.openhands/hooks.json` in the workspace defines `PreToolUse | PostToolUse | UserPromptSubmit | SessionStart | SessionEnd | Stop` shell hooks; each execution is an event with `blocked`, `exit_code`, `reason`, `stdout/stderr` (`src/api/hooks-service.ts`, `core/events/hook-execution-event.ts`). CONFIRMED.
* **Plugins** (`plugins` list on conversation/automation; `src/api/plugins-service.ts`) and **canvas extensions** (`docs/CANVAS_EXTENSIONS_TESTING.md`, `specs/canvas-extensions.md`). CONFIRMED (existence only).
* Tool annotations follow MCP hints: `readOnlyHint / destructiveHint / idempotentHint / openWorldHint` (`launch-child-conversation-client-tool.ts`). CONFIRMED.

## Sandbox & security posture

* **Isolation**: default `npm run dev` / `npx @openhands/agent-canvas` runs the agent-server **directly on the host with full filesystem, env and network access** (README warnings; `docs/architecture.md` "Runtime modes"). Docker option is an all-in-one image (`docker/Dockerfile` final stage `USER openhands`, based on `ghcr.io/openhands/agent-server`) that bind-mounts `~/.openhands` and `PROJECTS_PATH`; no `--read-only`, `--cap-drop`, pids/mem caps in the documented `docker run`. Cloud sandboxes are OpenHands Cloud. Per-conversation git **worktree** isolation is the default (`worktree: options.worktree ?? true`). CONFIRMED.
* **Network**: all local services bind `127.0.0.1` (`scripts/dev-safe.mjs` lines 218-296, 1017-1018); ingress proxy fronts them; `--public` mode requires `LOCAL_BACKEND_API_KEY` and does not bake the key into the frontend; auth header is `X-Session-API-Key` (`docs/SELF_HOSTING.md`, `bin/agent-canvas.mjs`). Known hole: bundled OpenVSCode shares the browser origin, so any script there can read `localStorage` holding **every registered backend's session API key** (issue #16492, `docs/SELF_HOSTING.md`, `config/defaults.json`). Inside Docker `openvscode-server` binds 0.0.0.0 (`docker/entrypoint.sh` header). CONFIRMED.
* **Credentials**: settings encrypted at rest with `OH_SECRET_KEY` (Fernet), auto-generated and persisted; the UI can fetch them `encrypted` and send `secrets_encrypted: true` so the server decrypts at conversation start (`agent-server-adapter.ts` 1281-1292). For ACP agents, **each secret's name is exactly the env var exported into the agent subprocess** (`ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `CODEX_AUTH_JSON`, ...) and host CLI logins (macOS Keychain, `~/.claude/.credentials.json`) are reused automatically (`docs/ACP_AGENTS.md`). The agent process therefore holds provider credentials. CONFIRMED.
* **Gates**: `confirmation_policy` is `NeverConfirm` when confirmation mode is off; `AlwaysConfirm` when on; `ConfirmRisky{threshold:"HIGH", confirm_unknown:true}` when on **and** `security_analyzer === "llm"`. Analyzers: `LLMSecurityAnalyzer` (the acting LLM predicts `security_risk ∈ UNKNOWN/LOW/MEDIUM/HIGH` on the tool call itself), `PatternSecurityAnalyzer`, `PolicyRailSecurityAnalyzer` (`agent-server-adapter.ts` 680-706; `action-event.ts` `security_risk`; `common.ts` `SecurityRisk`). Default `confirmation_mode: false`. Hooks can `block` a tool call pre-execution. CONFIRMED.
* **Governance add-on** documented, not built in: DefenseClaw guardrail proxy at the LLM base URL (observe/action modes) + skill/MCP scanners (`docs/DefenseClaw.md`). CONFIRMED (doc only).
* **Telemetry**: PostHog key baked into `config/defaults.json`; consent-gated, `VITE_DO_NOT_TRACK=1` disables (`AGENTS.md` Tracking section). CONFIRMED.

## BEST PARTS

1. **Child-conversation delegation contract** — idea: sub-tasks run as fully separate conversations with no shared history, a self-contained brief, one-call-per-task rule, worktree-per-child isolation, and an async "result envelope" message rather than blocking. Evidence: `src/api/launch-child-conversation-client-tool.ts`. Sector: **engineering / kernel** (CEO -> coder fleet fan-out). Why: matches our "one run per worker, own workspace" model and gives a proven prompt shape for the CEO's `delegate` tool; worktree isolation is exactly how parallel coding agents avoid fighting over files.
2. **Condensation as first-class events** — idea: memory compaction is itself logged (`forgotten_event_ids`, `summary`, `summary_offset`) and billed under its own usage id (`"condenser"`). Evidence: `src/types/agent-server/core/events/condensation-event.ts`, `conversation-state-event.ts` `UsageToMetrics`. Sector: **kernel**. Why: our hash-chained log can carry `context.condensed` events so a run's LLM view is reconstructible and the condenser's cost is attributable, without ever deleting events (invariant 5).
3. **Hook lifecycle with audited block decisions** — idea: `PreToolUse/PostToolUse/UserPromptSubmit/SessionStart/SessionEnd/Stop` hooks whose every execution is an event with `blocked`, `exit_code`, `reason`. Evidence: `src/types/agent-server/core/events/hook-execution-event.ts`, `src/api/hooks-service.ts`. Sector: **kernel / ops-security**. Why: gives a shape for kernel-side, non-LLM policy hooks (lint, secret scan, taint check) that produce log entries the Run Inspector can render; we run them in the kernel, not from a workspace file.
4. **Automation health rules** — idea: scheduled/webhook automations carry `timeout`, JMESPath payload `filter`, structured finish status (`success|partial_success|blocked|failed`), and are **auto-disabled after consecutive failures** with a machine-readable `disabled_detail`. Evidence: `src/types/automation.ts`. Sector: **ops-security / growth** (scheduled marketing/social posts, watchers). Why: our Phase 1 cron scheduler should ship with a circuit breaker and a typed outcome instead of free text.
5. **`/goal` judge loop with capped rounds** — idea: separate judge yields `{score, complete, missing}` per round; loop ends `complete | capped | interrupted`; all streamed as state events. Evidence: `src/types/agent-server/core/events/conversation-state-event.ts` `GoalStatus/GoalVerdict`. Sector: **engineering / executive**. Why: a template for the CEO's milestone verification (auditor as judge) with a hard round cap that budgets cannot be talked out of.
6. **Per-action critic result** — idea: every `ActionEvent` may carry `critic_result{score, categorized_features[insufficient_testing, loop behaviour, infra issues...]}`. Evidence: `src/types/agent-server/core/base/critic.ts`, `action-event.ts`. Sector: **engineering** (coder fleet) and **kernel** eval harness. Why: a cheap advisory signal for the auditor/eval harness; explicitly *not* an access-control input.
7. **Secrets hygiene in the settings API** — idea: encrypted-at-rest settings, an `X-Expose-Secrets: encrypted` mode so the UI can round-trip secrets without seeing them, a display-only redaction sentinel that is never written back, sparse per-server MCP patches. Evidence: `specs/mcp-settings.md`, `src/api/mcp-service/mcp-redacted-credentials.ts`, `agent-server-adapter.ts` 1281-1292. Sector: **ops-security**. Why: our control-plane views must never carry vault values; the sentinel/never-write-back rule is a good protocol-v1 test case.
8. **Scripted mock-LLM trajectories for e2e** — idea: an OpenAI-compatible server replays `TestLLM` trajectories (tool call then reply) with mapped error classes (401/429/context-window) so the whole stack is tested deterministically. Evidence: `tests/e2e/mock-llm/scripts/mock-llm-server.py`, `.github/workflows/mock-llm-e2e.yml`. Sector: **kernel** (Phase 1 eval harness). Why: same trick lets us test router, budgets, taint and the gate against fake providers without spend.

## BAD PARTS / anti-patterns

1. **The acting LLM predicts its own `security_risk` and `ConfirmRisky` gates on it.** Evidence: `agent-server-adapter.ts` 687-689 (`ConfirmRisky` only when `security_analyzer === "llm"`), `action-event.ts` comment "security_risk field predicted by LLM". Why out: CLAUDE.md invariant 3 says the model never makes an access-control decision; a prompt-injected agent simply labels everything LOW.
2. **Default is no confirmation at all** (`confirmation_mode: false` -> `NeverConfirm`) on an agent with host shell + filesystem + network. Evidence: `agent-server-adapter.ts` 683-685, `types/settings.ts`. Why out: we are default-deny with `irreversible` always human-gated.
3. **Agents hold credentials.** ACP agents get provider keys as env vars named after the secret, and reuse host Keychain/`~/.claude/.credentials.json`; `secrets_encrypted` decrypts into the agent process. Evidence: `docs/ACP_AGENTS.md` "How credentials reach the agent", `agent-server-adapter.ts` 1281-1292. Why out: invariant 2 (credentials injected only at the egress proxy edge).
4. **Host-process default runtime** with full filesystem access, and a Docker image with no read-only/cap-drop/pids guidance; per-run isolation is a git worktree, not a sandbox. Evidence: README Options 1 & 3 warnings, `docs/architecture.md`, `docker/entrypoint.sh`. Why out: invariant 9.
5. **Shared-origin editor exposes every backend's API key from `localStorage`**; `openvscode-server` binds 0.0.0.0 in the container. Evidence: `docs/SELF_HOSTING.md` NOTE (#16492), `docker/entrypoint.sh` VSCODE_PORT comment. Why out: invariant 1 (loopback, bearer only, no browser-storage tokens); our Shell holds no secrets.
6. **Workspace-file hooks and project skills are agent-writable policy** (`.openhands/hooks.json`, `.agents/skills/` in the project the agent edits). Evidence: `src/api/hooks-service.ts`, `src/utils/skill-scope.ts`. Why out: invariant 8 (souls/AGENTS.md read-only to agents); a coder could rewrite its own PreToolUse gate. Also hard-coded PostHog key in `config/defaults.json` (consent-gated, but on by default for source builds) conflicts with a local-first posture.

## Conflicts with CLAUDE.md invariants

1. Inv. 1 — API key in browser `localStorage`, editor on same origin, `X-Session-API-Key` header rather than bearer; `--public` mode intended to be internet-facing behind nginx.
2. Inv. 2 — agent subprocesses receive provider keys/OAuth tokens as env; host CLI logins reused; MCP secrets forwarded to the ACP subprocess.
3. Inv. 3 — `LLMSecurityAnalyzer` lets the model rate its own risk; `NeverConfirm` default; no taint concept; no default deny.
4. Inv. 4 — LLM calls are metered (`UsageToMetrics`) but the UI sees only stats, not paired request/response events (INFERRED for the SDK; not verifiable here).
5. Inv. 5 — no hash chain; condensation forgets events from the *view* only (good) but nothing here proves immutability of the store.
6. Inv. 6 — child conversations inherit the parent's workspace/backend with no tier/egress ceiling in the tool schema (`isolation=shared` lets a child edit the parent's live tree).
7. Inv. 7 — MCP servers are user-added with all tools exposed; no per-tool exposure/risk classification.
8. Inv. 8 — skills/hooks live inside the workspace the agent edits.
9. Inv. 9 — host runtime by default; Docker image lacks the required hardening flags; editor binds all interfaces.
10. Inv. 10 — n/a (the mapping concern does not arise; MCP tool actions are generic `MCPToolAction`).

## Verdict

Take the delegation contract (self-contained brief, one call per task, worktree per child, async result envelope), the event-typed condensation and hook-execution records, the automation circuit breaker with typed outcomes, the capped judge loop and advisory critic, and the mock-LLM trajectory harness. Leave the entire trust model: model-predicted risk as a gate, confirmation off by default, credentials in agent env, host-process runtime, browser-stored API keys, and agent-editable hooks/skills. Treat this clone as a UI/protocol reference for our Phase 3 Tauri shell (Run Inspector, approvals view, automations list) and not as a source for the coding-agent engine, which is not in this repository.
