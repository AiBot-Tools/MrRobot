## What it is

A single skill that gives a host LLM a video input. `scripts/watch.py` runs: captions-first metadata fetch via yt-dlp -> optional download (video, or audio-only in `transcript` detail) -> frame extraction at one of four detail levels -> transcript (native VTT captions, else Whisper API, chunked over 25 MB) -> a markdown report on stdout listing frame paths with `t=MM:SS` and a `reason=` provenance tag, plus the timestamped transcript. The model then `Read`s every JPEG (CONFIRMED, `REF/skills/watch/scripts/watch.py` report section; `REF/skills/watch/SKILL.md` Steps 1-5). README use cases include analyzing competitor content ("what hook did they open with?"), diagnosing a bug from a screen recording, summarizing, and stripping hype from launch videos (CONFIRMED, `REF/README.md` "What people actually use it for").

It is a media-perception tool, not an agent framework. There is no orchestration, no roster, no delegation, no memory system, no sandbox. Its value to our fleet is as a **kernel-wrapped perception tool** for the media/social sector and as a set of small, well-tested engineering patterns.

## Orchestration model

None in code. The procedure lives in prose in `SKILL.md`: Step 0 preflight (`setup.py --json` on first call, `--check` later), Step 1 parse input, Step 2 run `watch.py`, Step 3 `Read` all frames in one parallel batch, Step 4 answer with timestamp citations, Step 5 `rm -rf` the work dir if no follow-ups (CONFIRMED, `REF/skills/watch/SKILL.md`). The host model is the orchestrator and the only decision-maker (which detail mode, which `--timestamps`, whether to clean up). A two-pass "transcript-cue" loop is described: run once for the transcript, the model scans for deictic phrases ("look here"), then re-runs against the downloaded local file with `--timestamps` (CONFIRMED, SKILL.md "Transcript-cue frames"; `REF/skills/watch/scripts/frames.py` `extract_at_timestamps`, `merge_frames`).

## Sandbox & security posture

- **Isolation:** none. Scripts run on the host with the host's PATH, `$HOME`, and network. yt-dlp fetches any URL directly (`-N 8`, `--ignore-errors`, English-only subs) (CONFIRMED, `REF/skills/watch/scripts/download.py`). Frames land in the system tmp dir and are Read from there.
- **Credential handling:** keys in `~/.config/watch/.env` chmod 0600, plus fallback read of `Path.cwd()/.env` (CONFIRMED, `whisper.py` `load_api_key` `dotenv_paths`). `setup.py` warns once per process if the file is group/world readable (CONFIRMED, `_check_file_permissions`). Keys are sent only to their own provider with a Bearer header and a custom UA; never printed (CONFIRMED, `whisper.py` `_post_whisper`; SKILL.md Security section). SKILL.md instructs the *model* to write a user-supplied key into `.env` after `AskUserQuestion` (CONFIRMED, Step 0 "write it into ~/.config/watch/.env").
- **Argv hardening:** `--` before the URL in yt-dlp argv; `is_url` rejects `-`-prefixed sources and requires netloc; `Path.resolve()` before ffmpeg/ffprobe (CONFIRMED, `download.py`; `REF/CHANGELOG.md` 0.1.3 Security).
- **Egress enumeration:** SKILL.md "Security & Permissions" lists exactly what leaves the machine: yt-dlp to the URL host, audio to `api.groq.com/openai/v1/audio/transcriptions` or `api.openai.com/v1/audio/transcriptions`; video itself is never uploaded; no cookies/login (CONFIRMED).
- **Gates / human-in-the-loop:** only `AskUserQuestion` during first-run setup (key, default detail). No approval for `brew install` (auto-runs on macOS, never sudo) or for `rm -rf <work dir>` (CONFIRMED, `setup.py` `_install_macos`, SKILL.md Step 5).
- **Untrusted input:** captions/auto-subs and Whisper output are injected verbatim into the report and thus into model context; VTT parsing strips tags only (CONFIRMED, `transcribe.py` `TAG_RE`). No taint marking. This is the prompt-injection surface for any third-party video.
- **Evals:** pytest, no network; ffmpeg-synthesized cut/static clips as session fixtures; whisper tests stub the transcriber; download tests stub `subprocess.run` and assert argv (CONFIRMED, `REF/tests/*.py`).

## BEST PARTS

1. **Duration-aware frame budget with a hard 2 fps ceiling and a focus mode.** `auto_fps`/`auto_fps_focus` target a frame *count* by duration (12-30 / 40 / 60 / 80 / cap), `_clamp_fps` never exceeds `MAX_FPS = 2.0`, and `--start/--end` switches to denser per-second budgets. Evidence: `REF/skills/watch/scripts/frames.py` `auto_fps`, `auto_fps_focus`, `_clamp_fps`; `REF/README.md` "Frame budget". Sector: **growth** (producer/publisher review), **executive** (budget predictability). Why: it makes image-token cost a deterministic function of inputs, which is exactly what the kernel's per-run budget needs to pre-compute before the gate lets a media-QA run proceed; a reviewer agent that cannot blow its budget on a 49-minute video is a reviewer we can run unattended.

2. **Detail dial as data (`transcript | efficient | balanced | token-burner`) with measured costs.** Four modes differ only in candidate source and cap, never in sampling shape; README publishes measured extraction time and token estimates per mode from one real 49:08 run. Evidence: `REF/skills/watch/scripts/config.py` `frame_cap`, `REF/README.md` "Detail modes — measured", `REF/CHANGELOG.md` 0.2.0. Sector: **growth**, **ops-security**. Why: maps cleanly onto our tier ladder and policy gate: ephemeral `checker` templates get `transcript`/`efficient` only; `token-burner` is a budget-escalation the CEO can request but the gate enforces. Cost tiers as config, not model judgement (Invariant 3: the model never makes an access-control decision).

3. **Transcript-cue frames: evidence pinned at timestamps, with per-frame provenance.** `--timestamps` reserves budget for model-chosen moments before the detail engine runs; every frame in the report carries `t=MM:SS` and `reason=first-frame|scene-change|keyframe|uniform|transcript-cue`. Evidence: `frames.py` `extract_at_timestamps`, `merge_frames`; `watch.py` report loop; `REF/tests/test_timestamps.py`, `REF/tests/test_watch.py::test_timestamps_add_cue_frames_to_detail`. Sector: **growth** (social content review), **ops-security** (audit evidence). Why: a social/media QA verdict ("the CTA appears at 0:12; the logo is wrong at 0:41") becomes a citation into an artifact that lands in the hash-chained log. This is the shape of a trustworthy review event, and the two-pass loop (read transcript -> choose cues -> re-run on the local file) is a delegation-free pattern an ephemeral `checker` can execute inside one run.

4. **Near-duplicate frame dedup in pure stdlib, fail-open, tested.** One ffmpeg pass produces 16x16 grayscale thumbnails; greedy mean-absolute-difference against the last *kept* frame (threshold 2.0) drops held slides; runs before the cap so budget goes to distinct content; any ffmpeg error returns `[]` and dedup is skipped rather than breaking extraction. Evidence: `frames.py` `_thumb_frames`, `_frame_delta`, `_dedupe_by_deltas`, `dedupe_perceptual`; `REF/tests/test_dedup.py`. Sector: **growth**, **engineering**. Why: cuts image tokens on exactly the content our producer will generate (static cards, captions over B-roll) with no new dependency, which fits our "no new dependencies" rule; the fail-open contract is documented and tested, which is the standard we want for any kernel-side helper.

5. **Captions-first, download-only-what-you-need, chunked Whisper with partial-failure tolerance and a disciplined retry policy.** `fetch_captions` uses `--skip-download`; `transcript` detail never downloads video when captions exist; audio over 24 MB is split by an even time plan, chunks are transcribed independently with timestamps shifted back into source time, and the transcript fails only if *every* chunk fails; HTTP retry: no retry on 4xx except 429, 429 capped at 2, exponential backoff, `Retry-After` honored, 300 s timeout. Evidence: `download.py` `fetch_captions`; `whisper.py` `plan_chunks`, `split_audio`, `shift_segments`, `transcribe_chunks`, `_post_whisper` (`MAX_ATTEMPTS`, `MAX_429_RETRIES`); `REF/tests/test_whisper.py`. Sector: **engineering** (worker resilience), **growth**. Why: the cheapest-source-first ladder and the bounded retry caps are the same discipline our model router and MCP hub need; "retry caps never disabled" is already a CLAUDE.md rule, and this is a compact, tested reference implementation.

6. **Structured preflight that separates ideal state from the operational gate, silent on success.** `setup.py --json` returns `status` (what to *encourage*) and `can_proceed` (whether the run may start); `--check` exits 0 with zero output when runnable, with numbered exit codes 2/3/4 otherwise; keyless-but-completed setups are never nagged. Evidence: `REF/skills/watch/scripts/setup.py` `_status`, `cmd_check`; `REF/tests/test_setup.py::test_keyless_completed_setup_proceeds_silently`. Sector: **kernel** (capability probing, like `aos probe`), **ops-security**. Why: a machine-readable capability report per tool/sidecar is what the kernel should demand before binding a tool to an agent; the two-field split avoids the classic failure where a "warning" blocks a run or a "block" is downgraded to a warning.

7. **Argv hardening and explicit egress enumeration.** `--` before the URL, `-`-prefixed sources rejected, `Path.resolve()` before ffmpeg; SKILL.md lists every host the tool talks to and states what is *never* done (no video upload, no cookies/login, keys never cross providers). Evidence: `download.py` `is_url`, `fetch_captions`/`download_url` argv; `REF/CHANGELOG.md` 0.1.3 "Security"; `REF/skills/watch/SKILL.md` "Security & Permissions". Sector: **ops-security**, **kernel** (sandbox driver argv construction). Why: the host list is a ready-made per-agent hostname allowlist for the Phase 2 egress proxy, and the argv rules are the exact pattern our Docker driver must follow when it builds `docker run` argv from agent-supplied strings.

8. **Deterministic, network-free media fixtures for tests.** `conftest.py` synthesizes a 14-cut clip (forced keyframe per cut) and a static clip with lavfi `color=` sources; every engine, fallback, dedup, and end-to-end `--detail` route is asserted against them. Evidence: `REF/tests/conftest.py` `build_cut_clip`, `build_static_clip`; `REF/tests/test_frames.py`, `test_watch.py`. Sector: **engineering** (eval harness). Why: our Phase 1 eval harness and Phase 4 media pipeline need reproducible inputs that do not touch the network; this is the cheapest known way to get them.

## BAD PARTS / anti-patterns

1. **The model handles secret values.** SKILL.md tells the model to ask for a Groq/OpenAI key via `AskUserQuestion` and *write it* into `~/.config/watch/.env`; `whisper.py` also reads a key from `Path.cwd()/.env`. Evidence: `REF/skills/watch/SKILL.md` Step 0 ("write it into ~/.config/watch/.env"); `REF/skills/watch/scripts/whisper.py` `load_api_key` `dotenv_paths`. Why we leave it out: the key value transits the model context and the transcript; in our design the secrets broker over pmmcp's vault is the only key holder and credentials are injected at the egress proxy edge (Invariant 2; "never log a secret value").

2. **Unrestricted `Bash` plus model-issued destructive and install commands.** `allowed-tools: Bash` is unscoped; the model is instructed to `rm -rf <work dir>`; `setup.py` auto-runs `brew install ffmpeg yt-dlp` on macOS from a skill invocation. Evidence: SKILL.md frontmatter and Step 5; `REF/skills/watch/scripts/setup.py` `_install_macos`. Why we leave it out: every tool call must pass the policy gate, `irreversible` requires a human, and installing software on the operator's Mac is a human action (Invariant 3). Workspace lifecycle is a kernel responsibility, never a model-issued shell command.

3. **Direct, unproxied egress to arbitrary hosts and reliance on `$HOME`.** yt-dlp hits whatever host the URL names with 8 parallel connections and `--ignore-errors`; config lives under `Path.home()`; frames live in the system tmp dir. Evidence: `download.py` `download_url` argv; `config.py` `CONFIG_DIR = Path.home() / ".config" / "watch"`; `watch.py` `tempfile.mkdtemp`. Why we leave it out: workers run in containers with an internal network, mounts confined to `mountRoot`, and never `$HOME` (Invariant 9); all network must be proxy decisions logged per call (Phase 2). The tool as-is cannot run inside a T2/T3 worker without a rewrite of its I/O paths.

4. **Untrusted text (captions, auto-subs, Whisper output) is injected verbatim into model context with no taint.** VTT parsing strips only `<tags>`; the report prints the full transcript inline. Evidence: `REF/skills/watch/scripts/transcribe.py` `TAG_RE`, `parse_vtt`; `watch.py` "## Transcript" block; README use case "analyze someone else's content". Why we leave it out: a competitor's subtitles are attacker-controlled input. Any run that watches a third-party URL must be tainted at ingress so it cannot use `write` tools without a human (Invariant 3); the tool has no notion of this.

5. **Silent degradations.** Dedup fails open to "no dedup" without reporting why; yt-dlp exit codes are ignored and success is inferred from "a video file exists"; `_pick_subtitle` prefers English by filename heuristics. Evidence: `frames.py` `_thumb_frames` (`return []` on error), `download.py` `download_url` ("Treat 'video file present' as success"), `_pick_subtitle`. Why we leave it out (as-is): acceptable for a personal tool, but a QA gate must emit an event for every degraded path so the log explains a wrong verdict. The fail-open *contract* is good; the silence is not.

6. **Full transcript in the tool's stdout.** A 49-minute captioned video yields about 26.6k text tokens of transcript in the report. Evidence: `REF/README.md` "Detail modes — measured" (`transcript` row). Why we leave it out: `MAX_LOGGED_OUTPUT` forbids storing raw tool output of that size in the event log; the kernel must store transcript and frames as artifacts and log references plus hashes.

## Conflicts with CLAUDE.md invariants

1. **Invariant 2 (agents never hold provider keys):** the model writes and the worker reads `GROQ_API_KEY`/`OPENAI_API_KEY` from files in `$HOME` and cwd and sends them as Bearer headers itself (`whisper.py` `load_api_key`, `_post_whisper`; SKILL.md Step 0). In aos the Whisper call must go through the broker/egress proxy with the key injected at the edge.
2. **Invariant 3 (gate on every tool call, irreversible needs a human, taint):** unscoped `Bash`, model-issued `rm -rf`, auto `brew install`, and no taint on caption text from third-party URLs.
3. **Invariant 4 (every LLM call is two logged events with cost):** the Whisper transcription is a paid external model call with no logging or cost accounting; if wrapped, the kernel must emit request/response events with cost (transcription is not an `llm.*` call but must be an equivalent metered event).
4. **Invariant 5 / `MAX_LOGGED_OUTPUT`:** report output (transcript plus frame list) exceeds what may be stored raw in the log; needs artifact storage plus hash references.
5. **Invariant 7 (unknown tools default `kernel-only`):** if exposed as an MCP tool, `watch` must be classified in `tool-views.yaml` with `read` risk, `taint: true` for URL sources, and `quarantine` for output before a tainted run consumes it.
6. **Invariant 9 (container hygiene):** depends on `$HOME`, system tmp, host PATH binaries, and direct network; must be repackaged to run inside a T2 worker image with ffmpeg/yt-dlp baked in, workspace under `mountRoot`, and egress only via the proxy.
7. **Change control ("anything that widens what an agent can reach"):** adding yt-dlp reach to any host is a widening; it needs a per-agent hostname allowlist (the SKILL.md egress list is the starting point) and operator sign-off.

## Verdict

Take the perception pipeline and its cost discipline: duration-aware frame budgets with the 2 fps ceiling, the four-level detail dial as gate-enforced policy, stdlib frame dedup, captions-first with chunked Whisper and bounded retries, transcript-cue frames with `t=`/`reason=` provenance, the ideal-vs-operational preflight split, argv hardening, and network-free ffmpeg fixtures for our eval harness. Leave out everything that touches secrets, `$HOME`, the host shell, and unproxied egress: keys must come from the broker at the proxy edge, workspace cleanup and installs are kernel/human actions, and any third-party URL must taint the run because subtitles are attacker-controlled text. Wrap it as a kernel-hosted or T2-containerized `media.watch` tool (read risk, taint on URLs, artifacts for frames and transcript) that the `producer`, `publisher`, and an ephemeral `media-checker` template use for pre-publish QA, competitor teardown, and bug-repro-from-recording for the coding fleet.
