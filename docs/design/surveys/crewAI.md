## What it is

A Python multi-agent framework with two top-level abstractions: **Crews** (role-based agents assigned to a list of Tasks, executed sequentially or via an LLM "manager") and **Flows** (decorator-driven event graphs with `@start/@listen/@router/or_/and_`, persistent state, human-feedback nodes). It is a library that runs inside the caller's process; it has no daemon, no control plane, no sandbox, and no credential broker in the OSS package. CONFIRMED (`SRC/crew.py`, `SRC/flow/dsl/_start.py`, `_listen.py`, `_router.py`, `_conditions.py`).

## Orchestration model

- `Process` enum has exactly two members: `sequential`, `hierarchical`; `consensual` is a `# TODO`. CONFIRMED (`SRC/process.py`).
- Sequential: `_execute_tasks` iterates the task list in order; each task's `context` (list of prior tasks) is stringified into the prompt via `aggregate_raw_outputs_from_tasks`. `async_execution` tasks run as futures and are joined before the next sync task. CONFIRMED (`SRC/crew.py:1565-1640`, `SRC/task.py:167-175`).
- Hierarchical: `_create_manager_agent()` either uses a user-supplied `manager_agent` (forced `allow_delegation=True`; **raises if it has tools**) or synthesizes an `Agent(role="Crew Manager", ...)` from `translations/en.json` whose only tools are `DelegateWorkTool` and `AskQuestionTool`. Then it calls the same `_execute_tasks` with the manager as the executing agent for every task. CONFIRMED (`SRC/crew.py:1526-1560`, `SRC/crew.py:1727-1730`, `SRC/translations/en.json` key `hierarchical_manager_agent`).
- Delegation is a tool call: `BaseAgentTool._execute` fuzzy-matches the coworker role string (casefold, whitespace/quote-stripped), builds a fresh `Task(description=task, agent=selected_agent, expected_output="Your best answer to your coworker...")`, and calls `selected_agent.execute_task(...)` **synchronously in the same process/thread**, returning the string. There is no depth limit, no cycle guard, no budget split. CONFIRMED (`SRC/tools/agent_tools/base_agent_tools.py:57-135`, `SRC/tools/agent_tools/delegate_work_tool.py`; grep for `delegation_depth|max_delegation` found nothing in `SRC`).
- In sequential mode any agent with `allow_delegation=True` gets delegate/ask tools targeting every other agent in the crew (`_add_delegation_tools`). CONFIRMED (`SRC/crew.py:1833-1843`).
- The delegation prompt explicitly says the callee "know[s] nothing about the task, so share absolutely everything you know" — i.e. isolated-context delegation by design, the same shape as Hermes `delegate_task`. CONFIRMED (`SRC/translations/en.json` key `tools.delegate_work`).
- Planning: crew-level `planning=True` runs `CrewPlanner` (one LLM call producing `PlanPerTask` per task, injected into each task description). Agent-level `PlanningConfig` adds a step-observer with `reasoning_effort` low/medium/high, `max_attempts`, `max_steps`. CONFIRMED (`SRC/crew.py:347-352,1467`, `SRC/utilities/planning_handler.py:15-57`, `SRC/agent/planning_config.py:11-110`).
- Caps: `max_iter` (ReAct loop), `max_rpm` (token-bucket `RPMController.check_or_wait`), `max_execution_time`, `max_retry_limit`, per-tool `max_usage_count`, and a repeated-identical-tool-call detector. CONFIRMED (`SRC/agents/agent_builder/base_agent.py:275-289`, `SRC/agent/core.py:258,302`, `SRC/utilities/rpm_controller.py:12-44`, `SRC/tools/base_tool.py:184-195`, `SRC/tools/tool_usage.py:254-260,427-447`).
- Restart safety: crew `checkpoint` config plus `_get_execution_start_index` resumes at the first task with `output is None`; Flows have `SQLiteFlowPersistence` with `flow_states` and `pending_feedback` tables. CONFIRMED (`SRC/crew.py:400-419,1561-1567`, `SRC/flow/persistence/sqlite.py:39-114`).
- Events: a typed event bus with `Depends`-declared handler ordering resolved by `handler_graph.py` into parallel execution levels with circular-dependency detection; event types cover llm, tool, memory, mcp, guardrail, checkpoint, a2a, hooks. CONFIRMED (`SRC/events/handler_graph.py`, `SRC/events/types/`).
- Evals (experimental): `AgentEvaluator` with `GoalAlignmentEvaluator`, `ReasoningEfficiencyEvaluator`, `SemanticQualityEvaluator`, `ToolSelectionEvaluator`, `ParameterExtractionEvaluator`, `ToolInvocationEvaluator`. CONFIRMED (`SRC/experimental/evaluation/metrics/*.py`).
- Training: `Crew.train()` collects human feedback into a file for later prompt tuning. CONFIRMED (`SRC/crew.py:930-959`), internals not read.

## Agent roster / roles found

There is no shipped roster. Roles are free-form strings (`role`, `goal`, `backstory`) on `BaseAgent`; the only built-in persona is the synthesized "Crew Manager". CONFIRMED (`SRC/agents/agent_builder/base_agent.py:256-258`, `SRC/translations/en.json`). README examples (job descriptions, trip planner, stock analysis) are demo crews, not framework roles. The `crewai-tools` package ships 83 tool directories (search, scrape, file read/write, vector DBs, `e2b_sandbox_tool`, `daytona_sandbox_tool`) which effectively define what a "researcher"/"coder" can reach. CONFIRMED (`lib/crewai-tools/src/crewai_tools/tools/`).

## Memory model

- `Memory` (unified): records `{content, scope, categories, importance, source, private, embedding}`; an LLM infers scope/categories/importance on save; recall is a `RecallFlow` with confidence thresholds that trigger deeper exploration; consolidation merges near-duplicates above a similarity threshold; recency/semantic/importance weighting. CONFIRMED (`SRC/memory/types.py:20-70,135-276`, `SRC/memory/unified_memory.py:76-160`).
- Hierarchical path scopes (`/crew/research/<inferred>`) with `MemoryScope` (root-path view) and `MemorySlice` (multi-scope view); crews set a `root_scope`. CONFIRMED (`SRC/memory/memory_scope.py`, `SRC/memory/unified_memory.py:157-162`, `SRC/crew.py:659`).
- `private=True` records are only recalled by the same `source`. CONFIRMED (`SRC/memory/types.py:67-73`).
- Agents get `Search memory` and `Save to memory` tools; `Save to memory` is omitted only when memory is `_read_only`. Otherwise an agent writes to shared memory with **no gate**. CONFIRMED (`SRC/tools/memory_tools.py:25-110`).
- Flow HITL "learn" loop: on human feedback, `_distill_and_store_lessons` asks an LLM to distill lessons and saves them under a `learn_source`; `_pre_review_with_lessons` recalls them before the next review. CONFIRMED (`SRC/flow/human_feedback.py:279-400`).

## Tool / plugin / MCP model

CONFIRMED (`SRC/hooks/tool_hooks.py:86-192`, `SRC/hooks/dispatch.py:75-83`).

## Sandbox and security posture

- **No sandbox in core.** `allow_code_execution` and `code_execution_mode` are deprecated no-ops: "CodeInterpreterTool is no longer available. Use dedicated sandbox services instead." `_validate_docker_installation` is a no-op. Hosted sandboxes exist only as third-party tools (`e2b_sandbox_tool`, `daytona_sandbox_tool`). CONFIRMED (`SRC/agent/core.py:293-322,1397-1471`, `lib/crewai-tools/src/crewai_tools/tools/`).
- **Credentials live in the agent process.** Tools read `os.environ["SERPLY_API_KEY"]`, `os.getenv("TAVILY_API_KEY")`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `BROWSERBASE_API_KEY`, etc. directly; the LLM client holds provider keys in the same process as the agent loop. CONFIRMED (grep over `lib/crewai-tools/src/crewai_tools/tools`).
- `SecurityConfig` is a `Fingerprint` (uuid5 of a seed) with "Authentication credentials *TODO*", "Scoping rules *TODO*", "Impersonation/delegation tokens *TODO*". It is identity labelling, not access control. CONFIRMED (`SRC/security/security_config.py:14-30`, `SRC/security/fingerprint.py:74-88`).
- **Gates.** `Task.human_input=True` asks for feedback **after** the agent produces its final answer, then re-runs ("You got human feedback on your work, re-evaluate it"). It is a review loop, not a pre-execution approval. Pre-execution blocking exists only as an opt-in global `before_tool_call` hook. `Task.guardrail(s)` (callable, or a string that becomes `LLMGuardrail`, plus `HallucinationGuardrail` with a faithfulness threshold) validate output with up to `guardrail_max_retries=3` retries with feedback. Flow `human_feedback(emit=[...])` collapses free-text into an emit label via an LLM. CONFIRMED (`SRC/agents/crew_agent_executor.py:265-266`, `SRC/core/providers/human_input.py:60-364`, `SRC/task.py:233,252-280`, `SRC/tasks/llm_guardrail.py`, `SRC/tasks/hallucination_guardrail.py:20-84`, `SRC/flow/human_feedback.py:83-110,402-418`).
- Telemetry is on by default; disabled only if `OTEL_SDK_DISABLED` or `CREWAI_DISABLE_TELEMETRY` is set; `share_crew=True` additionally exports task outputs. CONFIRMED (`lib/crewai-core/src/crewai_core/telemetry.py:356-357`, `SRC/telemetry/telemetry.py:307-568`).
- Manager isolation: the hierarchical manager is forbidden to hold tools other than delegate/ask (it raises). CONFIRMED (`SRC/crew.py:1532-1542`).

## BEST PARTS

1. **Manager-has-no-tools rule.** Idea: the orchestrator may only delegate and ask; it never executes. Evidence: `SRC/crew.py:1532-1542` raises `"Manager agent should not have tools"`. Sector: executive (CEO). Why: it hard-codes the CEO's role as planner/delegator, which is exactly our invariant 3 shape and makes CEO runs cheap and auditable.
2. **Isolated-context delegation with explicit "they know nothing" contract.** Idea: delegation is a tool call that spawns a fresh Task for the callee with only the string the caller wrote. Evidence: `SRC/tools/agent_tools/base_agent_tools.py:110-125`, `SRC/translations/en.json` `tools.delegate_work`. Sector: executive + engineering (ephemeral scout/worker). Why: forces the delegator to write a complete brief, which is what makes child runs replayable from the event log and keeps ephemeral agents template-bounded (invariant 6).
3. **Blocking pre-tool-call hook with typed abort.** Idea: `before_tool_call` returning `False` or raising `HookAborted(reason, source)` refuses the call before execution and records why. Evidence: `SRC/hooks/tool_hooks.py:142-192`, `SRC/hooks/dispatch.py:75-83`. Sector: kernel (policy gate). Why: it is the right seam for gate → approval → quarantine; we already do this in the kernel, and their `HookAborted.source` field is a good idea for attributing which policy refused.
4. **Path-scoped memory with `root_scope`, `private`/`source`, and importance/consolidation.** Idea: memory addressed by `/crew/<id>/<scope>` paths, per-source privacy, LLM-inferred importance, near-duplicate consolidation, confidence-thresholded recall depth. Evidence: `SRC/memory/unified_memory.py:76-162`, `SRC/memory/types.py:20-73,135-276`, `SRC/memory/memory_scope.py`. Sector: kernel (pmmcp `project_id` namespacing), growth/trading (per-sector scopes). Why: maps directly onto `aos/ceo`, `aos/agent/<id>`, `aos/shared`; `private+source` gives a clean rule for tainted-run memories (comms ingress) not leaking into other agents' recall.
5. **Task-output guardrails with bounded retry-with-feedback.** Idea: callable or LLM guardrails on a task's output, `guardrail_max_retries=3`, feedback fed back to the agent, `HallucinationGuardrail` with faithfulness threshold. Evidence: `SRC/task.py:252-280,1327-1400`, `SRC/tasks/llm_guardrail.py`, `SRC/tasks/hallucination_guardrail.py`. Sector: growth (writer/marketing/social), trading (checker). Why: a cheap, logged QA loop for content and for a trading `checker` verifying a proposal against source data before any human sees it; bounded retries keep budgets honest.
6. **Hard per-agent caps: `max_iter`, `max_rpm`, `max_execution_time`, per-tool `max_usage_count`, repeated-call detector.** Evidence: `SRC/agents/agent_builder/base_agent.py:275-289`, `SRC/tools/base_tool.py:184-195`, `SRC/tools/tool_usage.py:254-260,427-447`, `SRC/utilities/rpm_controller.py`. Sector: kernel / engineering (coding fleet). Why: per-tool usage quotas in the manifest (e.g. `github.create_pr: max 1`) are a small, enforceable addition to our budget model.
7. **Flow `human_feedback(emit=[...])` with lesson distillation.** Idea: a human review node whose free-text answer is collapsed to a declared outcome label, and whose feedback is distilled into memory and pre-applied on the next review. Evidence: `SRC/flow/human_feedback.py:83-110,279-418`, `SRC/flow/persistence/sqlite.py:114` (`pending_feedback` table). Sector: executive (approvals UX), growth (publisher review queue). Why: gives approvals a structured verdict for routing plus a learning loop, and the persisted `pending_feedback` table is the same idea as our restart-safe approvals projection.
8. **Dependency-ordered event handlers.** Idea: listeners declare `Depends(...)`, resolved into parallel execution levels with cycle detection. Evidence: `SRC/events/handler_graph.py`. Sector: kernel. Why: a clean way to guarantee "redact → hash → chain → project" ordering for our event store listeners without ad-hoc sequencing.
9. **Eval metric set.** Idea: goal alignment, reasoning efficiency, semantic quality, tool selection, parameter extraction, tool invocation as separate LLM-judge evaluators. Evidence: `SRC/experimental/evaluation/metrics/*.py`. Sector: engineering (Phase 1 eval harness). Why: a reasonable starting taxonomy for scoring orchestration runs against the mock hub.

## BAD PARTS / anti-patterns

1. **Role-play theater as the core abstraction.** `role/goal/backstory` strings are the entire agent definition; the "Crew Manager" backstory ("seasoned manager with a knack...") is prompt padding, not capability. Evidence: `SRC/agents/agent_builder/base_agent.py:256-258`, `SRC/translations/en.json`. Why leave out: our manifests are capability/tier/egress/budget data; persona lives in `souls/*.md`, read-only, and never stands in for policy.
2. **Delegation by fuzzy string match, unbounded, in-process.** Coworker chosen by casefolded role string; missing agent returns an error string to the LLM; no depth cap, no cycle guard, no budget split; callee runs synchronously in the caller's thread and shares process memory and env. Evidence: `SRC/tools/agent_tools/base_agent_tools.py:57-135`; no `delegation_depth` anywhere. Why leave out: violates our lane/run model; delegation must be a kernel `run.spawn` with `goalId`, tier ceiling, budget slice, and depth cap.
3. **Credentials in the agent process.** Tools and LLM clients read API keys from `os.environ` in the same process that runs the model loop. Evidence: grep in `lib/crewai-tools/src/crewai_tools/tools` (`SERPLY_API_KEY`, `TAVILY_API_KEY`, `OPENAI_API_KEY`, `BROWSERBASE_API_KEY`, ...). Why leave out: invariant 2.
4. **No sandbox; code execution deprecated to "use a hosted service".** Evidence: `SRC/agent/core.py:293-322,1397-1471`; `e2b_sandbox_tool`, `daytona_sandbox_tool`. Why leave out: invariant 9 requires local Docker with hardened flags; hosted sandboxes ship the workspace to a third party.
5. **Human input is post-hoc review, not a pre-execution gate; the model can be asked to read the human.** `human_input` fires after the final answer; Flow `human_feedback` uses an LLM to collapse the human's text into an outcome label. Evidence: `SRC/agents/crew_agent_executor.py:265`, `SRC/flow/human_feedback.py:87-110`. Why leave out: invariant 3 puts the human before execution for `irreversible`/tainted writes, and the verdict must be a typed control-plane command, never an LLM interpretation of prose.
6. **Ungated shared-memory writes and default-on telemetry.** Any agent with memory gets `Save to memory`; telemetry exports unless an env var is set, and `share_crew` ships task outputs. Evidence: `SRC/tools/memory_tools.py:75-110`, `lib/crewai-core/src/crewai_core/telemetry.py:356-357`. Why leave out: memory writes are `write`-risk tools that go through the gate (taint rule), and nothing leaves the Mac without a logged proxy decision.
7. **Security module is a placeholder.** `SecurityConfig` docstring lists auth, scoping and delegation tokens as `*TODO*`; the only implementation is a uuid5 fingerprint. Evidence: `SRC/security/security_config.py:14-30`. Why leave out: not a model to borrow; it shows the framework treats access control as future work.

## Conflicts with CLAUDE.md invariants

1. Invariant 2 (agents never hold keys): tools/LLM clients read keys from env in-process. (`crewai_tools` grep; `SRC/llm.py` INFERRED same pattern, not read.)
2. Invariant 3 (gate on every call, human before irreversible): no default-deny; hooks are opt-in globals; `human_input` is post-answer; LLM collapses human verdicts.
3. Invariant 4 (two events per LLM call with cost): `LLMCallCompletedEvent` carries `usage` dict but no cost field. (`SRC/events/types/llm_events.py:97`.)
4. Invariant 5 (hash-chained immutable log): event bus is in-memory fan-out; Flow persistence is a plain SQLite table with no chaining or immutability triggers. (`SRC/flow/persistence/sqlite.py`.)
5. Invariant 6 (ephemeral bounded by template): delegated Tasks inherit the callee agent's full tool set and have no tier/egress ceiling or depth cap.
6. Invariant 7 (unknown MCP tools kernel-only): `StaticToolFilter` with empty allowlist allows every tool; default is allow-all. (`SRC/mcp/filters.py:62-88`.)
7. Invariant 9 (hardened containers): no container driver in core.
8. Invariant 3 corollary (model never makes access-control decisions): `LLMGuardrail` and `human_feedback` collapse use the model to decide pass/fail and route outcomes.

## Verdict

Take the shape, not the runtime: the tool-less manager rule, "callee knows nothing" delegation briefs, path-scoped memory with `private`/`source`, bounded guardrail retries with feedback, per-tool usage quotas, dependency-ordered event handlers, the `pending_feedback` persistence idea, and the eval metric taxonomy. Leave the role/goal/backstory persona theater, in-process fuzzy-string delegation, env-var credentials, hosted-sandbox-only execution, post-hoc human review, LLM-interpreted human verdicts, ungated memory writes, and default-on telemetry. Net: crewAI is a useful catalogue of orchestration ergonomics but its security posture is the same anti-pattern as OpenClaw and nothing from its runtime should be imported.
