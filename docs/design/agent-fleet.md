## 1. Executive summary

The fleet is **16 persistent agents and 15 ephemeral templates** across five sectors — executive, engineering, growth, trading, ops-security — plus **11 template profiles/soul sets** that reuse an existing manifest rather than adding one. Every agent earns its manifest through a distinct tool surface, isolation need, taint posture, model binding, context boundary or gate posture; anything that failed that test became a soul, a profile, a tool view, or kernel code. Fourteen things a first pass wanted to make agents are kernel subsystems instead: the risk officer, the ledger, the reconciler, the backtester, the market-data pipeline, the backup steward, the skills curator, the ingress edge, the approval relay, the watchdog, the scheduler, the egress proxy, the presenter engine adapter, and the content/suppression/lead projections. A backup schedule is an `if` statement; giving it a persona costs prompt tokens, an eval suite, a budget line and — for the backup key — an invariant-2 hazard.

Topology: **one orchestrator, depth 1**. The CEO is the only manifest with `role: orchestrator`; it plans an operator objective into a pmmcp goal tree, fans out isolated sibling runs with `dependsOn`, and is never blocked — a delegating CEO run *ends*, and the kernel schedules a continuation when the subtree comes to rest. Sector leads (`eng-lead`, `marketer`, `quant`) are non-delegating planner-workers that return a `ProposedPlan` the CEO adopts; the per-task pipelines they used to want to dispatch (implementer → tester → reviewer → integrate; writer → checker → publisher; scout → quant → critic) are **kernel DAGs of deterministic nodes with gated model nodes**, so advancing a DAG costs no model turn and no delegation level. Capability flows one way and only narrows: a child's envelope is (parent ∩ template ∩ spawn spec), the kernel computes taint from artifact provenance rather than believing a spawner, and no descendant may hold an approval-bearing tool its parent could not hold. Every side effect goes gate → (human) → (quarantine) → execute → log, default deny, with the model never deciding access.

## 2. Design principles

### 2.1 The invariants, restated as fleet rules

Each is CLAUDE.md's, phrased as something a roster can be checked against.

1. **No agent has a network identity.** Control plane is loopback + bearer; no agent reaches it. `fleet.halt`, `agent.promote`, `quarantine.release`, `mandate.issue`, `trading.mode.set`, `restore_backup` are `HumanActor` commands with no agent-facing tool at any tier (§7.7).
2. **No agent holds a credential.** Hub, router and broker are kernel-only; workers get credentials injected at the egress-proxy edge, bound to one hostname, never in env or on disk. Every credential holder outside the vault is inventoried in §7.10 — the publishing edge (accepted, five conditions, §13 Q13), the assistant's PIM OAuth (vault-held, kernel-refreshed, therefore not a second store), and the egress sidecar (holds a reference and a grant id, never material).
3. **Every tool call is gated, default deny, and the model never decides.** `irreversible` always reaches a human. A tainted run cannot call a `write` tool without a human. One candidate exception is proposed and **not adopted by default**: the fail-safe suppression write (`suppress.add`), marked `failSafe: true` in `tool-views.yaml` rather than hidden as a carve-out. Because it would narrow a non-negotiable invariant, it is an open decision, not a settled design (**§13 Q26**), and the shipping default is the kernel-side executor that needs no carve-out at all.
4. **Every LLM call is two logged events with cost** — including auxiliary lanes, condenser calls and per-persona simulation turns. "Auxiliary" never means "unlogged".
5. **The log is the truth.** Redact → canonicalize → hash → chain; UPDATE/DELETE refused; `verifyChain` after every writing test. Scores, KPIs and verdicts are computed from the log and the artifact store, never from a `RunResult` summary.
6. **An ephemeral agent cannot exceed its template.** Promotion is a human control-plane act; archive never deletes.
7. **Unknown tools are `kernel-only`.** Secret tools, `admin`, `restore_backup`, `delete_context_source`, `index_project` stay kernel-only; `coding_agent`, `session_insight_agent` and GitHub's `request_copilot_review` stay `disabled` — a nested LLM call bypasses router, budget, taint and log.
8. **Souls and `AGENTS.md` are read-only to agents.** The curator may file a proposal; no code path lets a run write them.
9. **Containers are `--read-only`, `--cap-drop=ALL` with no `CapAdd`, `no-new-privileges`, non-root, capped, internal-network, hard wallclock.** This survives contact with the offensive sector: `pentester` gets no `NET_RAW` (§13 Q12).
10. **`__` in provider tool names, dots everywhere else.** One mapping, `toolName`/`toolRef`.

* **Idempotency key minted before the confirmation prompt; mutation receipts keyed `pending|completed`.** eliza `src/security/trade-confirmation.ts` (CONFIRMED); orca `create-core-tables-sql.ts:96-107` (CONFIRMED).
* **Fail-closed egress bootstrap; audit by credential fingerprint, never value; re-evaluate established flows on policy change.** CubeSandbox `CubeEgress/lua/bootstrap.lua:14,57,104` and `audit.lua`/`redactor.lua` (CONFIRMED (survey)) — with their default-allow L3 inverted to deny-all.
* **Untrusted content is framed, escaped and never truncated.** odysseus `src/prompt_security.py` guard-marker escaping and standing policy header (CONFIRMED); ruflo's deterministic no-model guardrail that refuses rather than truncates (`tool-output-guardrail.ts`, CONFIRMED).
* **Provenance envelopes on memory, fail closed when missing; a single curated writer.** openclaw `docs/concepts/memory-architecture.md:71,172` (CONFIRMED); eliza `access-control/provenance-envelope.ts` (CONFIRMED (survey)).
* **Claim-before-deliver scheduling with coalesced missed ticks.** prime-agent `src/core/cron-jobs.ts` `claimDueInState` (CONFIRMED (survey)).
* **Three-valued liveness; absence never authorises stop, abandon, retry or release.** orca (CONFIRMED (survey)). Mastra's counter-example — blanket boot recovery re-issuing paid calls — is why we emit `run.orphaned` (`mastra/index.ts:614-629`, CONFIRMED (survey)).
* **Evals are gates (must be 1.0, block a binding or a promotion) or scorers (tracked thresholds).** mastra `evals/thresholds.ts` (CONFIRMED (survey)); prime-agent's artifact-only scoring with cheat fixtures (`scripts/evals/swarm_fanout/scorer.py`, CONFIRMED).
* **Compare every fleet shape against a single agent at equal spend before adopting it.** landscape anti-pattern 7 (CONFIRMED (survey)); sequential tasks degrade 39–70% under multi-agent variants (INFERRED (snippet) arXiv 2512.08296).
* **The privileged planner never reads raw untrusted data; a quarantined reader does.** CaMeL (INFERRED (snippet)). This is our taint rule plus §7.2's declassification.

### 2.3 The frontier-not-theater rules the roster was filtered through

1. An agent exists only for a distinct **tool surface, isolation need, taint posture, model binding, context boundary or gate posture**. Otherwise it is a soul, a profile, a tool view, or kernel code.
2. A deterministic job never gets a persona. If the judgement in the loop is an `if` statement, it is kernel code.
3. A model may **subtract** authority (a verdict, a flag, a block), never add it.
4. Verification is execution-grounded first, rubric second, and always in a fresh context.
5. Every number that bounds behaviour (budget, cap, window, quota, limit) is kernel-enforced config, never prompt text.
6. Every claim carries a resolvable evidence reference, or the kernel downgrades the claim (§7.6).

### 3.2 Depth

`KERNEL_MAX_DEPTH = 1`; the manifest schema already pins `spawn.maxDepth: literal 1` and every non-CEO manifest ships `spawn: none`. The engineering sector's first draft wanted `eng-lead` at `role: orchestrator` (depth 2); the executive layer's resolution stands: **`eng-lead` is a non-delegating sector lead in Phase 1**, and a registry refinement refuses an `orchestrator` manifest that is not the CEO. The two things depth 2 bought — a per-objective integration worktree owner and a `request_changes` route back to the *same* implementer — are kernel state (`ownership.paths` on the spawn spec; `retryOf: runId` reusing the prior child's workspace), not a delegating agent. The only sanctioned exception is a human `depth-raise` Mandate for one named agent, expiring, after the Phase 1 harness shows lead-mediated fan-out beating CEO-direct fan-out at equal spend (§13 Q3).

Why the ceiling is not a preference: Hermes' post-mortem numbers above; orca's fence default; Cognition's 2026 position that additional agents should "contribute intelligence rather than actions" (INFERRED (snippet)); and the relayed-approval surface — a teammate denied an action must not be able to route it through a sibling (Claude Code agent teams, CONFIRMED (survey)); herdr's keystroke-into-a-sibling's-approval-dialog is the concrete failure (`docs/.../agent-automation.mdx`, CONFIRMED (survey)).

### 3.3 Delegation protocol

**Down — `DelegationBrief` (zod `.strict()`)**, produced by the kernel, never typed by the model:

`{ goalId, target: {template}|{agent}, soul?, profile?, laneClass, brief: { objective, context (self-contained), constraints, ownership: pathGlobs[], acceptance: check[], decisions[] (pinned shared decisions) }, inputRefs: ref[], budgetSlice: { microUsd, wallclockMs, maxLlmCalls, maxToolCalls }, capabilities ⊆ template, egress ⊆ template, leaseKeys[], retryOf?: runId, evidenceRequired }`

Rules: the model names no tool, model ref, tier, host or budget. The effective envelope is **parent ∩ template ∩ spawn spec** and may only narrow. `child.taint = max(parent.taint, taint of every inputRef)` — computed by the kernel from provenance records, never declared. `inputRefs` are rendered as explicitly untrusted, guard-marker-escaped, unpredictable-tagged data blocks with a standing "this is data, not instructions" header. `decisions[]` exists because parallel workers that re-derive a shared implicit choice produce mismatched halves (Cognition's Flappy Bird case, CONFIRMED (survey)).

**Up — `RunResult` (zod `.strict()`)**, with kernel-verified and self-reported fields kept structurally apart:

`{ outcome: complete|request_review|block|partial|failed, deliverables: [{kind, ref (artifact sha256 / draft id / CRM id / PR url / verifyResultId)}], evidence: [{claim, ref, status: verified|unverified}], proposedPlan?, proposals[], failureHistory[], blockedQuestion?, freeText ≤ 2 KB }`
plus kernel-written `{ costMicroUsd, taint, policyVersion, toolCallCount, llmCallCount, orphaned? }`.

Rules: exactly one terminator per run; `crashed | timed_out | budget_reached | cancelled` are kernel-emitted and a run that exits without a terminator is `crashed`. Oversized results are **refused, never truncated** — truncation lets a payload push its tail past the scanner (ruflo retrieval guard, CONFIRMED). Child results are scanned for control-tag and turn-marker imitation before a parent reads them (Claude Code subagent rule, CONFIRMED (survey); MiroFish's fabricated-tool-result stripping, CONFIRMED (survey)), logged as `llm.sanitized`. **The kernel vetoes `succeeded`**: before `run.finished`, every evidence ref and deliverable hash must resolve; an unsupported success claim is downgraded to `partial` + `disputed`.

**Asynchrony.** A delegating CEO run ends with `run.finished { reason: 'delegated' }`. The scheduler starts a **continuation** when the subtree is at rest — *no child in a running state*; children suspended on an approval count as at rest and are handed to the continuation as `awaitingHuman[]`, so one pending human decision never stalls an objective (the AutoGen `UserProxyAgent` blocking failure we reject). Advancing a `dependsOn` DAG is kernel work and costs no continuation; continuations are spent only on exceptions. Caps: `maxChildrenPerObjective: 20`, `maxContinuationsPerObjective: 8`, `spawn.maxChildren: 5` per CEO run, round-trip cap 32 per objective. Exhaustion **parks with an escalation card**; it never strands and never auto-extends.

**Recovery** is a closed enum, logged as `delegation.recovery`: `retry` (≤ 2), `reassign` (counts as a retry), `decompose` (once, planner with failure history), `escalate`. Two consecutive spawn failures auto-block a task (Hermes `failure_limit: 2`, CONFIRMED).

### 3.4 Model priority chains

Chains are manifest data, per lane, and a chain is **never inherited from the spawner**:

```
model:
  primary: anthropic/claude-opus-5
  fallbacks: []
  editorModel: local/bonsai            # writing templates: proposer/editor split
  lanes:    { plan, judge, summarize, classify, embed, vision }
  laneClasses: { cheap: [llamacpp/local, ollama/qwen3:8b, anthropic/<haiku>], standard: [anthropic/<sonnet>], deep: [anthropic/claude-opus-5] }
```

Kernel rules: every ref must exist in `providers.yaml`, carry a **pricing entry** (local models must state `pricing: {input: 0, output: 0, metered: false}` explicitly — no price, no binding), and be routable (`aos probe` with `toolCalling: true`, unexpired TTL) or the lane is degraded and reported. Fallback is one-shot, only before any tokens stream, and always visible as `model.fallback { from, to, reason }`; per-(provider, model) cooldown with per-run dead-marking. Every lane call is an `llm.request`/`llm.response` pair with cost. `orchestrator: true` stays human-set after the eval harness. All refs other than `anthropic/claude-opus-5` are placeholders.

Routing has three tiers with **$0 first**: deterministic (plan rendering, digests, budget arithmetic, goal-status projection, approval cards, observation masking, codemods, money arithmetic); cheap/local (summarize, classify, triage, narration, persona turns) behind a `models.localConcurrency` semaphore (default 1) that falls back with `model.fallback { reason: 'local-busy' }` rather than queueing the 07:00 digest to 07:40; frontier (CEO planning, `planner`, strategy design, milestone `judge`, `deep` reassignments). Scheduled unattended runs are **bound to local lanes by construction** — an unattended run that can reach a frontier model is an unattended run that can empty a monthly envelope.

### 3.5 Budget-aware routing

Objective envelope → child slices are subsets. A spawn **reserves** the child's full budget in the same transaction that claims the lane (`spawn.refused { reasonCode: budget }` queues the task rather than starting a run that cannot pay); unspent reservation returns on `run.finished`, so ceilings may sum above the objective total but reservations may not. Inside a run the router pre-reserves the next request's worst case between model requests, so the ceiling is never crossed. `budget.threshold` events at 50/75/90/100% for run, objective and agent-month. Per-sector objective defaults with one global ceiling above which a human mandate is required. Counterfactual accounting (what always-cheap / always-frontier would have cost) is an **eval output**, never a runtime decision.

## 4. Tier ladder and sandbox domains (final)

Four orthogonal axes. One integer could not express `sre` (weak isolation, must request irreversible ops) or `tester` (strongest isolation, zero write tools), so the starter T-ladder is kept — as the meaning of `sandbox.domain`, not of `tier`.

| axis | field | values | who sets it |
|---|---|---|---|
| capability | `tier` | `0` no tools · `1` read-only MCP · `2` write tools + sandbox exec | manifest (human-authored) |
| isolation | `sandbox.domain` | absent = kernel-hosted (T0) · `process` (T1) · `trusted` (T2, Docker + egress proxy) · `hostile` (T3, Docker, no egress) · `hostile+mandate` (T3 plus a per-run proxy whose whole allowlist is the active mandate) | manifest |
| risk ceiling | `riskCeiling` | `read` · `write` · `irreversible` — the highest class the agent may **request** | manifest |
| delegated authority | `delegateTier` | `1` read+draft · `2` may file `irreversible` requests on its own initiative · `3` may be started unattended by `schedule:` | **human only**, via `agent.promote`, carried by an expiring `Mandate` |

D15's old rung 3 is gone: the irreversible bit lives in `riskCeiling`. **Nothing in any tier auto-approves** — the ladder widens what an agent may *ask for* and *when*, never who decides.

**A risk class is a property of (tool, domain, target), not of a tool name.** The gate resolves it from a `policy` block in `tool-views.yaml`:

| condition | class |
|---|---|
| `ws.exec`/`ws.test` in `hostile`, no egress, overlay discarded, worktree mounted read-only | `sandboxed-exec` (a `read`-ceiling class) |
| `ws.exec`/`ws.test`/`ws.edit`/`ws.commit` against a persisted worktree | `write` |
| `ws.push` to `^aos/` | `write` |
| `ws.push` to any other ref, `git.tag`, `github.merge_pull_request` | `irreversible` |
| `pmmcp.remember` inside the run's own `project_id` | `write-scoped` (bounded by `memory.projectId`) |
| `pmmcp.remember` into `aos/shared` | `needs-human` (`memory-promote`) |
| `venue.simulate` (keyless) / `venue.prepare` / `venue.paper.submit` / `venue.live.submit` | `read` / `write` / `write` / `irreversible` |
| `edge.stage` (self-hosted, loopback) / `publish.schedule` / `email.send` | `write` / `irreversible` / `irreversible` |
| a write that can only **stop** future action (`suppress.add`) | **proposed, not the default** — `write` + `failSafe: true` (would execute on a tainted run; blocking it is the unsafe direction). This narrows invariant 3, so it ships only if §13 Q26 is answered that way; the default is a deterministic kernel executor and no `failSafe` flag exists |
| anything unclassified | `kernel-only` (invariant 7) |

Domains on the operator's machine: `trusted` and `hostile` are the two Colima VMs (`scripts/colima-up.sh`); `hostile+mandate` is the `hostile` VM plus a per-run proxy instance, with no route to the `trusted` VM, the host, pmmcp or the control plane. Apple `container` stays a stub (macOS 15.6.1). Admission is by **declared `sandbox.memoryMb` summed against a per-domain memory budget**, not by counting containers.

### 5.6 Profiles

One paragraph per agent. The sector documents carry the full manifests (tool-view exposure, budget caps, KPIs split into gates and scorers, soul text).

**`ceo`** — the only `role: orchestrator`. Turns an objective into a pmmcp goal tree in `aos/ceo`, adopts plans, fans out siblings with `dependsOn`, collects typed results, picks recoveries from a closed enum, and writes an objective summary in which every claim carries a resolvable `evidence.ref`. Its tools are pmmcp goals and recall, `delegate`, `collect`, `catalog.search/inspect`, `events.search`, `request_human`, `request_promotion`, `propose_plan`. It has no shell, no sandbox, no non-pmmcp server and no irreversible tool, enforced by the registry rather than by its soul. It refuses to start tainted; untrusted material reaches it only through a `judge`/`checker` child, which is the CaMeL privileged/quarantined split expressed with our taint rule. Chain: `anthropic/claude-opus-5` with **no fallback** until a second card is probed.

**`planner`** — spawned only when an objective fails the inline-planning test, in the read-only plan phase. Produces a `ProposedPlan`: milestones, junior-sized tasks with acceptance checks, the template per task, a `dependsOn` DAG, budget estimates, pinned shared `decisions[]`, and the **named irreversible inventory** that drives the plan-mandate rule. Its headline KPI is *inventory recall*: an irreversible approval later requested but absent from the inventory is a planner defect.

**`judge`** — fresh-context, execution-free verification reading only the brief, the `RunResult`, the referenced deliverables and the objective's event-log slice — never the worker's reasoning. Emits `GoalVerdict {score, complete, missing[], evidenceChecked[]}`. Advisory always: it can trigger a recovery and inform the goal-status projection, and it never closes an irreversible decision. Its eval scores over-rejection as well as false passes, because a reviewer prompted to find gaps will find some.

**`curator`** — nightly, the fleet's single memory promoter. Dedupes and clusters episodic records across `aos/agent/*` on local lanes, proposes promotions to `aos/shared` (always a human card), archives (never deletes), compacts long `aos/ceo` threads with preimage hashes, and files draft procedures from repeated successful trajectories. It never reads untrusted-origin items into a promotion, never touches souls or manifests, and excludes its own summaries from its inputs.

**`assistant`** — the executive-assistant surface, **always tainted at ingress** by registry force. Its Google/Microsoft OAuth refresh token lives in the pmmcp vault and is refreshed by the kernel hub, which writes the rotation back through `set_secret`; the assistant is therefore not a second credential store and its egress column reads `none` truthfully (§7.10). The kernel gathers the calendar/mail/notes/approvals bundle deterministically behind a singleflight TTL cache; the assistant narrates and emits typed proposals (`reply_email`, `archive_email`, `create_event`, `create_reminder`). Every proposal is a card; acceptance is executed *by the kernel* under the approved `argsHash`. It never sends. Write-class proposals batch into the digest with a 24 h expiry; `email.send`/`reply` are individual irreversible cards showing the recipient as a kernel-rendered field.

**`eng-lead`** — owns one engineering objective per run: converts the CEO's brief into a goal tree, applies the complexity rule (no architect for a single-file fix), owns the integration lane (rebase onto `aos/int/<objective>`, re-run `tester` on merged state, kernel-side push to `aos/*`), files the PR-open card with the full evidence bundle attached, and routes `request_changes` back to the original implementer. It never edits code outside the integration worktree and never answers a blocked worker's question — a `block` becomes a `question` card for the human. In Phase 1 it is a non-delegating sector lead; the per-task pipeline is the kernel DAG.

**`prototyper`** — design brief → running UI on a demo branch with visual evidence. Starts the dev server inside its container, drives a DOM-first/vision-fallback browser loop bounded at 40 actions, uses the Design Mode payload (outer HTML + computed CSS + crop + source map) as its defect input, and ends with `request_review` carrying a screenshot set and a **verified-action ratio** — an unverified click never counts as a pass. Its PRs are draft-only and gate-enforced as such; hardening is a separate objective through the implementer pipeline. It ships in Phase 2a, not Phase 1, because a prototyper without visual verification is an implementer with a nicer soul.

**`sre`** — runs the operator's shipped products through the GitHub/Vercel/Supabase packs. Scheduled read-only reconcile emits `ops.drift`; failures become typed proposals with a rollback plan and an idempotency key minted before the card. Every production op is irreversible and human. Its ingest (logs, webhooks, error payloads) is user-controlled text, so it is tainted by default — which coincides with every op needing a human anyway. `ops.halted` blocks new deploys and **never** auto-rolls-back: kill is halt + persist.

**`scout`** — the fleet's one exploration template, with per-sector profiles. Engineering: hierarchical fault localisation (files → symbols → edit points) and subsystem summaries. Growth: competitor, SERP and channel research. Trading (`market-scout`, four souls): one question, one hostname bundle, one `ResearchMemo` with hashed and dated sources, quotes ≤ 300 chars, counterevidence and a confidence. Only the summary returns; raw pages never enter the log. Tainted whenever `web` is enabled, output quarantined, memo claims stamped `origin: 'untrusted'` so the curator can never promote them.

**`architect`** — plan-only, spawned per objective with a pinned `aos/agent/architect` namespace (it was persistent in a first draft; persistence bought a manifest-versioning ceremony for a thirty-minute run). Produces decomposition with ownership path sets, dependency levels, named acceptance tests, a `codemodFirst` analysis, a "when NOT to fan out" verdict and a risk register of every irreversible touch. A kernel-scored spec-quality rubric runs *before* it: a well-specified brief skips both `scout` and `architect`, which is the cheapest lever in the sector because it spends no tokens.

**`implementer`** — one task, one worktree, one branch, one PR candidate; three profiles on one manifest. `code`: frontier proposer with a local `editorModel` applying diffs. `docs`: local-first chain owning `docs/**`, `README.md`, `CHANGELOG.md`, ADRs. `refactor`: codemod tier first ($0, the target repo's own toolchain), then model edits, under a mandatory `plan.approve` and an **exclusive repo lease**. It edits only its owned paths (a kernel hook denies the rest), runs `ws.test` before claiming anything, and never pushes, opens PRs, touches lockfiles or installs software. Best-of-k spawns k worktrees in one all-or-nothing batch and the `tester` picks.

**`tester`** — the only path to "tests passed" in the log. Mounts a finished worktree read-only plus a writable tmp overlay in the `hostile` domain with no egress, runs the **pinned repo-profile check commands** (never commands read from the target repo's own files), runs the named acceptance/reproduction test, optionally replays a browser acceptance script, and emits `verify.result {pass, checks[], reproductions[], artifactHash, degradedPaths[], testDelta}`. `verify.testdiff` makes a removed or weakened test a hard block plus a `test-removal-ack` card.

**`reviewer`** — fresh context, sees only the diff, the acceptance criteria, the `verify.result` and the hook results. Typed verdict `approve | request_changes | block` with findings that must cite a line and a consequence or the kernel's schema drops them. The `security` soul additionally reads the dependency diff, the secret-scan and witness results and the run's proxy-decision summary. Bound to a different model family from the implementer as soon as a second provider probes.

**`release`** — cuts a release from a clean worktree at a tagged commit: deterministic version from conventional commits, drafted notes, tester run on the tag candidate, then three irreversible approvals in order (`git.tag`, `github.create_release`, `npm.publish`), each with an idempotency key minted before the card. A denial stops the sequence; a partial sequence is a logged resumable state, not a retry. `npm.publish` is deferred until a repo actually publishes.

**`marketer`** — growth sector lead: positioning, campaign plans, SEO (`marketer-seo` soul), analytics reads. Returns a `ProposedPlan` and a `CampaignBrief`; the CEO fans out `writer → checker → publisher` as siblings. Tainted evidence reaches it only as a **declassified extract addressed by hash**.

*Paid media* is the one marketing capability with an irreversible money-movement surface, and the design's default is that it does not exist (§13 Q28). If the operator ever enables it, this is its shape and it adds **no new manifest**: `marketer` owns it, every paid-media verb (`ads.campaign.create`, `ads.budget.set`, `ads.campaign.resume`) is `irreversible`, always carded **per campaign** with a kernel-computed spend ceiling in the card and a kernel-enforced daily cap — never a standing authorisation and never a per-impression decision a model makes. It inherits the two disciplines the landscape supplies: surface the credit/currency cost of every write in the tool view so the router charges it like tokens (Apollo, `survey/landscape-trading-growth.md:182,185`), and ration the paid step behind a confidence gate so spend follows qualification rather than enthusiasm (OpenOutreach, `:171,240`). Crossing a monthly paid-media envelope is a hard refuse, like media spend (§7.3). Until Q28 is answered otherwise, audience reach stays organic.

**`writer`** — drafts source content plus per-platform versions, each with `claims[]` carrying refs. Two-lane binding: deep for long-form, cheap/local for variants. It never publishes and never holds a platform tool. Revision loops are bounded at 3 and driven by `CheckVerdict.findings`, fixing only the listed issues.

**`publisher`** — the only manifest holding `publish.*`. Stages per-network versions on the self-hosted publishing edge, computes slots respecting per-platform caps and inter-post jitter, holds the `(platformAccount)` lease, and files the scheduling card. **Clean-only**: it refuses tainted or untrusted-derived inputs, so an injected competitor page cannot reach a scheduled post through a rubber-stamped `tainted-write`. Account-level verbs (channel connect, OAuth re-auth, DNS) are kernel-only. Never promoted above `delegateTier: 2`.

**`community`** — mentions, comments, DMs and reviews; **always tainted** by registry force. Proposes replies (every one an irreversible card) and files leads into the kernel-written inbox. Blocking an opt-out is the unsafe direction, so suppression must never wait on a human — but under the shipping default the agent does **not** hold a `failSafe` write for it: it files an `inbox`/`suppress` record and the kernel's deterministic opt-out reader (§6.3, KC24) performs the write with no agent and no model in the path, exactly as inbound opt-out replies are already handled. The `failSafe: true` alternative is §13 Q26 and would be a CLAUDE.md invariant-3 amendment. Replies only when mentioned; no likes, follows, reposts or engagement automation exist as tools.

**`sales`** — CRM hygiene, ICP scoring (weights computed by the kernel, reason written by the model), enrichment behind credit envelopes, outreach drafts and proposals whose totals are computed by the kernel's `money.total` helper in integer minor units. Tainted on the first inbound or CRM free-text read, so every write parks as one batched card with dry-run diffs. `email.send` carries `suppression.clear`, `postal.present`, `unsubscribe.present`, `daily.cap` and `warmup.ramp` as gate preconditions.

**`producer`** — the sector's only sandboxed agent: ffmpeg renders, captions and crops in the T2 growth-media image with an exec command allowlist, TTS/image/video calls as metered `media.request`/`media.response` pairs over a deny-all L3/L4 backstop, and the **recorded** presenter path (the live path is a kernel-driven playback session of an approved script with no model in the loop). Artifacts are sha256-addressed and tagged `synthetic: true`; disclosure text lives *inside* the hashed bytes.

**`checker`** — fresh-context verifier with four souls: `brand` (against the human-promoted kit), `policy` (against the operator-authored platform block, never a pack's own description), `facts` (claims against sources, frontier-bound), `media` (T2, transcript pass then cue pass, citations with timestamps). Its verdict may only subtract authority; a `block` the operator disagrees with is overridable with one confirmation, because a verifier that can strand the operator's own content is a denial of service.

**`reporter`** — scheduled narration over deterministic numeric bundles (`marketing`, `pipeline`, `social` souls). Kernel aggregates, model writes prose, local lane only, clean by construction because every free-text-bearing read is off its tool view. First agent to reach `delegateTier: 3` because it produces no cards.

**`focus-group`** — simulated-audience pre-test in the `hostile` domain: a cast built from ICP and released research, rounds in two worlds, per-round metering through the router, and a scenario-labelled report the **kernel** writes into quarantine. Ships disabled; enabled only if a cheap proxy metric beats the `checker-brand` baseline twice. Nothing it produces is ever framed as a prediction.

**`quant`** — trading sector lead. Turns a brief into a `ProposedPlan` (which scouts, which backtests, which signals), runs its evaluator-optimizer loop with `bt.run` inside its own run, files `StrategyCard` proposals (always a human `strategy` card) and stages `Signal` records. The `Signal` schema **has no quantity**: the quant never sizes. Its context is never rendered with a P&L leaderboard of its own strategies — the measured anchoring effect is why performance reaches it only as the bookkeeper's typed `param.review`/`strategy.retire` proposals.

**`executor`** — the only manifest that can request a live submit, and therefore the only one the registry keeps **clean by construction**: it refuses a tainted `run.start` and refuses a brief with tainted `inputRefs`. Its signal source is `signals.read`, returning a `SignalExecView` of numbers, enums and ids only — no thesis, no memo, no prose an LLM wrote inside a tainted run. Sizing, bracket, `clientOrderId` and venue routing are kernel code; the model's outputs are an `OrderPlan` (in `llm` mode) and closed-enum monitor responses (`wait | cancel | replace_within_band | escalate`). Default mode is `deterministic` for the first 60 paper days.

**`bookkeeper`** — scheduled narrator over deterministic state: daily journal, post-mortem per closed position, halt post-mortem, typed proposals (`strategy.retire`, `param.review`, `halt.request`, `wash_sale.note`). It does not reconcile and does not compute P&L; it explains what the ledger and the reconcile job emitted, and every claim carries an evidence ref the harness diffs against the bundle.

**`critic`** — the `judge` template with two trading souls. `bear`: the strongest opposing case, unstated assumptions, which thesis breaker is most likely to fire, and an evidence grade. `compliance-reviewer`: annotates a batch with the deterministic checks the kernel already computed (wash-sale flags, trading window, day-trade count, venue eligibility) plus what the operator must re-read from a primary source. Advisory; never a gate.

**`warden`** — one persistent agent for five lenses, because all five share one tool surface (read-only kernel tools over the immutable log, catalog and projections), one taint posture and one gate posture — zero write tools, not even to its own namespace. `warden-sre` (woken by watchdog anomaly), `warden-audit` (daily; chain, witness, redaction probe, "did any run reach past its template", declassification-laundering audit), `warden-cost` (rollups, counterfactuals, approval-budget burn), `warden-steward` (narrates a failed backup, frames the restore card), `warden-forensics` (operator request only; the one soul that reads payloads, which taints its run). Its monthly-envelope exhaustion raises a `critical` alert rather than going quiet.

**`security-reviewer`** — change control over what the fleet can reach, fired by a trigger rather than the CEO. `exposure`: does this `tool-views.yaml` diff move a tool toward an agent, widen a default, or add a write verb with no precondition, quota or rate limit? `packs`: cross-tool description overlap (split-injection), the five server-fact check, schema-hash pin present, and which existing trust rules the pin invalidates. `skills`: a staged package against the orca TM-01..TM-20 checklist, statically, in a no-egress worker that never executes it. `deps`: ask-before rule, minimum release age, transitive footprint, install-script presence. **It may tighten, never loosen**: a blocking verdict stops a classification; a clean verdict allows nothing by itself.

**`evaluator`** — runs an agent's suite against the in-process mock hub and normalised recorded snapshots, scores gates (1.0) and scorers from the log and artifact store with a read-only judge, and emits `eval.verdict` bound to the exact `definitionHash`. A hash change revokes the pass. Advisory in Phase 1, a hard precondition on `agent.promote` and on every tier/egress/`riskCeiling`/`delegateTier` widening at Phase 5. It scores; it never promotes.

**`pentester`** — instantiated **by the kernel** from a human-signed `PentestMandate`, so no model ever decides to start an offensive run. Recon and analysis classes unattended; anything state-changing on a target is a per-target human card. Isolation is `hostile+mandate` — not `trusted`, because the agent whose job is running attack tooling should not sit next to the coding fleet — with the per-run proxy allowlist *being* the mandate, so scope holds structurally: an injected "also scan corp-partner.com" in a target's response is denied at the proxy, not by the model's restraint. No `CapAdd` of any kind. Findings are typed events, provenance-stamped untrusted; fixes route to engineering as drafts.

**`comms-triage`** — one inbox record in, one label out (`approval-reply | question | task-request | noise`), plus a ≤ 200-char summary and the deterministic pre-pass's injection flags restated as evidence. It holds exactly one tool, `inbox.read`, scoped to the item it was fired for. It cannot enrol, relay, reply, file or resolve — the ingress edge and the approval relay are kernel subsystems, and the relay is bound to paired identity + `argsHash` + TTL nonce + `maxUses`, none of which a message body can supply. Being always tainted costs nothing because it has no write tool to park.

## 6. Sector workflows

Events marked ★ are additions (§11 KC27). Every flow ends with `chain.verify` passing in the test suite.

### 6.1 Executive — objective → goal tree → fan-out → verified summary (Phase 1 exit)

1. `run.start {agentId: ceo, input, goalId?}` → `run.queued`, `run.started {phase: 'plan'}` (read-only gate mode, fail-closed).
2. CEO recalls context (provenance-filtered), then either plans inline (small objective) or `delegate → planner`; `delegation.admitted`★; the CEO run **ends** `run.finished {reason: 'delegated'}`.
3. Planner returns `ProposedPlan` → `delegation.result`★ → subtree at rest → scheduler enqueues a CEO continuation.
4. `propose_plan` → kernel validates and writes objective/milestones/tasks into `aos/ceo` → `plan.adopted`★. **Deterministic mandate rule**: irreversible inventory empty ∧ budget within envelope ∧ no hostile-domain template ⇒ `plan.accepted {by: 'policy'}`★; otherwise one `approval.requested {class: 'plan'}` → `plan.accepted {by: 'human'}`★.
5. CEO fans out siblings with `dependsOn`; each child carries `goalId`; task status → `in_progress` by projection. **Kernel advances the DAG**; no CEO turn per node.
6. Per milestone: `judge` (rounds capped at 3) → `GoalVerdict` → `done` only when `complete` and every acceptance evidence resolves; else the continuation picks a recovery from the enum.
7. Final continuation writes the summary — kernel renders the skeleton, the CEO adds narrative constrained to claims with a resolvable `evidence.ref` — `run.finished {costMicroUsd}`.
8. Restart mid-objective: boot reconciliation classifies each child `live | unverifiable | exited`, emits `run.orphaned`★ for the unverifiable, and **never re-executes**; the next continuation or the human decides.

### 6.2 Engineering — issue → merged PR

1. CEO → `eng-lead` with a self-contained brief; objective goal → `in_progress`.
1b. **Spec-quality triage (kernel, no model)**: a rubric scores the brief (acceptance test named? files/symbols identified? reproduction? out-of-scope stated?) → `plan.routed {score, route, reasons[]}`★. A good score skips `scout` and `architect` entirely.
2–3. Otherwise `scout` × N localise, then `architect` writes the plan; `plan.approve` is required above the budget threshold or when the plan touches deps, migrations, CI or protected paths.
4. Kernel creates one worktree per L1 task (`worktree.created`★), runs a **kernel-owned setup phase** per worktree (pinned `npm ci --ignore-scripts`, registry egress, no model, `setup.result`★), then spawns `implementer` with `egress.allow: []`, up to `maxConcurrent: 3` and only as far as budget reservations and the domain memory budget allow. A checkpoint commit lands on `refs/aos/ckpt/<runId>` after each accepted edit (retention-bounded, profile-disableable).
5. `tester` (hostile) per candidate → `verify.result`★. Best-of-k: the passing candidate with the smallest diff wins; losing branches are kept, checkouts removed.
6. Deterministic hooks on the winner: `verify.secrets`, `verify.deps` (→ `dependency-ack`), `verify.testdiff` (→ hard block + `test-removal-ack`), `verify.witness`, `verify.protected_paths` — each a `tool.hook`★ with `{decision, matchedRule, reasonCode}`.
7. `reviewer` × 2 (code, security), fresh contexts; `request_changes` routes once back to the original implementer at dispatch generation + 1; two consecutive failures auto-block and file a `question` card.
8. `eng-lead` integration lane: rebase onto `aos/int/<objective>`, re-run `tester` on merged state, kernel-side push to `aos/*`.
9. `github.create_pull_request` — `approval: always`, preconditions P1–P6 computed **from the log**; the card carries diff stat, `verify.result`, both verdicts, hook results, dependency-ack state, proxy-decision summary, cost to date and `argsHash`. `pr.bound`★ on the first URL; retries cannot substitute a sibling PR.
10. `github.merge_pull_request` — irreversible, human → task `done`, worktree removed, **branch kept**.

Failure branches: `block` → `question` card (a sibling may never answer it); crash → dispatcher reclaims by PID + spawn fingerprint + dispatch generation; restart → projections rebuild, live worktrees without terminators become `run.orphaned`★; `eng.pause` stops new spawns and PR opens and never kills in-flight work; `aos kill <objective>` cascades, fences every leaf, keeps every branch, and stays `cancelling` until a human clears an incomplete cascade.

### 6.3 Growth — campaign brief → published post

1. CEO → `marketer`; plan names `writer → checker{brand,policy,facts} → publisher`, plus `reporter-social` at T+7d; inventory `publish.schedule × 2` ⇒ one `plan` mandate.
2. `writer` drafts source + per-platform versions with `claims[]` → `content.draft`★ (artifact hashes).
3. Three `checker` siblings in fresh contexts → `check.verdict`★ × 3; one `request_changes` routes a bounded revision (≤ 3) then re-checks.
4. `publisher` acquires the `(platformAccount)` leases or ends with a typed refusal; `edge.stage` × 2 → `content.staged`★; computes slots under `minInterPostMs`; files `publish.schedule` × 2. Preconditions evaluated from the projection: approved hash, verdicts pass, platform window, jitter, eligibility, **disclosure inside the hashed bytes**, lease held, receipt fresh, provenance clean.
5. One card, two items, each showing platform, time, content hash, **provenance lineage**, verdicts, and the model's reason rendered as an escaped quotation. Operator ticks → receipt `pending` → continuation executes under the approved hashes → receipt `completed` → `publish.scheduled`★. A crash between execution and result leaves a `pending` receipt that a second attempt refuses and escalates — it never posts twice. The edge fires on its own clock; its callback is ingested as `publish.published`★.
6. `reporter-social` at T+7d on the local lane → `metrics.recorded`★ with `source` and `seq`.

**Inbound lead → outreach**: the kernel's ingest writes the raw lead into the `inbox` projection with provenance `untrusted` (no card, no model). A scheduled `sales` run reads it, becomes tainted (`run.tainted`★), and every write parks into one batched `tainted-write` card with dry-run diffs; approval re-checks taint and lease **at execution time**. `email.send` is a separate irreversible card with the recipient kernel-rendered from the CRM record. An opt-out reply is ingested by a deterministic kernel reader — **no agent, no model, no approval** — and the next send's `suppression.clear` precondition refuses the address.

**Clip → post (Phase 4 exit)**: `producer` (holding the presenter-session lease) plays back an approved script in echo mode, records, renders with ffmpeg; `checker-media` verifies on the local artifact with timestamped citations; `publisher` stages and files one `publish.schedule`. Exactly one human approval sits between the clip and the post.

### 6.4 Trading — objective → research → strategy card → paper orders (Phase 2a exit)

1. CEO → `quant` (clean: the brief is operator text) → `ProposedPlan`: 6 `market-scout` tasks with named hostname bundles, a design+backtest task, a `critic:bear` task, a `strategy` approval. Irreversible inventory empty (paper) ⇒ plan auto-accepts.
2. Scouts run tainted; pages are quarantined; memos are artifacts.
3. CEO re-delegates `quant` with `inputRefs: [memos]` ⇒ **the quant run is tainted**. `bt.run` × 5 in the `hostile` domain over a read-only point-in-time data mount, each `backtest.result`★ carrying `guardsEnabled`, `datasetHash` and `postCutoff` computed from the bound card's `trainingCutoff`; an in-window window is labelled `contaminated` and excluded. `strategy.propose` → always-human `strategy` card; `signals.propose` × 12 park as one deferred `tainted-write` batch.
4. `critic:bear` over the card and memos → verdict attached to the card.
5. Operator approves the card (`strategy.approved`★, 90 d expiry), ticks 9 of 12 signals (3 expire as logged denies), and issues a **paper mandate**.
6. Scheduler fires `executor` (clean, lane concurrency 1 per venue) at the window open: `signals.read` → `venue.quote` → `venue.simulate` → `venue.prepare` (kernel mints a UUIDv7 `orderKey`, encodes an injective `venueClientId`, `risk.size` sets qty and bracket) → `venue.paper.submit` → `order.acked`★ → fills → ledger. Breakers evaluate on every fill and every mark (15 s polling while a position is open, sampled into the chain at 60 s and on every transition).
7. Reconcile every 5 min (`trading.reconciled`★, claim-before-dispatch, auto-disable into halt after three failures); bookkeeper journals daily.

**Live path (Phase 2-late/3)**: `venue.live.submit` → `needs-human` card carrying `orderKey`/`venueClientId`, kernel-computed qty/notional/stop/take-profit with `sizeReason`, venue and instrument as kernel-rendered fields, `withinMandate`, wash-sale flag, prepared `argsHash`, 120 s TTL. At redemption the gate **re-runs everything** — halted, mandate validity and coverage, lease held, breaker state, `risk.check`, quote freshness and deviation — and a failure emits `approval.voided`★ with no order sent. An ambiguous venue response is resolved by `venue.order.get(venueClientId)` before any resend; a `pending` receipt is never blind-retried at boot.

**Breaker trip**: `trading.breaker.tripped`★ → `trading.halted`★ → kernel cancels open **non-protective** orders and leaves protective stops resting → `bookkeeper` post-mortem → the operator chooses `trading.resume` or a per-position `trading.flatten` card. Nothing flattens automatically. If cancelling would leave a naked position, the halt **escalates instead**, unless the venue carries an operator-signed reduce-only-close pre-authorisation.

**Drift**: a venue position the ledger does not know → `trading.drift`★ → halt. Reconcile resolves what it can by `venueClientId`; what it cannot stays a drift for a human. Absence of a kernel record never authorises the kernel to invent one.

### 6.5 Ops-security — watch, change control, mandate, restore, promotion, ingress

**Invariant watch → automatic fail-closed halt.** A 60 s in-process watchdog tick ($0, no run) reads subsystem state, lane depths, burn rate, hub heartbeats, the incremental chain delta, `witness.verify` and a sampled `redaction.probe`. On drift — a failed chain delta, a missing immutability trigger, an absent security-critical witness marker — the kernel **halts admission automatically**, persists in-flight state, emits `ops.alert {severity: critical, evidenceSeq, reasonCode}`, and **remediates nothing**. The trigger registry wakes `warden` to assemble evidence. `fleet.resume` is always human, over the loopback control plane the halt does not touch.

**Change control.** A proposed `tool-views.yaml` exposure change fires `security-reviewer:exposure` → `secrev.verdict {blocking, reasonCodes[]}` as a typed event (not a card). The operator resolves the findings or keeps the tool kernel-only; the kernel refuses to apply any exposure change without the `HumanActor` action.

**Authorized pentest (Phase 2 sector exit).** Operator signs a `PentestMandate` → the kernel instantiates `pentester` in `hostile+mandate` with the mandate as the proxy allowlist. An injected out-of-scope target is denied at the proxy with `ops.alert` and a dead socket; an `active`-class technique the mandate does not enable is denied by the gate's floors **before any approval path**. Near the call cap a reflector steers to a clean termination. Every network call is a `proxy.decision`; zero credentials exist in the container.

**Backup → restore.** Scheduled encrypted backup of DB + anchor + config + souls + agents, `verifyChain` over the copy, head match, weekly full verify, integrity projection rebuilt from `backup.*` events. A failed verify auto-disables the schedule with machine-readable detail and raises an alert; an ambiguous write is recorded failed and never blind-retried. Restore is a `HumanActor` command with an idempotency key minted before the card; `warden-steward` narrates what it would overwrite, the backup's head, its age and the seq-diff.

**Promotion gate.** `agent.promotion.requested` fires `evaluator` against the exact `definitionHash`; `agent.promote` and every tier/egress/`riskCeiling`/`delegateTier` widening is refused without a passing verdict for that hash (Phase 5 hard; Phase 1 advisory).

**Ingress (Phase 4).** Pairing is checked **before** any attachment is fetched; an unpaired sender is dropped and logged. A deterministic pre-pass stamps `injectionSuspected`; the kernel writes an `inbox` record with provenance `untrusted`; `comms-triage` labels it and can do nothing else. A reply that claims to approve a card cannot: the relay path requires a nonce, the `argsHash`, the paired identity and an unexpired TTL.

## 7. Safety architecture

### 7.1 Taint boundaries

Taint is **kernel-computed from artifact provenance** and is never declared by a spawner, asserted by an agent, or inferred by a model. A run is tainted iff its brief, workspace or context transitively references an artifact whose provenance record is untrusted. A spawn spec may raise taint, never clear it. `child.taint = max(parent.taint, taint of every inputRef)`.

Sources of taint, by sector: web fetches and SERPs, competitor pages, third-party video captions (`scout`, `producer`); social mentions, comments, DMs, reviews (`community`); inbound email, form submissions, CRM free-text that originated from a lead (`sales`, `assistant`); logs, webhooks and error payloads (`sre`); news and social text in trading — which is why `marketdata` is **split**: `marketdata.series.*` (numeric, schema-validated, allowlisted providers) is `taints: false`, while `marketdata.text.*` is `taints: true`, `quarantine: true` and scout-only; target responses (`pentester`); simulated utterances (`focus-group`); any recall with `includeUntrusted: true`, which taints the caller by construction.

Structurally clean by registry force: `ceo` (refuses a tainted start), `executor` (refuses a tainted start *and* a brief with tainted `inputRefs`), `publisher` (refuses tainted or untrusted-derived inputs). Structurally tainted by registry force: `assistant`, `community`, `market-scout`, `pentester`, `comms-triage`.

**The trading taint boundary is the operator decision this design flags loudest.** Scouts read the web and are tainted; the quant consuming their memos is tainted; therefore `signals.propose` parks for a human. The human's approval of a signal batch is the single point at which untrusted research becomes an input the clean executor may read — and what it declassifies is the **decision** (a numeric `SignalExecView`), never the prose. The alternative, a kernel rule treating a scout's zod-validated `numbers[]` as clean, is specified in the trading document and is **not** the default: the attacker chooses the numbers, so a schema is not a security boundary (§13 Q1).

### 7.2 Declassification — the only way taint goes down

`quarantine.release` is a control-plane command by a `HumanActor`; no agent tool can reach it, and the CEO may only file `request_human {class: 'declassify'}`. It binds **bytes, not runs**: an extract of ≤ 8 KiB with its own sha256, optionally schema-validated, scoped to an objective (and optionally one agent), with an expiry (30 d) and a `revokedAt` that blocks new reuse. The release produces a **new clean artifact addressed by that hash**; the source stays tainted forever and one changed byte is a different, tainted artifact. Bulk release is a batch of individually hashed extracts. There is no command that makes a run clean.

Two consequences the design depends on: **approving a `tainted-write` is not a declassification** (the operator authorised the write, not the bytes; a staged draft keeps `untrusted-derived` provenance and the clean-only publisher still refuses it), and **a publish card whose content hash descends from an untrusted ancestor says so, with the chain**. Both close a laundering path from an injected page to a scheduled post.

### 7.3 Approval design and the fatigue budget

A gate the operator rubber-stamps is worse than no gate, because the log then records consent that was never given. Every mitigation below is deterministic; **none lets a model or a timeout approve**.

*Card* (`approval.requested`): `{approvalId, class, runId, agentId, goalId, objectiveId, toolRef, argsHash, argsPreview ≤ 500 chars redacted, modelClaim ≤ 300 chars rendered as an escaped quotation, consequence (kernel-derived), alternatives?, withinMandate?, mandateId?, idempotencyKey, requestedAt, expiresAt}`. The rename from `reason` to `modelClaim` is deliberate: an unbounded model string on a card is a second-order injection channel aimed at the human. *Resolution* (`approval.resolved`): `{approvalId, decision: approved|denied|expired, actor {connectionId, kind: 'human'}, resolvedAt, argsHash, clientOrigin?}` — a durable consent record, bound to the exact argument bytes.

Classes: `irreversible`, `tainted-write`, `plan`, `promotion`, `escalation`, `memory-promote`, `declassify`, `question`, `strategy`, `dependency-ack`, `test-removal-ack`, `lease`, `budget-raise`.

Dampers, in order of effect: **produce fewer asks** (prefer `simulate` → `prepare`/`stage`/`dry_run` → `submit`, so the irreversible card shows the staged preview's hash); **one mandate per objective** for the plan and its inventory; **batch as a view** (one card, per-item ticks, each its own `approval.resolved`, irreversible items never collapsed); **deferral classes** (`tainted-write` and `memory-promote` into the digest window with long expiry; `irreversible` and `escalation` notify immediately); **back-pressure** (when the unresolved deferred queue exceeds `approvals.dailyBudget`, the scheduler refuses to start new unattended card-producing runs and logs `schedule.skipped {reason: 'approvalBacklog'}` — nothing auto-approves, nothing expires early, in-flight and operator-started runs are untouched); **hard refuse over a card for metered third-party spend** — crossing a media provider's monthly envelope produces a denial with a reason code, not a `budget-raise` card, because a card at that boundary is exactly the rubber-stampable ask this section exists to avoid and the money is already irreversible (a *per-run* overage remains a `budget-raise` request, consistent with §3.5); **pinned commands** in `config/repo-profiles.yaml` to remove a recurring exec-approval class without growing an agent-side allowlist; **`maxOpenApprovals: 3`** per lead so the fleet slows to the operator's review rate instead of building a backlog cleared by clicking.

Expiry is **fail-closed**: a card that expires resolves to `denied` and interrupts the waiting run (24 h default, 2 h for `question`, 120 s for a trading ticket). Where the operator is away, the Phase 1 semantics are **suspend-then-continue**: the run ends `suspended`, the approval persists in a restart-safe projection, and an approval resumes it as a continuation in which the gated tool executes first under the same `argsHash` — made safe by the receipt in §7.4.

Phase 3 **scoped trust rules** (protocol v2, ask-before) are restricted to an allowlist of one class: `write`-from-a-clean-run, exact argument shape, one named tool, `maxUses`, expiry, issuer, invalidation on tool-schema drift, and void whenever the run is tainted at execution time. Permanently excluded: `irreversible`, `tainted-write`, `memory-promote`, `declassify`, `plan`, `promotion`, `escalation`. "Non-irreversible" was the first draft's rule and would have auto-approved exactly what invariants 3, 6 and 7 reserve for a human.

What a model may do around approvals: attach a `hint: routine | novel` and a one-line summary. Cards are ranked by class and age, never by the hint. There is no approval-triage agent: a model between the operator and the decision is the failure mode, not the fix.

### 7.4 Exactly-once execution

The `approvalId` is minted **when the card is filed** and is the idempotency key on the card. A receipt row `{approvalId, toolRef, argsHash, state: pending|completed, resultRef}` is written `pending` *before* the call and `completed` after, as a projection of `tool.call`/`tool.result`. A second execution against `completed` is refused; against `pending` it is refused and escalated as an ambiguity, because absence never authorises retry. Trading order idempotency is a **specialisation** of this, not a second mechanism: the kernel mints a UUIDv7 `orderKey`, encodes a per-venue injective `venueClientId`, records both on `order.prepared`, and `submitWithRecovery` looks up by `venueClientId` before any resend.

Single-writer state is the other half, and it is one mechanism too: a compare-and-set **lease table** (`lease.acquired|released|expired`) keyed by platform account, thread, CRM record, inbox item, presenter session, repo (exclusive refactor), signal id and venue id. Acquired at admission for the keys the brief names, released on `run.finished`, expired by the kernel on an orphan, `lease.held` re-evaluated at execution time, and a second claimant refused with a typed reason — never queued, never resolved by a model.

### 7.5 Trading risk policy (kernel-enforced, paper by default)

The LLM never touches the trade. `config/trading.yaml` + `src/trading/risk.ts` hold limits (`maxNotionalPerOrder`, `maxOpenNotional`, `maxPositionsOpen`, `riskFractionPerTradeBps`, `maxOrdersPerDay` 10 paper / 3 live, `maxPriceDeviationBps`, `maxSlippageBps`, `maxSpreadBps`), breakers (daily loss, max drawdown, mark-to-market, cooldown, fee erosion, overtrading, naked position, stale mark), venue blocks (`bracketSupport`, `onProtectiveFailure`, `clientIdFormat`), marks (15 s while a position is open), keys (90 d rotation warning, 180 d hard stop that degrades the venue to paper), and the promotion block. `risk.size` computes quantity and an ATR-scaled bracket; `Signal` and `OrderPlan` have **no money fields**; the executor's context contains no leaderboard and no research prose.

Floors run **first**, before any approval or mandate path, and cannot be approved away: `halted`, `kernel-only`, `irreversible`, taint denials, out-of-scope, out-of-mandate. `trading.mode` defaults to `paper`; `live-*` requires `promotion.eligible` (60 paper days, 100 paper orders, zero drift, zero naked positions, paper beats the benchmark net of fees, both drills fresher than 45 days, key probe passed) and an override is its own logged `trading.mode.force`. Keys are trade-only, withdrawal-disabled, IP-allowlisted (the allowlisted IP *is* the proxy), attested and probed where a permission endpoint exists; a key whose probe reports withdrawals enabled is refused. Kill = halt + persist: cancel open non-protective orders, keep protective stops, never auto-flatten. Mandates bound what may be *prepared*; under the default they do not change who decides a live submit (§13 Q2).

### 7.6 Evidence and verification

`done` requires execution-grounded evidence plus a rubric verdict, and the kernel vetoes unsupported success (§3.3). A model verdict may only subtract authority. Verifiers read artifacts and the event-log slice through read-only tools, never the worker's reasoning. Every KPI is split into **gates** (must score 1.0; block a model binding, a `delegateTier` promotion, a `trading.mode.set`) and **scorers** (tracked thresholds), and every score is computed from the log and the artifact store with cheat fixtures (fabricated answer, silent drop, no-spawn, double-spawn, unresolvable id, verdict without minimum evidence reads) in the self-test set. Every fleet shape is compared against a single agent at equal spend before adoption.

### 7.7 Self-preservation rules (fleet-wide)

No agent tool exists, at any tier, that: halts or resumes the fleet or the trading sector; silences an alert; re-arms or creates a schedule; mutates the witness manifest, `tool-views.yaml`, `trading.yaml`, `pentest-scope.yaml`, `repo-profiles.yaml`, a soul or an `AGENTS.md`; raises a budget or a cap; issues, extends or renews a mandate; resolves, batches or expires an approval — including its own; releases a quarantine; promotes an agent; restores a backup. The running kernel never loads policy, config or souls from a worktree it manages, and invariant-test removal is denied at edit time against a repo-pinned witness manifest of normalised content hashes (never line numbers).

### 7.8 Authorized pentest scope

`config/pentest-scope.yaml` (zod `.strict()`, no secrets) enumerates operator-owned assets. A signed `PentestMandate` carries a scope ⊆ that file, a technique set (`recon`/`analysis` read-class; `active` irreversible per target; `destructive` flagged and carded), `maxUses`, `expiresAt`, `revokedAt`, on an event-seq-anchored clock. The gate precondition `target.inScope` parses the arguments; the per-run proxy allowlist *is* the mandate, so scope holds even when the model is injected. An out-of-scope egress host is refused at **config load**, not at runtime. The registry refuses a `pentester` run without an active mandate, and mandate expiry, revocation or `maxUses` exhaustion RSTs open sockets.

### 7.9 Social posting gates

`publish.*` is irreversible and always carded, at every `delegateTier`. Preconditions read from kernel projections, not from prompts: approved content hash, all checker verdicts pass, platform window and daily cap, inter-post jitter, account eligibility, **synthetic-media disclosure inside the hashed bytes**, lease held, receipt fresh, provenance clean (a hash descending from an untrusted ancestor is refused unless declassified), `replyOnlyWhenMentioned`, DM policy. The platform policy block is operator-authored in `tool-views.yaml` and is **never** parsed from a pack's description or annotations. No like/follow/repost/engagement-automation tool exists. Duplicate-detection evasion (the "image MD5 variation" trick that sits two lines from the caps we did adopt) is rejected: we respect the control by not cross-posting identical content. Email outbound carries suppression, postal address, unsubscribe header, daily cap and warmup ramp as preconditions, with opt-out ingestion running as a deterministic kernel reader that needs no approval.

### 7.10 Credential injection at the edge

Agents hold nothing. The hub, router and secrets broker are kernel-only; the vault is pmmcp's (`get_secret`/`set_secret`, Fernet + keyring, audited), and the kernel is its only caller. Workers that need a credential get it **substituted at the egress proxy**, bound to one exact hostname, as an opaque sentinel under the real env name, revocable per process. **The sidecar holds no secret material.** Its policy document carries a secret *reference* plus a per-run grant id, never a value; at inject time it calls the kernel broker over loopback for short-lived material bound to `(runId, hostname)`, caches it in process memory only for the grant's lifetime, zeroes it on `proxy.grant.revoked` and on process exit, and **never** writes it to its policy store, to a shared dict or to disk. This is the one place CubeSandbox's design is inverted rather than borrowed (`survey/CubeSandbox.md:88`; their own security doc says "Don't put secrets in `ngx.shared.*`" while the implementation does), and it is what keeps invariant 2 true across a process boundary: the broker stays kernel-only and the sidecar is a credential *user*, not a credential *holder*. KC20's witness manifest carries a marker for it.

The shared Phase 2 sidecar: fail-closed bootstrap (no policy, no serve), per-template/per-run L7 hostname allowlists over a **deny-all L3/L4 backstop**, SSRF deny-CIDRs including the cloud metadata IP, `git-receive-pack` blocked so a push cannot originate inside a container, **token-returning paths denied by path as well as host** (credential substitution is outbound-only, so an OAuth/STS exchange response would leak the token it returns), established flows re-evaluated on policy change with RST when a verdict flips, and every request logged as `proxy.decision` with a credential **fingerprint, never a value**. **Inventory of every credential holder outside the vault** — the threat model names them exhaustively, because "one exception" was wrong:

1. **The publishing edge** (self-hosted Mixpost Lite / Postiz), the one *accepted* second credential store: the platforms' OAuth refreshes continuously against the edge's own client registration and cannot live in the vault. Five conditions (§13 Q13): loopback bind, admin credential in the vault, never exposed over Tailscale, in the backup set, and treated as a credential holder in the threat model.
2. **The assistant's / ingress PIM OAuth** (Google, Microsoft: calendar, mail, notes; KC25's email/calendar/notes packs) is **not** a second store. The refresh token is held in the pmmcp vault; the **kernel hub** performs the refresh on the kernel side and writes the rotated token back through `set_secret`; the assistant never sees either token and holds no egress entry of its own. If a provider's client registration ever makes kernel-side refresh impossible, that surface becomes a second store and inherits all five §13 Q13 conditions before it ships — it does not get to appear quietly.
3. **The egress proxy sidecar** holds **no secret material at all** — see the paragraph above. It is a credential *user*, not a credential *holder*.

Nothing else outside the vault holds credential material.

## 8. Memory architecture

| tier | store | writer | reader |
|---|---|---|---|
| Instructions | `souls/*.md`, `agents/*/AGENTS.md` | **human only** (invariant 8) | loader |
| Working | the run's event-log view (masked or condensed) | kernel | that run |
| Episodic | `aos/agent/<id>` | kernel on `run.finished`; the agent via gated `remember` (write-scoped) | that agent, the curator |
| Curated shared | `aos/shared` | **human promotion only**, proposed by the curator | every clean run |
| Executive | `aos/ceo` (goal tree, adopted plans, mandate records) | kernel projections; the CEO via gated goal tools | ceo, planner, judge (read) |
| Domain state | CRM, publishing edge, ledger, content/inbox/suppression/metrics/lease/receipt projections | gated tools; kernel projections | agents through read views; the gate |
| Untrusted evidence | quarantined scout/community/pentest/focus-group output | kernel, provenance `untrusted` | never by a clean run |
| Declassified extracts | artifact store, sha256-addressed | `quarantine.release` by a `HumanActor` | clean runs inside the extract's scope until expiry |

Namespaces: `aos/ceo`, `aos/shared`, `aos/agent/<id>` — one per persistent agent, plus pinned namespaces granted at spawn to templates that need them (`aos/agent/architect`, `aos/agent/trading/signals`). Sector-shared knowledge (brand kit, ICP, playbooks, banned claims, approved scripts, ADRs, runbooks, thesis libraries) lives in `aos/shared` and gets there only through a human `memory-promote` card.

Every pmmcp write through the hub is stamped by the kernel: `provenance {runId, agentId, taint, origin: operator|agent|untrusted|system, sessionKind: interactive|scheduled|delegated, observedAt}`. Recall for a clean run **structurally excludes** `origin: 'untrusted'`; a run may pass `includeUntrusted: true` and the hub then taints it, so the taint rule — not a prompt — protects writers. Whether pmmcp's `remember`/`recall` carry a metadata field is NEEDS VALIDATION against the live `listTools`; if not, provenance lives in a kernel-side projection keyed by pmmcp record id.

The curator is the **single promotion proposer**: it may promote (human-carded), archive (never delete — `delete_context_source` stays kernel-only), compact with preimage hashes, and file draft procedures. It never reads untrusted-origin items into a promotion and never re-reads its own summaries as fresh observations.

**What never enters memory**: secret values of any kind; raw tool output above `MAX_LOGGED_OUTPUT` (a handle goes in instead — and oversized content is refused, never truncated); untrusted-origin text promoted to `aos/shared`; model-written prompt notes, subagent specs or auto-extracted "learned" skills (a second-order injection channel and an invariant-8 violation); anything written by a cron, heartbeat or delegated session as a durable *candidate* without a human; simulation output framed as prediction; a run's claim that it is clean.

Context management: default condensation is **observation masking** (no model, matches summarisation at half the cost), with LLM summarisation opt-in per manifest on the `summarize` lane; every condensation is a `context.condensed {forgottenEventIds, summaryRef, summaryOffset, costMicroUsd}` event over the untouched append-only log, and the condenser's cost is attributed to the run. `contextBudget` is a manifest field, and every template carries a negative scope ("does not own") in its lane contract.

## 12. Operating limits on one M1 Max

64 GB unified memory, 2 TB SSD, macOS 15.6.1, two Colima VMs (`trusted`, `hostile`), Qdrant in Docker, Ollama native for Metal, ≤ ~40 GB for local weights + KV.

**Concurrency.** `maxConcurrent: 3` writing containers by default, and admission is by **declared memory, not by count**: a Node build container with a dev server is ~1.5–3 GB and Chromium adds ~1–1.5 GB, so eight concurrent T2 workers plus a `hostile` tester is 15–25 GB inside the VMs alone and would starve the local `editorModel`. Each template declares `sandbox.memoryMb`; the spawn path sums it against `kernel.yaml sandbox.domains.<d>.memoryBudgetMb` and refuses with `spawn.refused {reasonCode: capacity}`, queueing rather than thrashing. The operator raises concurrency only by raising a memory budget — the honest knob. Per-provider and per-MCP-server lanes stop three Opus-bound runs colliding. `executor` lane concurrency is **1 per venue**, always.

**Local model budget.** One llama.cpp process (Bonsai at `localhost:8080/v1`) plus Ollama. `models.localConcurrency: 1` by default; 2 only if a probe shows weights plus two KV caches fit inside 40 GB. Everything scheduled and unattended is pinned to local lanes and off-peak where possible (curator 02:00, reporter and bookkeeper after their windows), and a call that cannot get a permit within `localQueueMs` falls back up the chain with `model.fallback {reason: 'local-busy'}` so the cost appears as a fact rather than a mystery digest at 07:40.

**Expected daily approvals** at Phase 4 with paper trading, per sector sub-budget under `approvals.dailyBudget: 20`:

| sector | cards/day | dominant sources |
|---|---|---|
| executive | ~4 | 2 digest batches (~10 ticks), 1 curator `memory-promote` batch, ~1 plan mandate |
| engineering | ~4 | PR open + merge per merged PR at ~2 PRs/day; occasional dependency/test-removal ack |
| growth | ~4 | 1 batched publish card, 1–2 replies, ~1 sales batch, ~0.5 declassification |
| trading (paper) | ≤ 2 | 1 deferred signal-batch card, ~1 strategy card per week |
| ops-security | 0–2 | watchdog `critical` alerts and the halts that need a resume |
| **total** | **~15–17** | under the budget, with back-pressure when the deferred queue overflows |

Live per-order trading adds up to `maxOrdersPerDay` (3 live) plus a halt/escalation, so **~19–22**. Below ~20/day this is a coffee-and-phone routine; above it the operator starts ticking without reading, which is the failure the design is accountable to. Safety cards (halts, flatten, protective-leg escalations, drift) are **exempt** from the budget and from back-pressure: back-pressure that delays a stop increases risk.

A plausible steady state at Phase 4 is **$300–600/month** at 2–4 objectives/day. That range is unvalidated until the Phase 1 harness runs; the binding constraint is the objective reservation, not the ceilings, and no number here is enforced by prose — all of them are `kernel.yaml`, manifest or `trading.yaml` data.

**Storage.** Disk is an operating limit like memory and dollars, so it gets a number per consumer rather than a paragraph. 2 TB SSD, and a full disk halts the fleet in a way nothing currently watches for:

| consumer | ceiling | eviction / archival rule |
|---|---|---|
| local model weights + KV | 40 GB | CLAUDE.md's budget; a new weight set requires retiring one |
| Colima `trusted` disk | 120 GB | worker images pruned to the pinned tags; dangling layers weekly |
| Colima `hostile` disk | 60 GB | no persisted workspace by construction; overlays discarded per run |
| Qdrant + pmmcp store | 40 GB | pmmcp's own compaction; archive never deletes, so growth is monitored, not trimmed |
| artifact store | 300 GB | sha256-addressed and never deleted, and **media renders from `producer` are the only class large enough to need a policy**: intermediate renders (pre-caption, pre-crop, losing takes) are evicted at objective close + 30 days keeping the hash and the manifest; a render referenced by a `publish.*` receipt, a `check.verdict` or an approved card is permanent |
| worktrees + checkpoint shadow refs | 60 GB | worktrees removed at task close, **branches never deleted**; shadow refs retention-bounded to objective + 7 days and **off above a 1 GB repo size** (the previously unnamed threshold) |
| event-log hot segments | 20 GB | KC21 seals seq ranges; sealed cold segments are copied out and dropped locally once the copy verifies |
| cold segments + encrypted backup set | 400 GB | a second full copy by design; retention-delete below the floor is `irreversible`-class |
| point-in-time market-data store (KC23) | 150 GB | revisions appended, never rewritten; instruments outside the active universe archived to cold storage at 12 months |
| **total ceiling** | **~1.19 TB** | leaving ≥ 800 GB headroom on a 2 TB SSD for the OS and the operator's own work |

The KC20 watchdog tick adds a **free-space floor**: below 10 % free it emits `ops.alert {severity: critical, reasonCode: 'diskLow'}`, and below 5 % free it **refuses new sandbox admission** (`spawn.refused {reasonCode: 'disk'}`) while leaving in-flight work and the control plane untouched. Exhaustion is then a logged fail-closed halt rather than a crash mid-chain-write. Marks are polled at 15 s while a position is open but **sampled into the chain at 60 s** plus every breaker transition. Raw tool output above `MAX_LOGGED_OUTPUT` is a handle, never a payload; oversized content is refused, never truncated.

## 13. Open decisions for the operator

Each is question, then default. The defaults are what ships if the operator says nothing; the starred ones change the system's safety properties and should not be answered quickly.

1. **★ Trading taint boundary.** Is the human's approval of a signal batch the only laundering point — declassifying the *decision* (a numeric `SignalExecView`), never the prose — or should a kernel rule treat a scout's zod-validated `numbers[]` as clean so the quant stays clean on numbers? **Default: approval is the only laundering point.** A schema is not a security boundary when the attacker chooses the numbers.
2. **★ Live orders under a mandate.** Does a human-signed mandate with `maxUses` and ≤ 30 d expiry ever satisfy "irreversible always requires a human" for `venue.live.submit`? **Default: no.** It is a CLAUDE.md amendment, not a kernel toggle; it would additionally require 60 paper days, a passed reconcile drill and the Phase 3 trust-rule machinery.
3. **Depth.** Keep depth 1 with sector leads as non-delegating planner-workers, or grant one expiring `depth-raise` mandate to `eng-lead` after a harness win at equal spend? **Default: depth 1 for Phase 1**, revisited only on measured evidence.
4. **Approval wait semantics.** Keep the Phase 0 park-then-deny, or adopt suspend-then-continue with class-specific expiry? **Default: suspend-then-continue in Phase 1**, now safe because of the exactly-once receipts (KC9).
5. **Plan auto-accept.** Auto-accept a plan when the irreversible inventory is empty, the budget fits the envelope and no hostile-domain template is used; otherwise one mandate. **Default: yes** (engineering adds a $10 threshold plus protected-area triggers; refactors and `class: self` repos are always human).
6. **★ Scoped trust rules (Phase 3).** Restrict them to `write`-class approvals from clean runs only, exact shape, `maxUses`, TTL, void while tainted — never tainted-write, memory-promote, declassify, plan, promotion, escalation or irreversible? **Default: yes, Phase 3 only.**
7. **Budget numbers.** The §12 table is now complete — per-sector objective defaults, the **$100 per-objective** ceiling, a **$700 kernel-enforced fleet-month ceiling** that refuses new unattended runs above it, per-agent monthlies for all five sectors (growth restored from `fleet/growth.md`; engineering's four figures proposed here because the sector document states none), and the $100/month per-provider media envelope as a separate non-LLM line — including the trading conflict (executive proposes $10 research-only; trading asks $40). **Default: the completed table as tabulated**, with trading at $10 until Phase 2a and $40 thereafter if the operator agrees; the four engineering monthlies and the producer's LLM monthly are this document's proposals and are the ones most likely to be wrong; none is unlimited and nothing is left open.
8. **Approvals daily budget.** 20/day with per-class sub-budgets and scheduler back-pressure on card-producing unattended runs. **Default: yes, back-pressure only; nothing auto-approves.**
9. **Local concurrency.** `models.localConcurrency: 1` with off-peak pinning. **Default: yes**; raise to 2 only if a probe shows weights plus two KV caches fit 40 GB.
10. **Manifest complexity.** Are `profiles:` on one template acceptable, or would the operator rather have three manifests and three eval suites (`implementer` code/docs/refactor)? **Default: profiles.**
11. **Declassification granularity.** Per-extract with a content hash, a ≤ 8 KiB human-read preview, 30 d expiry and a `revokedAt` that blocks new reuse; bulk release is a batch of hashes; no "mark this run clean". **Default: as stated.**
12. **★ Pentest capabilities.** Keep `--cap-drop=ALL` with **no** `CapAdd` (TCP-connect scanning, HTTP probing, dependency analysis), or amend invariant 9 to allow `NET_RAW` for SYN scanning? **Default: no CapAdd.** `SYS_PTRACE` is refused outright.
13. **Publishing edge as a second credential store.** Accept it (self-hosted Mixpost Lite or Postiz on loopback, admin credential in the vault, never over Tailscale, in the backup set, treated as a credential holder in the threat model), or hold audience reach until the vault can hold refreshing OAuth? **Default: accept with those five conditions; Mixpost Lite.**
14. **Automatic fail-closed halt.** Halting admission automatically on chain-verify failure or a missing witness marker risks the operator finding a stopped fleet. **Default: halt automatically** — a control plane that cannot prove its log is intact must stop authorizing; `fleet.resume` stays available on the loopback control plane the halt does not touch.
15. **Evaluator strictness.** Advisory in Phase 1, hard gate at Phase 5? **Default: yes**, so early manifests are not stuck behind an incomplete harness.
16. **★ Facts that must come from primary sources before they become config.** Platform limits (X, LinkedIn, Instagram, TikTok, Reddit), FTC/CAN-SPAM and the Google/Yahoo bulk-sender requirements, FINRA Notice 26-10 (PDT), day-trade buying power, IRS Pub. 550 wash sales and the crypto exclusion, venue ToS on automated trading, Hyperliquid US eligibility. **Default: nothing goes live until the operator has re-read each and confirmed the block.** Every number currently in these designs is INFERRED from search snippets.

20. **`delegateTier` promotions.** Which agents reach tier 3, when, and for how long (every promotion is a Mandate expiring within 30 days)? **Default: `reporter` immediately; `community` and `sales` after two weeks of tier-2 cards above 80% acceptance, re-issued monthly; `publisher` never above tier 2.**

Accept the amended map as written (trading research in Phase 1, trading kernel and `pentester` in Phase 2a/2b), or hold both behind CLAUDE.md's existing exits and land them as Phase 2c and Phase 6? **Default: hold trading *execution* and the pentest sector to a Phase 2c that starts only after CLAUDE.md's own Phase 2 exit is met**, and keep trading *research* (`quant` research-only, `market-scout`, `critic:bear`) in Phase 1, since it adds no kernel subsystem and no new egress. KC23 and the pentest items in §11 are blocked on this answer.
28. **Paid media at all.** Marketing's only irreversible money-movement surface. Enable paid-media spend verbs (shape in §5.6 `marketer`: `irreversible`, carded per campaign, kernel-computed spend ceiling, kernel daily cap, confidence-gated, credit cost in the tool view, no new manifest), or record them as out of scope? **Default: no** — audience reach stays organic until after Phase 4's exit, and the Phase 5 clause is conditional on this answer, not a plan.
