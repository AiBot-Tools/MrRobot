## What it is

CONFIRMED. An E2B-API-compatible sandbox *service* for AI agents: each sandbox is a KVM MicroVM with its own kernel, restored from a pre-snapshotted template in <60 ms, with <5 MB memory overhead, O(1) copy-on-write snapshot/clone/rollback (XFS reflink `FICLONE`), per-sandbox eBPF network policy (CubeVS), and a transparent L7 MITM egress proxy (CubeEgress) that does domain/method/path filtering, header credential injection, and JSONL audit logging. It is infrastructure, not an agent framework: no LLM loop, no agent roles, no memory, no MCP. Integrations are all "point an existing agent's shell/exec at us" (E2B SDK, Claude Code `PreToolUse` hook, OpenCode plugin hook, OpenClaw skill, LangChain, OpenAI Agents).

## Orchestration model

CONFIRMED (`docs/architecture/overview.md`, `docs/guide/cubemaster-scheduler-config.md`, `docs/guide/lifecycle.md`):

- **Control plane vs data plane.** Control plane (CubeAPI, CubeMaster, CubeOps, WebUI) is stateless; Redis is the single source of truth for sandbox metadata, lifecycle events, proxy routing table, and distributed locks. Data plane (Cubelet, CubeShim, CubeHypervisor, CubeCoW, CubeVS, CubeEgress, CubeProxy) is node-local.
- **Request lifecycle.** `POST /sandboxes` → CubeAPI (auth callback) → CubeMaster gRPC (node filter + score + pick from top-N) → Cubelet gRPC `RunCubeSandbox` → CoW clone of template rootfs+memory → containerd Shim v2 → VMM restore → `AddTAPDevice` + `AttachFilter` → lifecycle event to Redis.
- **Scheduling.** Filters (cpu, mem, template_locality, realtime_create_num, disk watermark, affinity/labels) then scoring (`real_time_weighted_average` over `mvm_num`, `local_create_num`, `quota_cpu_usage`, `quota_mem_usage`); `priority_select_num` picks randomly among top-N. Per-node caps: `mcpu_limit`, `mem_limit`, `mvm_limit`, `creation_concurrent_num` (`Cubelet/dynamicconf/conf.yaml` via the doc).
- **Concurrency primitives.** Per-key mutex in Cubelet (`Cubelet/internal/kmutex/kmutex.go`, containerd-derived `KeyedLocker`); Redis lease elects one `cube-lifecycle-manager` replica for idle sweep; per-sandbox Redis state transitions and CubeMaster lifecycle locks serialize pause/resume; delete of a paused sandbox returns `503 + Retry-After: 2` when another lifecycle op holds the lock.
- **Lifecycle state machine.** `running → pausing → paused → resuming → running`, `→ terminated` (kill is irreversible and always wins over pause). `timeout` is *idle* seconds; `on_timeout` is `kill` (default) or `pause`; `auto_resume` wakes on next request and resets the idle clock. Server default TTL `default_timeout_insec: -1` ships as "never".
- **Snapshot / clone / rollback** (`docs/guide/snapshot-rollback-clone.md`): `create_snapshot()` (memory+fs, independent lifecycle), `clone(n, concurrency)` (all-or-nothing: partial failure kills the already-created clones), `rollback(snap_id)` in place with same sandbox ID.
- **Policy update of a running sandbox** (`docs/guide/network-policy.md` "Updating the policy"): `PUT /sandboxes/{id}/network` is a full replacement; each sandbox carries `policy_version`; established flows are re-evaluated once on their next packet and RST'd if the verdict changed; CubeEgress is updated before CubeVS, durable state last ("no more permissive than old ∪ new" on partial failure).

## Sandbox & security posture

### Isolation (CONFIRMED)
- One KVM MicroVM + dedicated guest kernel per sandbox; VMM is RustVMM-based with `--seccomp` (`hypervisor/src/main.rs:360,631-651`); virtiofsd has its own seccomp + chroot/namespace sandbox modes (`hypervisor/virtiofsd/src/seccomp.rs`, `sandbox.rs`).
- Guest workload is an OCI container run by `rustjail` inside the VM, driven by cube-agent (`agent/README.md`).
- Per-sandbox TAP device; no bridge; three eBPF programs (`from_cube` on TAP ingress, `from_world` on host NIC ingress, `from_envoy` on cube-dev egress) do policy, SNAT, conntrack (nf_conntrack-like TCP state machine with per-state timeouts), DNS-learned allow entries with TTL expiry, ARP proxy (`docs/architecture/network.md`).
- Always-denied ranges regardless of policy: `10/8, 127/8, 169.254/16, 172.16/12, 192.168/16` (`docs/architecture/network.md` §5.2). Note nuance in `docs/guide/network-policy.md`: these are installed in `deny_out` when `allow_internet_access` is not false; with `allow_internet_access=false` the `0.0.0.0/0` deny covers them.
- Host mounts restricted to allowlisted prefixes; `validateHostPath` uses `filepath.Clean` + `HasPrefix` only, **no `EvalSymlinks`** on the admission path (`CubeMaster/pkg/service/sandbox/hostdir_mount.go:205-215`). Cleanup path does resolve the base but deliberately not the leaf (`Cubelet/storage/hostdir.go:174-186`).
- Inbound: `allow_public_traffic=false` mints a per-sandbox `traffic_access_token`, single delivery, no rotation, enforced at CubeProxy with 403 (`docs/guide/restrict-public-access.md`).

### Egress / credential handling (CONFIRMED)
- CubeVS marks SYNs for `(host,port)→scheme` from `allow_out_v3`; iptables `mangle/PREROUTING -m mark -j TPROXY` steers to CubeEgress `:8080`/`:8443` (`CubeEgress/scripts/cube-proxy-iptables-init.sh`). Sandbox trusts the CubeEgress root CA baked into the template; leaf certs minted per SNI (`CubeEgress/lua/cert_signer.lua`).
- `access_phase.lua`: builds ctx from `remote_addr`/SNI/Host/method/uri/original dst port (TPROXY preserves it); looks up per-sandbox-IP policy; first-match-wins; **no rule match → deny 403** with `security_event`; **no policy for sandbox → deny**; **bootstrap not `ready`/`skipped` → deny all (fail closed)**. Gates before inject: G1 scheme, G4 `Host == SNI` (HTTPS) / Host present (HTTP) — a mismatch drops the inject, flags `security_event`, but still proxies the request per `action.allow`. Injected headers are `clear_header`'d **before** gating so a sandbox-forged `Authorization` can never ride through.
- Upstream TLS: `proxy_ssl_verify on; proxy_ssl_verify_depth 4; proxy_ssl_server_name on; proxy_ssl_name $cube_original_sni` (`CubeEgress/nginx.conf:95-100,193`).
- Audit: `audit.lua` writes a JSONL record per request `{ts, request_id, sandbox{src_ip,policy_id}, conn{original_dst}, tls{sni,cipher,version,alpn}, http{...}, policy{matched_rule,decision,duration_us}, credentials{injected:[header names], secret_ids:[fp-xxxxxxxx]}, security{reason,...}, redacted_request_headers}`. `redactor.lua` scrubs header names matching token/secret/key/password/credential/auth (Authorization keeps only the scheme, cookies keep only names) and recursively scrubs JSON bodies. Secret fingerprint = `"fp-" + sha256[:8]` (`policy.lua` "inline-secret fingerprint").
- Admin API `127.0.0.1:9091` loopback only; GET surfaces return `***REDACTED***` for every `inject[].secret` (`admin.lua` header).
- Secrets travel **inline** in the rule list: SDK → CubeAPI → CubeMaster (`CubeMaster/pkg/service/sandbox/types/types.go:191 Secret string`) → Cubelet (`Cubelet/network/runtime/types.go:167`, `cubeegress/wire.go:75`) → CubeEgress `lua_shared_dict policy_store`. CubeMaster redacts on read paths (`util.go:1073`). Whether the raw secret is persisted in Redis/MySQL is not stated — INFERRED likely yes for restart re-apply ("a Cubelet restart re-applies the last policy that was successfully persisted", `docs/guide/network-policy.md`).
- AgentHub has two credential modes: "credential hosting" (CubeEgress inject, placeholder key inside OpenClaw) and "environment injection (legacy)" which writes the real key into the sandbox (`docs/guide/digital-assistant.md`).

### Gates / human-in-the-loop
None. No approval concept anywhere (grep of docs found only the Claude Code hook's *auto-approve*). Authorization is entirely the operator's external auth callback + per-sandbox network policy.

## BEST PARTS

1. **Egress proxy as the credential edge, with forged-header clearing and Host==SNI gate.** Evidence: `CubeEgress/lua/access_phase.lua` (`allow()` clears each inject header before `inject_gates`; G4 `host_sni_mismatch`), `docs/guide/security-proxy.md`. Sector: kernel (Phase 2 egress sidecar), engineering (coding fleet). Why: this is exactly our invariant 2 realized; the "clear-then-gate" ordering and the request-smuggling defense are details we would otherwise learn the hard way.
2. **Fail-closed by construction: no policy / no match / bootstrap pending → 403.** Evidence: `access_phase.lua` `_M.decide()` bootstrap gate and `no_policy_for_sandbox` / `no_rule_match` denies; `bootstrap.lua` "MUST NOT serve data-plane traffic without policies" (exits process on load failure). Sector: kernel, ops-security. Why: our sidecar must deny during its own startup/restart windows, not just at steady state; this matches invariant 3 default deny.
3. **Structured JSONL audit with secret fingerprints instead of values, and a pure, unit-testable redactor.** Evidence: `CubeEgress/lua/audit.lua` (`credentials_block` records header names + `secret_ids` only), `CubeEgress/lua/redactor.lua` (pure functions, exact list + fragment list, scheme-preserving Authorization, cookie names only, recursive JSON scrub, `max_bytes` truncation), `policy.lua` `compute_fingerprint`. Sector: kernel (event log redaction), ops-security. Why: every proxy decision becomes an event we can chain (invariant 5) and correlate by credential without ever logging it; the fingerprint idea lets `auditor` answer "which runs used key X" cheaply.
4. **Two-layer egress: L3/L4 CIDR+DNS-learned allow (with TTL) beneath an L7 rule list, with explicit "which traffic never reaches the proxy" table.** Evidence: `docs/architecture/network.md` §5-6, `docs/guide/network-policy.md` "Which traffic reaches CubeEgress", "Behavior cheat sheet". Sector: kernel (T2/T3 network model), trading (hard allowlists to exchange APIs). Why: our T2 `trusted` domain needs both a hostname allowlist and a hard L3 backstop so non-HTTP protocols cannot slip past an HTTP-only proxy; the doc's honesty about proxy blind spots is the checklist for our own design.
5. **Policy generation + re-evaluation of established flows on policy change; retire (RST) on verdict change; non-transactional update ordered so the interim state is never more permissive.** Evidence: `docs/guide/network-policy.md` "What happens to connections that are already open", "The update is not transactional across planes". Sector: kernel, ops-security. Why: when a run becomes tainted mid-flight or an approval is denied, we need open sockets to die, not merely new ones to be blocked; the "never more permissive during a partial update" rule is a good invariant for our own policy pushes.
6. **Idle-timeout lifecycle with pause/resume and all-or-nothing clone fan-out.** Evidence: `docs/guide/lifecycle.md` (state model, `on_timeout`, `auto_resume`, `kill` always wins), `docs/guide/snapshot-rollback-clone.md` ("If any sub-task fails, already-created clones are automatically kill()ed"). Sector: engineering (coding fleet: checkpoint before risky step, roll back on failed tests, fork N attempts), kernel (sandbox manager lifecycle). Why: our sandbox manager only has a hard wallclock; an explicit idle timeout + "kill is irreversible and wins" rule + no-orphans fan-out semantics are the lifecycle contract we should write down for the Docker driver even without VM snapshots.
7. **Hook-level, unconditional shell redirection for host-resident coding agents.** Evidence: `docs/guide/integrations/claude-code.md` ("Why a hook": MCP/SDK sandboxing depends on the agent *choosing* it; the hook intercepts the tool call itself; fail-closed; `shlex`-quoted single argument; nested wrapping fails inside the sandbox, never on the host), `docs/guide/integrations/opencode-plugin.md`. Sector: engineering (coding fleet), kernel. Why: it is the same principle as our invariant 3 ("the model never makes an access-control decision") applied to exec: the gate must be in the runtime, not in the tool the model can decline to use. Our worker loop should route *all* exec through the sandbox driver, never offer a "run locally" tool.
8. **Auth callback that receives path AND method, with the documented escalation trap.** Evidence: `docs/guide/authentication.md` ("A callback that only whitelists by path cannot distinguish a read from a destructive operation"). Sector: kernel (control-plane protocol), ops-security. Why: our policy gate keys on tool + risk; this is a reminder that any route-based check must include the verb, and that `irreversible` must be classified by what the call *does*, not where it goes.

## BAD PARTS / anti-patterns

1. **L3/L4 default is allow.** Evidence: `docs/architecture/network.md` §5.2 "allow > deny > default-allow"; `docs/guide/network-policy.md` "Default allow if neither matches", and `Cubelet/network/plugin_policy.go` `formatCubeNetworkAllowInternetAccess` prints `default(true)`. Why we leave it out: our invariant 3 is default deny; a sandbox tier that is open unless someone remembers `allow_internet_access=false` is the OpenClaw posture we are avoiding. T2 must start from deny-all and punch holes; T3 has no egress at all.
2. **Policy update is replace-not-patch and silently re-opens the internet.** Evidence: `docs/guide/network-policy.md` warning "Leaving out `allowInternetAccess` restores internet access ... regains public internet access after any update that does not restate the field". Why: a footgun that turns a narrowing edit into a widening one; our kernel must make policy edits monotone-or-explicit (a widening requires a distinct, human-approved command) and must never let an omitted field mean "more permissive".
3. **Secrets travel inline through every control-plane hop and sit in an nginx shared dict.** Evidence: `CubeMaster/pkg/service/sandbox/types/types.go:191`, `Cubelet/network/runtime/cubeegress/wire.go:75`, `CubeEgress/lua/policy.lua` (`inject[].secret` stored in `policy_store`), `admin.lua` "Operators must keep the source of truth externally"; `bootstrap.lua` says a legacy top-level `secrets` (by-reference) mode was removed. Why: our invariant 2 says only the broker touches the vault; the proxy sidecar should resolve a *reference* at inject time through the kernel broker (or receive a per-run, short-lived material), not carry raw secrets in its policy document that also flows through the scheduler, gRPC, and possibly Redis. The Cube authors themselves warn "Don't put secrets in `ngx.shared.*`" (`docs/guide/security-proxy.md`) while the design does exactly that.
4. **Inject gate failure still forwards the request upstream (without the secret) and does not deny.** Evidence: `access_phase.lua` header comment "any G1-G8 failure → drop inject; the request continues based on action.allow" and `allow()`. Why: for us, a Host/SNI mismatch on a credentialed rule is an attack signal; the run should be denied and tainted, not allowed to proceed unauthenticated (which may hit a public endpoint and exfiltrate). Same for `secret_missing_in_policy`: they flag it but let traffic flow.
5. **Host-mount allowlist does not resolve symlinks on admission.** Evidence: `CubeMaster/pkg/service/sandbox/hostdir_mount.go:205-215` (`filepath.Clean` + `HasPrefix` only; comment says it "resolves `..`" but there is no `EvalSymlinks`). Why: our invariant 9 requires confinement *after* symlink resolution; a symlink under `/data/shared/` pointing at `$HOME` would pass their check. We keep our stricter rule.
6. **Auto-approve in the Claude Code hook and no human gate anywhere.** Evidence: `docs/guide/integrations/claude-code.md` "Auto-approval — the hook answers `permissionDecision: \"allow\"`"; grep for approval/human-in-the-loop yields nothing else; AgentHub "environment injection (legacy)" writes the real LLM key into the sandbox (`docs/guide/digital-assistant.md`). Why: isolation is treated as a substitute for authorization. For us, sandboxing is one layer; the policy gate → approval → quarantine chain (invariant 3) stays in front of every tool call regardless of how good the box is.
7. **Ships with no idle TTL and no wallclock ceiling.** Evidence: `docs/guide/lifecycle.md` "`default_timeout_insec: -1`", "Cube doesn't impose hard wall-clock ceilings". Why: our invariant says never disable the wallclock; every run gets a hard ceiling from its manifest, idle timeout is additive.

## Conflicts with CLAUDE.md invariants

1. **Inv. 3 (default deny):** CubeVS L3/L4 default-allow; L7 default-deny only for traffic that reaches the proxy. We cannot adopt the network model as-is; adopt the L7 layer semantics, invert the L3 default.
2. **Inv. 2 (agents never hold credentials; broker is kernel-only):** the inject secret is embedded in the per-sandbox policy document that flows CubeAPI→CubeMaster→Cubelet→CubeEgress shared dict. Our sidecar must fetch by reference from the broker per request or per run, never store raw material in its policy.
3. **Inv. 9 (mounts confined after symlink resolution):** `validateHostPath` does not `EvalSymlinks`. Keep our resolution step.
4. **Inv. 9 (hard wallclock):** Cube has idle timeout only, default never. Wallclock stays mandatory for us; idle timeout is an addition.
5. **Inv. 5 (every event chained):** Cube's audit is a per-host JSONL file with O_APPEND, no hashing/chaining, and stdout gets a different schema. Proxy decisions must be ingested as kernel events, not left as a side file.
6. **Inv. 3 (`irreversible` needs a human; the model never makes access decisions):** Cube has no approval concept and the Claude Code hook auto-approves. No conflict to import, but nothing to reuse either; our gate sits in front of the sandbox exec.
7. **Inv. 7/8:** not applicable (no MCP, no souls). No conflict.
8. **Environment:** KVM/x86_64 Linux only (`README.md`); cannot run on the operator's macOS M1 Max. Everything we take is design, not code.

## Verdict

Take the CubeEgress *design* for the Phase 2 egress sidecar: TPROXY-style interception the worker cannot opt out of, first-match rule grammar (scheme/sni/host/method/path/port), clear-then-gate credential injection with Host==SNI check, fail-closed on no-policy/no-match/not-bootstrapped, JSONL audit with header names + secret fingerprints and a pure redactor, plus the "policy generation + RST established flows on verdict change" and "never more permissive mid-update" rules, and the lifecycle contract (idle timeout, kill wins, all-or-nothing fan-out) for the sandbox manager. Leave out the L3 default-allow, replace-not-patch policy updates, inline secrets in the policy document, "proceed without secret on gate failure", symlink-blind mount checks, no-wallclock defaults, and the auto-approve hook, and treat the whole thing as reference architecture only since it requires KVM on Linux. Nothing here informs roster, roles, memory, or model routing; its value to the fleet is confined to the T2/T3 sandbox and egress tiers and to the rule that a coding agent's exec path must be intercepted at the runtime, not offered as an optional tool.
