## What it is

A single-operator coding/research agent (TUI + headless JSON/RPC/ACP modes) built on two ideas: the **Recursive Language Model (RLM)** runtime, where the model's only built-in tool is a persistent IPython kernel (`ipython`) and files/shell/tools/subagents are all Python calls; and the **Continual Harness**, a persisted, model-editable ledger of prompt notes, memories, skill descriptions and subagent specs that `/refine` updates in small evidence-backed edits with rollback snapshots. A local daemon (supervisor + one resident worker process per root session tree) keeps sessions, kernels, schedules and children alive after the terminal detaches. It also ships a Prime Intellect skill and two model-free-testable eval harnesses (Short SWE release gate, swarm-fanout orchestration scorer). CONFIRMED (`README.md`, `packages/coding-agent/docs/{rlm,rlm-runtime,daemon,long-running-agents}.md`)

## Orchestration model

- Topology: supervisor (sockets, routing, attachments, agent-message delivery, journals) -> resident worker per root tree -> root `AgentSession` -> Python kernel + `sub-xxxxxxxx` child `AgentSession`s. Supervisor never executes providers/tools. CONFIRMED (`docs/daemon.md`, `docs/architecture.md`)
- Delegation: `await rlm.spawn(prompt, name=..., model=None, thinking=None)` travels as a `host_request` over stdio JSONL to the TypeScript host, which checks `RLM_DEPTH < RLM_MAX_DEPTH` (default 2), resolves the model (exact `provider/model` selector or inherit; unavailable model fails, never silently substitutes), admits the child into a parent-scoped registry, and returns an admission handle immediately. Results arrive only via explicit `agent_message.send(..., receiver_role="parent")` or files; `rlm.collect(targets, timeout_ms)` gives typed snapshots. CONFIRMED (`docs/rlm-runtime.md`, `src/core/rlm-runtime.ts`, `src/core/prompts/rlm.ts` lines 157-238)
- Child usage/cost is folded into the parent assistant turn as a persisted `child_usage_attributed` transcript entry; context-tree reporting subtracts it so own vs aggregate usage reconcile. CONFIRMED (`docs/rlm-runtime.md` "Usage and Cost Attribution")
- Agent-to-agent messaging: daemon-routed, reach limited to the "nuclear family" (parent, siblings, direct children); sender identity daemon-derived, cannot be spoofed from Python; caps 16,384 chars, 20 pending per session, token bucket 3 capacity / 1000 ms refill; delivery modes `auto|steer|follow_up`. CONFIRMED (`src/core/agent-messages.ts` lines 18-30, `skills/agent-message/SKILL.md`)
- Spawn ledger: daemon-owned append-only JSONL `rlm-ledger/<hash>.jsonl` with `spawn|rename|delete|meta` records (childId, parent, child, depth, name, delete reason `user|parent-teardown|revoked|gc`); topology is read from the ledger, not re-derived from writer-owned files; bounded read fails closed at 32 MiB / 100k records. CONFIRMED (`src/modes/daemon/rlm-ledger.ts`)
- Continuation machinery: persistent goals (`idle|active|paused|budget_limited|complete|error`, token budget, only `goal.complete()` ends), user `/heartbeat`, agent `rlm_heartbeat`, cron/once/interval schedules persisted per session with claim-before-deliver and coalesced missed ticks, and **autonomous mode** with defaults maxContinuations 3 / maxTurns 12 / maxTokens 80k / 30 min wall clock and shell **quality gates** (retry cap 3, 5 min timeout, gate skipped when worktree unchanged since last failure, timer continuations held while subagents run with a 25 min keep-alive valve). CONFIRMED (`src/core/goals.ts` line 10, `src/core/cron-jobs.ts` `claimDueInState`, `src/core/autonomous.ts` lines 53-75, `docs/long-running-agents.md`)
- Roots may also create peer top-level sessions with `rlm.create_session(...)` from a daemon-backed depth-0 session. CONFIRMED (`src/core/prompts/rlm.ts` line 157)

## Agent roster / roles found

There is no static roster. Roles are created ad hoc by the model at spawn time (`name="api-reviewer"`, `"test-reviewer"`, `"researcher"` appear only as prompt examples in `docs/rlm.md` and `src/core/prompts/rlm.ts`). Reusable roles exist only as **continual-harness `subagent` specs** (`kind: "subagent"` entries in `harness/harness_state.json`, rendered as a "subagent-spec menu" in the system prompt) that the model or `/refine` writes. CONFIRMED (`src/core/refinement/refinement.ts` lines 34-60 and 141-155, `src/core/prompts/rlm.ts` lines 205-240, `prime-agent-runtime/src/rlm/harness.py` `create_subagent`)

## Memory model

- Two layers. (1) Kernel state: Python namespace persists across tool calls and compaction; `kernel-state.dill` snapshots under `session-artifacts/<root>/` for revival. (2) Continual harness: `harness_state.json` with entries of kind `prompt|memory|skill|subagent`, scope `local` (session artifact dir, default) or `global` (`~/.prime/agent/harness/`), each with `version`, `created_at/updated_at`, `reference`/`arguments` contracts for Python skills, and a `refinements.jsonl` history of `{trigger, changes, evidence, outcome}` events. `/refine` is a separate model call (`REFINEMENT_SYSTEM_PROMPT`) emitting JSON create/update/delete edits; before/after snapshots enable `rollbackId`; an auto-refine review gate (`AUTO_REFINE_REVIEW_SYSTEM_PROMPT`) decides at turn intervals / compaction whether to refine. The base system prompt is declared immutable; harness prompt entries are "supplemental notes". Global entries are read-only during a local refinement. CONFIRMED (`src/core/refinement/refinement.ts`, `prime-agent-runtime/src/rlm/harness.py`, `docs/rlm-runtime.md` "Continual Harness State")
- Transcript is JSONL per session with compaction summaries; no vector store. CONFIRMED (`docs/rlm-runtime.md` "Session Artifacts")

## Tool / plugin / MCP model

- One model-facing tool by default: `ipython`. `bash()` returns a background handle (`pid`, `tail`, `poll`, `kill`, `await`); "Background command finished" notices are delivered as steering. `edit` is a Python skill. Tool output truncation defaults: 2000 lines / 50 KB (`src/core/tools/truncate.ts`). CONFIRMED (`docs/rlm.md`, `src/core/prompts/rlm.ts` line 37)
- Extensions (TypeScript, loaded from `~/.prime/agent/extensions`) can register tools/commands/flags and hook `tool_call` (mutable input, can `{block: true, reason}`), `tool_result`, `session_start`, `user_bash`, etc. Extensions "run with your full system permissions". CONFIRMED (`src/core/extensions/types.ts` lines 775-830, `docs/extensions.md` line 110)
- Skills: Agent-Skills `SKILL.md` format extended with Python packages installed into the kernel venv and exposed by import name; skills may themselves call `rlm.spawn`. Only metadata goes in the startup prompt. CONFIRMED (`docs/rlm.md` section 3, `prime-agent-runtime/src/rlm/skill.py`)
- MCP: a generic `mcp` Python module in the kernel (`list_plugins`, `search_plugins`, `list_connections`, `search_tools`, `describe_tool`, `list_tools`, `call_tool`). The host serves a catalog + per-connection config via `host_request("mcp.config")`; the **Python kernel itself opens the HTTP/stdio MCP transports** and resolves the bearer token (`_headers`: static token, `bearerTokenEnvVar` from `os.environ`, or OAuth `access` via `_bound_auth`). `list_tools` fails closed on broken pagination (never a partial inventory); stdio servers get only `_SAFE_ENV` + explicitly referenced env; HTTP client sets `follow_redirects=False` so secret headers never follow a redirect; stderr tails redact configured secret values. Tool enable/disable policy is a user `enabledTools/disabledTools` list raising `PermissionError`. CONFIRMED (`prime-agent-runtime/src/rlm/mcp.py` lines 1-60, 264-320, 925-975; `skills/mcp/SKILL.md`; `src/core/mcp/mcp-manager.ts`)

## Sandbox & security posture

- Isolation: none by default. Worker and kernel processes are "lifecycle and failure containment, not a security sandbox"; model-generated Python and `bash()` run with the user's OS permissions. Stated repeatedly. CONFIRMED (`README.md` warning, `docs/rlm.md` "Trust Model", `docs/daemon.md`, `docs/rlm-runtime.md` "Trust Boundary")
- Optional OS sandbox: an *example* extension wraps `bash` with `@anthropic-ai/sandbox-runtime` (sandbox-exec on macOS, bubblewrap on Linux) with domain allow/deny lists and filesystem deny-read (`~/.ssh`, `~/.aws`, `~/.gnupg`) / deny-write (`.env`, `*.pem`, `*.key`). It only covers the `bash` tool; the `ipython` kernel is not sandboxed by it. CONFIRMED (`packages/coding-agent/examples/extensions/sandbox/index.ts`)
- Credentials: the kernel is spawned with `env: { ...process.env, ...options.env }`, so every provider key in the operator's environment is visible to model-executed Python (`src/core/kernel/repl-manager.ts` line 345). CONFIRMED. MCP bearer tokens are resolved inside the kernel (see above). CONFIRMED. Docs say "the full auth store does not" cross into Python, which is true of the `auth.json` store but not of env vars. INFERRED from the two facts above.
- Gates / human-in-the-loop: no built-in policy gate on tool calls. `permission-gate.ts` is an example extension that regex-matches `rm -rf|sudo|chmod 777` in `bash` input and asks `ctx.ui.select`, blocking by default when no UI. It does not inspect `ipython` cells, so `subprocess`/`os.system` from Python bypasses it. CONFIRMED (`examples/extensions/permission-gate.ts`, `types.ts` `IpythonToolCallEvent`)
- Audit: session JSONL transcripts, RLM spawn ledger, and ACP semantic-edge ledger are append-only JSONL with a crash-safe tail rule (unterminated last line skipped; interior malformed lines fail closed) and bounded reads. No hashing, chaining, or immutability enforcement beyond O_APPEND. CONFIRMED (`src/core/event-log.ts` header; grep for hash/chain/hmac in that file returned nothing)
- Supply-chain and release discipline: 7-day `min-release-age` for deps (`.npmrc`, dependabot cooldown); pre-push guard; `check-test-policy.mjs` enforces no `.skip/.only/retries/sleep-as-readiness` and "no more test lines than source lines"; `VOUCHED.td` allowlist for external contributors; label-gated paid behavioral eval with a documented trust boundary (candidate code gets no GitHub/provider/sandbox credentials; tarballs treated as opaque bytes on runners; two independent statuses, both revoked on head change). CONFIRMED (`AGENTS.md`, `SECURITY.md`, `scripts/evals/short_swe/README.md`, `.github/VOUCHED.td`)

## Evals and verification

- `scripts/evals/short_swe`: 28 fixed tasks (15 SWE-bench Verified, 8 SWE-bench Pro, 5 ScaleSWE), repository-stratified with a fixed seed; base vs head of the exact PR; pinned model with one authorized backup; gate fails on -5 resolved, +3 model failures, or 2x tokens/time without gain; verifier runs in a fresh credential-free network-free sandbox, gold patches stripped before tests, gold-patch oracle must resolve first, infra failures are errors not zero rewards. CONFIRMED (`scripts/evals/short_swe/README.md`, `verified_verifier.py`)
- `scripts/evals/swarm_fanout`: scores orchestration purely from on-disk artifacts (spawn ledger, `sub-*` dirs, parent transcript, combined answer file), never from the agent's claims. Rubric: coverage, delegation evidence (a live depth-1 ledger edge per shard whose child session file exists), dedup (<= 2x spawns), receipts (every child has a reply or explicit failure in the parent transcript), efficiency. Self-tests include no-spawn, double-spawn, fabricated-answer and silent-drop cheats. CONFIRMED (`scripts/evals/README.md`, `swarm_fanout/scorer.py`)
- RL: the repo integrates with Prime's `verifiers` / Environments Hub / `prime-rl` via the `prime-intellect` skill and the hosted eval pipeline; there is no RL training code in this repo. CONFIRMED (`skills/prime-intellect/SKILL.md`, README links)

## BEST PARTS

1. **Admission-only spawn with explicit fan-in.** `rlm.spawn` returns a handle at admission, never the answer; children reply via daemon-routed messages or files; `rlm.collect` gives typed snapshots; child usage is attributed to the parent turn. Evidence: `docs/rlm-runtime.md`, `src/core/rlm-runtime.ts`, `src/core/prompts/rlm.ts` lines 164-238. Sector: kernel (runtime loop) and executive (CEO delegation). Why: it is the cleanest available shape for our CEO -> fleet -> ephemeral runs: no blocking parent turn, cost roll-up per delegation, and no implicit result channel that bypasses the log.
2. **Daemon-owned append-only spawn ledger as the source of truth for topology.** Evidence: `src/modes/daemon/rlm-ledger.ts` (records `spawn|rename|delete` with depth and delete reason; bounded, fail-closed reads). Sector: kernel. Why: our hash-chained event log should carry the same `agent.spawn/rename/archive` edges so approvals, promotion and restart-safe projections rebuild the fleet tree from the log, not from process state.
3. **Artifact-scored orchestration eval with cheat fixtures.** Evidence: `scripts/evals/swarm_fanout/scorer.py`, `scripts/evals/README.md`. Sector: engineering (Phase 1 eval harness) and executive. Why: our CEO eval must score from the event log (spawn edges, `run.finished`, goal status) and explicitly fail no-spawn, double-spawn, fabricated-answer and silent-drop; this is a ready rubric.
4. **Bounded autonomous mode with shell quality gates and fail-closed defaults.** Evidence: `src/core/autonomous.ts` lines 53-75 (3 continuations / 12 turns / 80k tokens / 30 min; gates retried max 3, skipped when worktree unchanged), `DEFAULT_AUTONOMOUS_CONTINUATION_PROMPT` ("prove it with host-observable evidence"). Sector: engineering (coding fleet), kernel (budgets). Why: coder runs should end only when `npm run typecheck && npm test` passes or budget is exhausted, and "gate passed" must never be inferred from the model's claim.
5. **Claim-before-deliver scheduling with coalesced missed ticks.** Evidence: `src/core/cron-jobs.ts` `claimDueInState` / `recoverInterruptedInState`, `docs/daemon.md` "Scheduling". Sector: kernel (Phase 1 cron scheduler), ops-security. Why: our `schedule:` implementation needs exactly this: persist the claim as an event before the run starts so a kernel crash never replays or backlogs runs.
6. **Continual harness with scoped, versioned, rollback-able edits and an immutable base prompt.** Evidence: `src/core/refinement/refinement.ts` (kinds `prompt|memory|skill|subagent`, `local|global` scope, before/after snapshots, `refinements.jsonl`), `prime-agent-runtime/src/rlm/harness.py`. Sector: executive, growth (marketing/sales playbooks), engineering. Why: the *shape* (small evidence-backed diffs, history, rollback, base prompt untouchable) is how CEO-proposed changes to agent manifests and pmmcp memories should look; in our system the write goes through a human gate (invariant 8), not the model.
7. **Family-scoped, daemon-authenticated agent messaging with hard limits.** Evidence: `src/core/agent-messages.ts` lines 18-30, `skills/agent-message/SKILL.md`. Sector: kernel, ops-security. Why: sender identity derived by the kernel, reach limited to parent/siblings/children, size/rate/pending caps; this is the right inter-agent channel for taint propagation (a tainted child's message taints the receiver) and it keeps the model from addressing arbitrary agents.
8. **Release-eval trust boundary and test discipline.** Evidence: `scripts/evals/short_swe/README.md`, `scripts/check-test-policy.mjs`, `AGENTS.md` "Testing Policy", `.npmrc` `min-release-age=7`. Sector: engineering, ops-security. Why: candidate code never sees credentials, evaluation status is revoked on head change, flaky tests are deleted not retried, and new deps age 7 days; all directly applicable to Phase 5 "per-agent eval suites gating manifest changes".

## BAD PARTS / anti-patterns

1. **No security boundary around model-executed code.** Python and `bash()` run with the user's OS permissions; the sandbox is an optional example extension that covers only `bash`, not `ipython`. Evidence: `README.md` warning, `docs/rlm.md` "Trust Model", `examples/extensions/sandbox/index.ts`. Why we leave it out: violates invariant 9 (containers with cap-drop, read-only, egress proxy) and the T1-T3 tier ladder.
2. **Credentials reachable from the model's process.** The kernel inherits the full `process.env` (`src/core/kernel/repl-manager.ts` line 345) and resolves MCP bearer tokens in Python (`prime-agent-runtime/src/rlm/mcp.py` `_headers`, `_bound_auth`). Why: violates invariant 2 (agents never hold a provider key, vault handle, or MCP connection; credentials injected at the egress edge).
3. **Agents hold their own MCP connections.** The `mcp` Python module opens HTTP/stdio transports inside the kernel and calls tools directly; policy is a user allow/deny list, no risk classification, no taint, no per-call log at a gate. Evidence: `prime-agent-runtime/src/rlm/mcp.py` `_Generation._open_http/_open_stdio`, `skills/mcp/SKILL.md` "Errors and permissions". Why: violates invariants 2, 3 and 7 (hub is kernel-only; unknown tools default kernel-only).
4. **Model-writable prompt/memory/subagent state fed back into the system prompt.** `/refine` and `rlm.harness.create_prompt_note(...)` let the model (or an auto-refine gate that is itself a model call) write "supplemental prompt notes" that render into the next system prompt, including global scope. Evidence: `src/core/refinement/refinement.ts` lines 141-155 and 632-637, `src/core/prompts/rlm.ts` line 47. Why: a prompt-injection persistence channel; conflicts with invariant 8 (souls/AGENTS.md read-only to agents) and with "the model never makes an access-control decision" once a note can steer tool use.
5. **Permission gating is an opt-in regex on `bash` text.** `examples/extensions/permission-gate.ts` matches `rm -rf|sudo|777` and ignores `ipython`, so `subprocess.run(...)` bypasses it; default is allow. Why: invariant 3 is default deny with a kernel gate on every call, classified by tool risk, not by string matching.
6. **Audit log is append-only JSONL without tamper evidence.** `src/core/event-log.ts` relies on O_APPEND and a tail rule; no hashing/chaining, no immutability enforcement, and transcripts live in the same user account that runs the agent. Why: invariant 5 requires redaction, canonicalization, hash chaining and SQLite triggers refusing UPDATE/DELETE.
7. **Skills and extensions are trusted native code with full permissions**, installed into the shared kernel venv or loaded as TypeScript; `skill-creator` lets the agent author new executable skills. Evidence: `docs/extensions.md` line 110, `docs/rlm.md` section 3. Why: Phase 5 wants a signed skills repo; agent-authored executable skills would need a human gate and sandboxed execution.

Invariant 7 (unknown MCP tools kernel-only; nested-LLM tools disabled): tool policy is a user allow/deny list; skills may spawn nested agents from Python (`rlm.spawn` inside skills) which do go through the host, so nested LLM calls are logged, but MCP tool exposure is not classified. CONFIRMED (partial conflict).
5. Invariant 8 (souls and AGENTS.md read-only to agents): harness prompt notes and subagent specs are model-writable and rendered into the system prompt. CONFIRMED.

7. Invariant 6 (ephemeral agents bounded by template; promotion is human): children inherit the parent's full tools/skills/model and may pick any credentialed model via `find_models`; there is no tier or egress ceiling. CONFIRMED (`docs/rlm-runtime.md` "Child Execution" step 6).
8. Invariant 4 (two events per LLM call with cost) is partially met: usage/cost is persisted per assistant message and attributed per child, but there is no separate request/response event pair. INFERRED from `docs/rlm-runtime.md` "Usage and Cost Attribution".

## Verdict

Take the orchestration mechanics: admission-only spawn with explicit reply/collect fan-in and parent cost attribution, the daemon-owned spawn ledger as topology source of truth, claim-before-deliver scheduling, bounded autonomous mode with shell quality gates, family-scoped rate-limited agent messaging, the artifact-scored swarm-fanout rubric with cheat fixtures, and the shape (not the writer) of the continual harness: scoped, versioned, rollback-able edits over an immutable base. Leave the entire trust model: user-permission Python kernel, env-inherited provider keys, agent-held MCP connections, regex permission gates, model-writable prompt notes, and un-chained JSONL logs. Net: prime-agent is a strong reference for how the CEO loop, scheduler, and eval harness should behave inside our kernel, and an anti-reference for everything on the credential, gate, and sandbox side.
