## What it is

A "meta-harness" layered on top of Claude Code and Codex: it does not run models itself. Claude Code's `Task` tool spawns the subagents; ruflo contributes agent prompt files, an MCP server with 300+ tools, hooks (PreToolUse/PostToolUse bridge), a vector memory (AgentDB + HNSW + "ReasoningBank"), a swarm coordinator library, a policy engine, cost tracking, and a signed-witness regression system. CONFIRMED `README.md` ("Agent = Model + Harness ... Ruflo is the harness"), `CLAUDE.md` §"Capability Brain": "Ruflo is the coordination ledger and policy decision point. Claude Code executes code ... A Ruflo coordination call records work; it does not perform the implementation."

## Orchestration model

* Coding fleet is a fixed pipeline `researcher -> architect -> coder -> tester -> reviewer`, spawned concurrently as named `Task` subagents that `SendMessage` to the next stage. CONFIRMED `CLAUDE.md` §"Auto-Start Swarm Protocol".
* "Anti-drift" defaults: hierarchical topology, 6-8 agents max, `specialized` strategy, `raft` consensus (leader owns authoritative state), frequent `post-task` checkpoints, short cycles with verification gates. CONFIRMED `CLAUDE.md` §"Anti-Drift Coding Swarm (PREFERRED DEFAULT)".
* Task-type routing table (bug fix -> coordinator/researcher/coder/tester; feature adds architect+reviewer; security -> security-architect+auditor; docs -> mesh/balanced). Swarm auto-invoked only for 3+ files, features, cross-module refactors, API/schema/security/perf changes; skipped for single-file edits. CONFIRMED `CLAUDE.md` §"Agent Routing (Anti-Drift)", §"Task Complexity Detection".
* Worker dependency levels: L0 architect, L1 coder + tester, L2 reviewer, L3 optimizer (only after reviewer approval). CONFIRMED `CLAUDE.md` §"Worker Dependency Levels".
* 3-tier model routing: Tier 1 deterministic codemod ($0, no LLM, TypeScript compiler transforms), Tier 2 Haiku for complexity <30%, Tier 3 Sonnet/Opus. CONFIRMED `CLAUDE.md` §"3-Tier Model Routing (ADR-026, ADR-143)".
* Concurrency rules: never two writers in one worktree; writing agents get an isolated worktree with explicit file ownership; read-only agents may share; only the integration owner edits manifests/lockfiles; "A lease or work claim coordinates ownership; it never grants authority"; "Darwin, Flywheel, MetaHarness, memory, and neural systems may propose and evaluate candidates, but cannot self-promote or expand tools, network, secrets, spend, concurrency, or release authority." CONFIRMED `CLAUDE.md` §"Concurrent Automated Development".
* Queen coordinator (library): task decomposition, complexity score (`0.3 + 0.1*subtasks + 0.05*deps`, priority multiplier), agent scoring `capability*0.30 + load*0.20 + performance*0.25 + health*0.15 + availability*0.10`, consensus modes majority/supermajority/unanimous/weighted/queen-override. All heuristic, no LLM call. CONFIRMED `v3/@claude-flow/swarm/src/queen-coordinator.ts` lines 591-660, 873-891, 1182-1240, 1698-1808.
* Topologies: mesh (default), hierarchical, centralized, hybrid. CONFIRMED `v3/@claude-flow/swarm/src/topology-manager.ts` header + switch cases.
* 12 background worker triggers (audit, testgaps, map, refactor, benchmark, document, consolidate ...). CONFIRMED `v3/@claude-flow/swarm/src/workers/worker-dispatch.ts` header.
* Work claims / handoffs / work-stealing with contest windows, event-sourced (`@claude-flow/claims`, ADR-016). CONFIRMED `v3/@claude-flow/claims/src/index.ts` header.
* Business pods: cron-ticked departmental pods (marketing, sales, finance, hr, exec, support, ops) each with role list, `allowedMcpTools`, `budgetUsdMonthly` / `budgetUsdPerRun`, `cronSchedule`, `bench.successCriteria`, `piiPolicy`, audit read view. Dry-run by default; `--live` refused in the current phase. CONFIRMED `plugins/ruflo-business-pods/templates/marketing.json`, `sales.json`, `scripts/pod-tick.mjs` header.

## Memory model

* AgentDB (SQLite / sql.js / RVF backends) + HNSW index (M=16, efConstruction=200) + MiniLM-L6 384-dim ONNX embeddings; "ReasoningBank" stores `GuidancePattern {strategy, domain, embedding, quality, usageCount, successCount}` and returns agent routing suggestions with historical success rate. CONFIRMED `v3/@claude-flow/hooks/src/reasoningbank/index.ts` header; `v3/@claude-flow/memory/src/` tree (hnsw-index, tiered-memory, consolidator, hybrid-backend).
* Three memory scopes mirroring Claude Code: project (`<gitRoot>/.claude/agent-memory/<agent>/`, committed), local (gitignored), user (`~/.claude/agent-memory/<agent>/`); knowledge transfer between agents filtered by `minConfidence` (default 0.8) and category. CONFIRMED `v3/@claude-flow/memory/src/agent-memory-scope.ts`.
* Read-side defense: `agentdb-retrieval-guard.ts` wraps `ToolOutputGuardrail` over every top-K chunk, oversized chunks (>8 KiB) are flagged/dropped instead of truncated ("truncation would let an attacker pad a payload past the guardrail's own scan window"). OFF by default (`CLAUDE_FLOW_RETRIEVAL_GUARD=true`). CONFIRMED.
* Write-side defense: `memory-poison-forensics.ts` tracks per-principal write timing and content-delta features in a rolling window and flags outliers; its own header admits "AgentDB accepts writes from any swarm agent with no anomaly detection layer at all" and that the repo has "three separate, non-interoperating things called workers". CONFIRMED `v3/@claude-flow/hooks/src/workers/memory-poison-forensics.ts`.
* Agent prompts' `hooks.pre` search memory for similar plans and "failures-only" plans before acting, and `hooks.post` store a reward. CONFIRMED `core/planner.md`.

## Tool / plugin / MCP model

* MCP server exposes 300+ tools (`swarm_init`, `agent_spawn`, `memory_store`, `hooks_route`, `hooks_codemod`, claims tools ...); the docs themselves warn "The CLI reported 333 tools. That count describes the available interface, not 333 capabilities proven in your environment." CONFIRMED `docs/ruflo-explained.md` §13.
* Hooks bridge maps internal events (pre/post tool, edit, read, command, task, route, session, agent-spawn, pattern-learned) onto official Claude Code hooks (PreToolUse, PostToolUse, PermissionRequest, Stop, SubagentStop, PreCompact, SessionStart) and can return `permissionDecision: allow|deny|ask` plus `updatedInput`. CONFIRMED `v3/@claude-flow/hooks/src/bridge/official-hooks-bridge.ts`, `hooks/src/types.ts`.
* Guidance provider hard-blocks edits to `.env/.pem/.key/credentials/secret/password` paths and commands matching `rm -rf`, `drop database`, `push --force`, `reset --hard`; warns on `npm publish`, `git push`, `deploy`, `kubectl apply`. CONFIRMED `v3/@claude-flow/hooks/src/reasoningbank/guidance-provider.ts`.
* Plugins are Claude Code plugins (skills + commands + agents + hooks.json); per-pod `allowedMcpTools` allowlists exist in business-pod templates. CONFIRMED.
* MCP composition inspector: SimHash + word-shingle detector for injection payloads split across several tool descriptions (ShareLock attack); warn+log by default, blocking opt-in via env. CONFIRMED `v3/@claude-flow/security/src/mcp-composition-inspector.ts`.
* `ToolOutputGuardrail`: deterministic, sub-ms, no-LLM pattern scan of tool results / memory reads / API responses with categories instruction-override, role-hijack, exfiltration, jailbreak, hidden-unicode, embedded-system, tool-spoofing, truncation; caller picks allow/flag/redact/reject. CONFIRMED `v3/@claude-flow/security/src/tool-output-guardrail.ts`.

## Sandbox & security posture

* Isolation: none of its own. It relies on Claude Code's / Codex's sandbox. The generated Codex config ships a `[profiles.dev]` with `approval_policy = "never"` and `sandbox_mode = "danger-full-access"`, and CI with `approval_policy = "never"`; only `safe`/`production` profiles use `untrusted` approvals. CONFIRMED `v3/@claude-flow/codex/src/generators/config-toml.ts` lines 570-700.
* Credentials: shell-environment policy excludes `*_KEY, *_SECRET, *_TOKEN, *_PASSWORD` from Codex env (CONFIRMED same file). But `payments/agentic-payments.md` instructs the agent to call `sign_mandate({ private_key_hex })`, i.e. a private key flows through agent context (CONFIRMED). `github/code-review-swarm.md` runs `gh auth status` in the agent's own shell (CONFIRMED).
* Policy engine (`AgenticPolicyEngine`): modes `legacy | observe | enforce`; effects `allow | deny | require_approval`; deny wins, then approval, then allow; no match => `default-deny` unless mode is `legacy` (`legacy-default-allow`); in `observe` the `enforcedOutcome` is always `allowed`. Capability envelopes (actions/resources/tools/servers/read+write namespaces/environments/maxCostUsd/maxTokens/maxConcurrency/network/destructive/delegationDepth/expiresAt) are checked BEFORE rules and a crossing "is always blocked, including legacy installations". `delegateEnvelope` decrements `delegationDepth`, takes min expiry, and throws `capability-envelope-cannot-grow` if the child is not a strict subset. Evidence carries provenance (`user_claim | agent_output | system_observation | tool_result`) and may require signatures; approvals have issuer, expiry, `maxUses`, revocation; every decision appends a hash-chained receipt (`previousReceiptHash`, `sequence`) that can be verified. CONFIRMED `v3/@claude-flow/security/src/policy/{types,evaluator,envelope,engine}.ts`.
* Verification: Ed25519-signed "witness" manifests attest that the load-bearing line of every documented fix still exists (SHA-256 + marker substring), per OS, with JSONL temporal history; CI `witness-verify` blocks publish. Performance baselines per capability in `performance.jsonl`. CONFIRMED `verification/README.md`, `verification/CAPABILITIES.md`.
* Metaharness plugin: 5-dim readiness scorecard (harnessFit/compile/coverage/safety/memory + cost), static MCP security scan, threat model, drift-from-history; must remain removable (CI runs with `--no-optional`). CONFIRMED `plugins/ruflo-metaharness/README.md`.
* Cost control: per-agent/per-model USD attribution, budget ladder 50/75/90/100% with hard stop (exit 1), burn-rate, MAD anomaly detection, counterfactual vs always-haiku/sonnet/opus, PR cost diff; captured from the Claude Code session JSONL after the fact via a Stop hook. CONFIRMED `plugins/ruflo-cost-tracker/README.md`.
* Federation: signed Nostr events over a membership-gated relay; the gateway "holds no channel keys and cannot decrypt" private channels. CONFIRMED `plugins/ruflo-x-gateway/README.md`.
* Supply chain: the trading plugin's dependency `neural-trader` <=2.7.1 had an install hook that fork-bombed (120 GB RAM on Apple Silicon); README mandates `--ignore-scripts` and a CI guard enforces it. CONFIRMED `plugins/ruflo-neural-trader/README.md`.

## BEST PARTS

1. **Capability envelopes that only shrink on delegation, checked before any rule, unaffected by mode.** Evidence: `v3/@claude-flow/security/src/policy/envelope.ts` (`delegateEnvelope`, `isEnvelopeReduction`, `delegation-depth-exhausted`), `policy/evaluator.ts` lines 70-85. Sector: kernel. Why: this is exactly invariant 6 (ephemeral agents cannot exceed their template) expressed as data: a child run's tools/servers/namespaces/cost/tokens/concurrency/network/destructive/expiry must be a subset of the parent's, depth decrements, and the check runs even when policy is in observe mode. Our `agents/<id>/agent.yaml` templates and ephemeral spawn should carry an envelope with these exact fields, and the gate should refuse spawn when the child envelope is not a reduction.
2. **Policy decisions as hash-chained, signed receipts with evidence provenance and single-use, expiring human approvals.** Evidence: `policy/types.ts` (`PolicyEvidence.provenance`, `PolicyApproval.maxUses/expiresAt/revokedAt`, `obligations: ['valid-human-approval']`), `policy/engine.ts` lines 146-161 (`previousReceiptHash`, receipt chain verify). Sector: kernel. Why: our event log already hash-chains; adding an `approval` record with `maxUses`, TTL and issuer, plus tagging evidence as `user_claim` vs `tool_result` vs `agent_output`, closes the "agent claims the human said yes" hole and makes `require_approval` rules replayable from the log (Phase 1 restart-safe projections).
3. **Deterministic, no-LLM content guardrail at every boundary (tool result, memory read, API response) with flag/redact/reject actions, plus a size gate that refuses to truncate.** Evidence: `security/src/tool-output-guardrail.ts` header (threat model, scope, non-goals), `memory/src/agentdb-retrieval-guard.ts` (`maxPayloadBytes`, "truncation would let an attacker pad a payload past the guardrail's own scan window"). Sector: ops-security (comms / tainted ingress) and kernel. Why: fits invariant 3's quarantine step: a sub-ms pattern pass is the right first taint classifier for Telegram/SMS/web content and pmmcp recall results, before anything reaches a model; the never-truncate rule is a concrete bug our `MAX_LOGGED_OUTPUT` path must avoid.
4. **Anti-drift coding swarm shape: hierarchical, 6-8 agents, fixed role pipeline researcher -> architect -> coder -> tester -> reviewer, dependency levels, one integration owner, isolated worktree per writer, swarm only above a complexity threshold.** Evidence: `CLAUDE.md` §"Anti-Drift Coding Swarm", §"Auto-Start Swarm Protocol", §"Worker Dependency Levels", §"Concurrent Automated Development", §"Task Complexity Detection". Sector: engineering. Why: this is the tested answer to "we need a fleet of coding agents": small, role-bounded, leader-owned state, no two writers in one checkout, and a rule for when NOT to fan out. Maps directly onto our T2 coder with one CEO-owned integration lane and ephemeral `worker` templates per file-ownership set.
5. **3-tier routing with a $0 deterministic tier before any model, and cost accounting as a CI gate (budget ladder with hard stop, burn-rate, anomaly, counterfactual vs fixed-model baselines).** Evidence: `CLAUDE.md` §"3-Tier Model Routing (ADR-026, ADR-143)", `plugins/ruflo-cost-tracker/README.md` (`cost-budget-check` exit 1 on HARD_STOP, `cost-counterfactual`, `cost-burn`, `cost-anomaly`, `cost-diff`). Sector: executive (budgets) and engineering. Why: our router already binds models per agent; adding "codemod/regex/AST first, Haiku-class second, frontier third" plus a per-run/per-day budget ladder that the kernel enforces (not an agent) is cheap and gives the operator the counterfactual numbers to justify model choices.
6. **Signed witness manifests: attest that each documented fix's load-bearing line still exists, per OS, with temporal history, blocking publish on drift.** Evidence: `verification/README.md`, `verification/witness-fixes.json`, `verification/CAPABILITIES.md`. Sector: engineering (verification gate) and kernel (auditor agent). Why: our auditor agent needs something mechanical to check besides "tests pass"; a marker manifest for invariants (loopback bind, `--cap-drop=ALL`, SQLite immutability triggers, `kernel-only` defaults) catches an agent quietly deleting a guard line even when tests still pass.
7. **Business pods as declarative departmental templates: roles, `allowedMcpTools`, monthly and per-run USD budgets, cron, bench success criteria, PII policy, audit view, drafts "for human review", dry-run default with `--live` refused until the gate work lands.** Evidence: `plugins/ruflo-business-pods/templates/marketing.json`, `sales.json`, `scripts/pod-tick.mjs` header. Sector: growth (marketing, sales, social). Why: it is the cleanest small design for the operator's marketing/sales ask: each department is a manifest with a tool allowlist and a budget, outputs are drafts routed to a human, and the pod cannot go live until the gates exist, which mirrors our phase ordering (Phase 2 before Phase 4).
8. **Split-payload MCP tool-description inspection and "registered / configured / reachable / healthy / authorized are separate facts".** Evidence: `security/src/mcp-composition-inspector.ts` header, `CLAUDE.md` §"Capability Brain", `docs/ruflo-explained.md` §13. Sector: ops-security / kernel (MCP hub). Why: Phase 2 adds GitHub/Vercel/Supabase MCP servers with schema-hash pinning; adding a cheap cross-tool description overlap check and a five-state server status in the hub's views is low cost and closes a class of attack we had not listed.

## BAD PARTS / anti-patterns

1. **Agent definitions carry `hooks.pre/post` shell snippets with unquoted `$TASK` interpolation and a self-computed "reward" (`REWARD = (TASKS_COUNT + AGENTS_ALLOCATED)/30`, `SUCCESS` if more than 3 tasks) fed back into "self-learning".** Evidence: `v3/@claude-flow/cli/.claude/agents/core/planner.md` hooks block. INFERRED: no in-repo runtime executes those frontmatter hooks (grep for a hooks.pre executor found only init/template code). Why left out: shell in prompt-file frontmatter is a command-injection surface and unauditable; rewarding plan size teaches the planner to over-decompose. Our runs log and score against acceptance tests, never against self-reported counts.
2. **The model is placed in the access-control loop.** `v3/claims-authorizer.md` is an LLM agent whose prompt says it "enforces fine-grained access control"; the queen resolves decisions by majority/weighted/unanimous votes of agents and has `queen-override` for `emergency-action` and `agent-termination`. Evidence: `.claude/agents/v3/claims-authorizer.md`, `swarm/src/queen-coordinator.ts` lines 1698-1808. Why left out: violates our invariant 3 outright; a vote among LLM agents is not a gate, and an agent that can "terminate agents" is an authority we reserve for the kernel and the human.
3. **Credentials and irreversible actions inside agent context.** `payments/agentic-payments.md` has the agent pass `private_key_hex` to a signing tool and "authorize AI agents for purchases"; `github/code-review-swarm.md` runs `gh auth status` in-agent; generated Codex `dev` profile is `approval_policy="never"` + `sandbox_mode="danger-full-access"`, CI is `approval_policy="never"`. Evidence: those files; `codex/src/generators/config-toml.ts` lines 670-700. Why left out: invariants 2 and 3 forbid all of it; payments/trading stay behind the egress proxy with kernel-side signing and `irreversible => human`.
4. **Safety features default off or non-enforcing.** Policy engine mode `legacy` = default allow; `observe` sets `enforcedOutcome: 'allowed'`; retrieval guard off unless `CLAUDE_FLOW_RETRIEVAL_GUARD=true`; composition inspector warn-only unless `CLAUDE_FLOW_MCP_COMPOSITION_BLOCK=1`; poison forensics can be disabled by env. Evidence: `policy/evaluator.ts` lines 115-119, `memory/src/agentdb-retrieval-guard.ts` header, `security/src/mcp-composition-inspector.ts` header, `hooks/src/workers/memory-poison-forensics.ts` header. Why left out: our gate is default deny and has no legacy mode; env-var kill switches for security are exactly the "bypass for testing" CLAUDE.md forbids.
5. **Sprawl and unverifiable capability claims.** 89 agent prompt files (with duplicates such as `analysis/analyze-code-quality.md` vs `analysis/code-review/analyze-code-quality.md`), 35 plugins, 300+ MCP tools; prompts advertise "GNN-enhanced", "Flash Attention", "EWC++", "SONA <0.05ms" as agent capabilities; the maintainers' own header says the repo has "three separate, non-interoperating things called workers" and the docs concede tool counts are not capability proofs. Evidence: `cli/.claude/agents` listing, `core/planner.md`, `hooks/src/workers/memory-poison-forensics.ts` header, `docs/ruflo-explained.md` §13. Why left out: our roster must stay small enough that every agent has a manifest, a soul, an eval, and a tier; marketing adjectives in prompts cost tokens and mislead the planner.
6. **Shared writable memory from any agent, and agent prompt files living in a directory agents can write.** AgentDB accepts writes from any swarm agent (admitted in `memory-poison-forensics.ts`); agent definitions live in `.claude/agents/` and agents such as `code-review-swarm` are given `Write`. Evidence: same file; `github/code-review-swarm.md` `tools:` list. Why left out: invariant 8 makes souls/AGENTS.md read-only to runs; memory writes go through pmmcp via the hub with per-agent `project_id` namespaces and a quarantine step, never a shared free-for-all.
7. **Trading sector built on an unaudited native npm dependency with a fork-bomb history and heavy cloud offload.** Evidence: `plugins/ruflo-neural-trader/README.md` (install-hook fork bomb, 120 GB RAM, `--ignore-scripts` mandatory, Managed-Agent cloud backtests). Why left out: for our trading sector we take only the shape (data-engineer ingest + pattern index + strategy/risk roles, backtests in T3 no-egress, orders behind `irreversible`), not the package.

## Conflicts with CLAUDE.md invariants

1. Invariant 3 (the model never makes an access-control decision): `claims-authorizer` agent, queen consensus voting and `queen-override`, agent-driven payment authorization.
2. Invariant 2 (agents never hold credentials): `agentic-payments.md` private key in tool args, `gh auth` in agent shell, Codex `danger-full-access` dev profile.
3. Invariant 3 / 7 (default deny): policy engine `legacy` default-allow and `observe` non-enforcement; guardrails opt-in by env var.
4. Invariant 9 (container hardening): ruflo has no sandbox of its own; it inherits Claude Code/Codex sandboxes, one generated profile of which disables the sandbox.
5. Invariant 8 (souls and AGENTS.md read-only): agent prompt files are ordinary workspace files under `.claude/agents/`, and review agents are granted `Write`.
6. Invariant 4 (every LLM call is two logged events with cost): ruflo cannot see model calls made by Claude Code's Task subagents; cost is reconstructed from the session JSONL after the fact by a Stop hook.
7. Invariant 5 (redacted, hashed, chained log): only policy receipts are chained; memory writes and swarm events are not, and any agent may write memory.
8. Invariant 6 (ephemerals bounded by template): supported in `envelope.ts`, but not wired as the default path; the prompt-level coordinators spawn agents with free-form `--capabilities` strings.

## Verdict

Take the capability-envelope subset-on-delegation rule, hash-chained approval receipts with evidence provenance and single-use TTL approvals, the deterministic content guardrail with a never-truncate size gate, the anti-drift 6-8 agent hierarchical coding pipeline with one integration owner and worktree-per-writer, tiered $0-first model routing with a kernel-enforced budget ladder, signed witness markers for invariants, and business pods as declarative department manifests with tool allowlists and USD budgets. Leave the prompt-frontmatter shell hooks and self-scored rewards, LLM agents as authorizers or voters on access, credentials in agent context, `approval_policy=never` sandbox profiles, opt-in security, the 89-agent/300-tool sprawl, shared writable agent memory, and the `neural-trader` dependency. Net: ruflo is a rich idea mine for the kernel's policy and cost layers and for the coding-fleet shape, but its security posture is the anti-pattern we already reject in OpenClaw, so we copy data shapes and rules, never its execution model.
