## What it is

Two products on one framework. **UI-TARS Desktop** is an Electron app that drives a local computer, a remote cloud computer, or a browser with the UI-TARS vision-language model: screenshot -> model emits `Thought:/Action:` -> operator executes a click/type/scroll -> repeat (`packages/ui-tars/sdk/src/GUIAgent.ts`). **Agent TARS** is a general multimodal agent (CLI + Web UI + headless server) built on **Tarko**, a small agent kernel with an event stream, pluggable tool-call engines, MCP integration, snapshot-based testing, and a hybrid DOM+vision browser control mode (`multimodal/tarko/*`, `multimodal/agent-tars/core`). **omni-tars** composes GUI, code (AIO sandbox bash/editor/jupyter), and MCP capabilities into one agent via plugins (`multimodal/omni-tars/*`). CONFIRMED

## Orchestration model

Single-agent loop; no multi-agent delegation, no roles, no CEO/worker topology. CONFIRMED (no delegate/subagent code found in `multimodal/tarko/agent/src`, `multimodal/agent-tars/core/src`).

* **v1 GUI loop** (`packages/ui-tars/sdk/src/GUIAgent.ts` L128-455): while loop bounded by `maxLoopCount` (default `MAX_LOOP_COUNT = 100`, `packages/ui-tars/shared/src/constants/vlm.ts`) and `MAX_SNAPSHOT_ERR_CNT = 10`; each turn: `operator.screenshot()` (async-retry) -> validate image with Jimp -> `toVlmModelFormat` + `processVlmParams` sliding window of the last `MAX_IMAGE_LENGTH = 5` screenshots -> `model.invoke` (async-retry, 30 s min backoff) -> parse predictions -> for each parsed action: internal actions `error_env`/`max_loop` abort, `call_user` sets `StatusEnum.CALL_USER` and breaks, `finished` ends; otherwise `operator.execute(...)`. Optional `loopIntervalInMs` sleep. Pause/resume/stop are first-class (`pause()`, `resume()`, `stop()` L495-520; a `user_stop` action is dispatched to the operator in `finally`, L465). Per-turn timing and token accounting are attached to every conversation entry (`timing.cost`, `costTokens`). CONFIRMED
* **Tarko loop** (`multimodal/tarko/agent/src/agent/runner/loop-executor.ts`): iteration loop up to `maxIterations`; `abortSignal` check; `agent.isLoopTerminationRequested()`; `onBeforeLoopTermination(sessionId, finalEvent)` lets a higher-level agent veto the model's "I am done" and force continuation; `onEachAgentLoopEnd` hook. Tool execution in `runner/tool-processor.ts`: `onProcessToolCalls` may intercept and replace execution entirely (L165-236), otherwise sequential `onBeforeToolCall` (may rewrite args) -> `executeTool` -> `onAfterToolCall` (may rewrite result) -> `onToolCallError`. The full hook surface is in `multimodal/tarko/agent-interface/src/agent.ts` L145-312 (`onLLMRequest`, `onLLMResponse`, `onLLMStreamingResponse`, `onBeforeToolCall`, `onAfterToolCall`, `onToolCallError`, `onEachAgentLoopStart/End`, `onAgentLoopEnd`, `onProcessToolCalls`, `onBeforeLoopTermination`, `onPrepareRequest`). CONFIRMED
* **Tool-call engines** (`multimodal/tarko/agent/src/tool-call-engine/`): `NativeToolCallEngine`, `PromptEngineeringToolCallEngine`, `StructuredOutputsToolCallEngine`; omni-tars adds a `ComposableToolCallEngine` that routes by environment (`multimodal/omni-tars/core/src/ComposableToolCallEngine.ts`). CONFIRMED
* **Composition** (`multimodal/omni-tars/core/src/AgentComposer.ts`, `AgentPlugin.ts`): plugins contribute tools + an `environmentSection` of system prompt; the composer concatenates them and fans hooks out to each plugin in order. Plan events exist in the event schema (`plan_start/plan_update/plan_finish`, `multimodal/tarko/agent-interface/src/agent-event-stream.ts` L69-71). CONFIRMED

## Memory model

No long-term memory. Per-run context = event stream (`multimodal/tarko/agent/src/agent/event-stream.ts`) rebuilt into messages by `MessageHistory` with an optional `maxImagesCount` that replaces the oldest images with placeholders (`multimodal/tarko/agent/src/agent/message-history.ts` L36-193). v1 uses a 5-image sliding window (`processVlmParams`, `packages/ui-tars/sdk/src/utils.ts` L58-73). `@tarko/context-engineer` has image compression, `@`-reference resolution, and workspace packing (`multimodal/tarko/context-engineer/src/node/*`). Server persistence of sessions/events via `File|Memory|SQLite|MongoDB` storage providers (`multimodal/tarko/agent-server/src/storage/`). INFERRED: nothing cross-session beyond replaying stored events. CONFIRMED for the listed files.

## Tool / plugin / MCP model

* `MCPAgent` connects to every configured server at init, lists tools, and registers each as a first-class `Tool` whose `function` calls `mcpClient.callTool` directly (`multimodal/tarko/mcp-agent/src/mcp-agent.ts` L45-96). Include/exclude glob filters exist at the server level (`filterMCPServers`) and the tool level (`multimodal/tarko/agent/src/utils/tool-filter.ts`). No risk classes, no default-deny; an unknown tool is simply registered. CONFIRMED
* Own MCP servers: browser (23 tools incl. `browser_evaluate`, `browser_vision_screen_capture/click`, `packages/agent-infra/mcp-servers/browser/src`), commands, filesystem, search. The browser server has a blocklist/allowlist origin option that is commented out (`packages/agent-infra/mcp-servers/browser/src/index.ts` L45). CONFIRMED
* **Hybrid browser control** (`multimodal/agent-tars/core/src/environments/local/browser/browser-control-strategies/browser-hybrid-strategy.ts`): registers the vision tool `browser_vision_control` (schema `{thought, step, action}` with a textual action space, `browser-gui-agent.ts` L95-135) alongside DOM tools (`browser_click`, `browser_form_input_fill`, `browser_get_clickable_elements`, `browser_evaluate`, tabs...) and content tools (`browser_get_markdown`, links). `validateBrowserControlMode` falls back to `dom` when the model is not a supported VLM (`browser-control-validator.ts` L23-52). CONFIRMED
* Operator contract: `screenshot(): {base64, scaleFactor}` and `execute({parsedPrediction, screenWidth, screenHeight, scaleFactor, factors})`, plus `static MANUAL.ACTION_SPACES` that is spliced into the system prompt (`packages/ui-tars/sdk/src/types.ts` L67-75, `docs/sdk.md`). CONFIRMED
* Evals: `@tarko/agent-snapshot` records real LLM/tool traffic with hooks and replays it deterministically as vitest fixtures, with a normaliser for volatile fields (`multimodal/tarko/agent-snapshot/src/agent-snapshot.ts`, `agent-generate-snapshot-hook.ts`, `agent-replay-snapshot-hook.ts`, `utils/snapshot-normalizer`). `@tarko/agio` defines an operational-metrics event schema (`agent_ttft`, loop/tool events; `multimodal/tarko/agio/src/index.ts`). CONFIRMED

## Sandbox & security posture

* **Isolation**: local desktop operator runs nut.js against the operator's real session with full user privileges; the only gate is macOS Accessibility/Screen Recording permission prompting (`apps/ui-tars/src/main/utils/systemPermissions.ts` `ensurePermissions`). Remote computer/browser operators run in a ByteDance-hosted sandbox reached through `PROXY_URL` with a device-registered bearer token (`apps/ui-tars/src/main/remote/auth.ts` L73-97, `proxyClient.ts`). Agent TARS "AIO sandbox" mode disables all local resource operations and routes bash/editor/browser through a remote streamable-HTTP MCP sandbox (`multimodal/agent-tars/core/src/environments/aio/index.ts` L11-60). No Docker/cgroup hardening in-repo. CONFIRMED
* **Credentials**: the desktop app stores `vlmApiKey` in a plain `electron-store` without `encryptionKey`/`safeStorage` (`apps/ui-tars/src/main/store/setting.ts` L40; schema `store/validate.ts` L20) and logs the entire old/new settings object with `JSON.stringify` on any change (`setting.ts` L45-48), so the key lands in the app log. Presets (YAML incl. `vlmApiKey`, `examples/presets/default.yaml` L5) can be auto-synced from a remote URL (`docs/preset.md`). The model receives raw tool results and the agent process holds the MCP clients and provider key. CONFIRMED
* **Gates / HITL**: none at the tool level. The model self-selects `call_user()` when stuck (`packages/ui-tars/sdk/src/constants.ts` action space) and the app pauses with `StatusEnum.CALL_USER` (`apps/ui-tars/src/main/services/runAgent.ts` L150); humans get pause/resume/stop buttons and a transparent "screen water-flow" overlay + prediction marker showing where the agent will click (`apps/ui-tars/src/main/window/ScreenMarker.ts` L27-81). Tarko's `onBeforeToolCall` is the only place a policy could be inserted; nothing ships. Server has CSRF and an `exclusive-mode` middleware (409 while a session runs) (`multimodal/tarko/agent-server/src/api/middleware/`). CONFIRMED
* **Egress**: none; the browser MCP allow/block-list is commented out; `browser_evaluate` (arbitrary JS in page) is exposed to the model in hybrid mode. CONFIRMED

## BEST PARTS

1. **Operator abstraction (`screenshot()` / `execute()` / `MANUAL.ACTION_SPACES`)** — `packages/ui-tars/sdk/src/types.ts` L67-75, `docs/sdk.md`. Sector: engineering (prototyper QA) + growth (web ops). One tiny interface makes desktop, browser, Android, remote-sandbox, and cloud-browser interchangeable; the action space is data spliced into the prompt, so a T3 "hostile" browser operator and a T2 "trusted" one differ only by construction. Fits invariant 9 (operator lives in the worker; the kernel only sees actions).
2. **Bounded screenshot loop with explicit terminal actions** — `packages/ui-tars/sdk/src/GUIAgent.ts` L128-455 (`maxLoopCount`, `MAX_SNAPSHOT_ERR_CNT`, `call_user`, `finished`, `error_env`, `user_stop`, per-turn `timing`/`costTokens`, 5-image sliding window). Sector: engineering + kernel. This is the shape of a GUI run we can log as `llm.request`/`llm.response` pairs with cost (invariant 4) and hard caps (never disable retry/wallclock caps).
3. **Hybrid DOM + vision browser control with capability fallback** — `browser-hybrid-strategy.ts`, `browser-control-validator.ts`, `browser-gui-agent.ts` (`browser_vision_control` + `browser_get_markdown` + `browser_get_clickable_elements`). Sector: growth (web ops, competitor research, form filling), sales (live demo driving), prototyper QA (click-through of a Tauri/React build). Text/DOM tools are cheap and auditable; vision is the fallback for canvas/complex UIs; the validator downgrades to DOM when the bound model is not grounding-capable, which mirrors our `aos probe` binding rule.
4. **Tool-call interception hooks at the exact gate point** — `multimodal/tarko/agent/src/agent/runner/tool-processor.ts` L165-236 (`onProcessToolCalls`), L263 (`onBeforeToolCall` may rewrite args), L312 (`onAfterToolCall` may rewrite results); `onBeforeLoopTermination` in `loop-executor.ts`. Sector: kernel. The pattern (not the code) is what our run loop needs: a single choke point where policy gate -> approval -> quarantine -> execute -> log is enforced, plus a kernel-side veto over "done".
5. **Snapshot record/replay for agent tests** — `multimodal/tarko/agent-snapshot/src/*` with normaliser. Sector: engineering + kernel (Phase 1 eval harness). Record one live GUI/browser run, replay it deterministically against the mock hub; ideal for the "in-process mock MCP server" and "eval harness scoring orchestration" exit criteria.
6. **Visible-intent overlay for human oversight** — `apps/ui-tars/src/main/window/ScreenMarker.ts` (transparent border while the agent controls the screen, marker at the predicted click). Sector: ops-security + executive (Ops Deck / Run Inspector). Cheap, honest signal of "an agent is driving right now" for the Tauri/SwiftUI shell; pairs with pause/resume/stop.
7. **Environment-plugin composition of one agent** — `multimodal/omni-tars/core/src/AgentComposer.ts`, `AgentPlugin.ts`. Sector: engineering (coding fleet). A worker's capabilities = ordered plugins each owning tools + a prompt section; maps cleanly onto our manifest `tools:` blocks and tool-view exposure rather than one monolithic agent.
8. **Typed event stream + Agio metrics schema** — `multimodal/tarko/agent-interface/src/agent-event-stream.ts` (`tool_call`, `tool_result`, `environment_input`, `plan_*`, `final_answer`), `multimodal/tarko/agio/src/index.ts` (`agent_ttft`, loop/tool events). Sector: kernel + executive. Confirms our event-log-first design; `environment_input` (screenshot as an event) and `plan_update` are two event kinds our protocol v1 will want when the GUI worker lands.

## BAD PARTS / anti-patterns

1. **Plaintext provider key in electron-store, logged on every change** — `apps/ui-tars/src/main/store/setting.ts` L40-48, `store/validate.ts` L20. Violates our "never log a secret value" and invariant 2; secrets belong in the pmmcp vault behind the broker.
2. **Remote presets auto-synced from a URL, carrying `vlmApiKey`** — `docs/preset.md`, `examples/presets/default.yaml` L5. A remote config that rewrites model endpoint + key is a supply-chain hole; our config is local data, no secrets, reviewed in git.
3. **Model-chosen `call_user()` is the only human gate; no per-action policy** — `packages/ui-tars/sdk/src/constants.ts`, `apps/ui-tars/src/main/services/runAgent.ts` L150; no `onBeforeToolCall` policy shipped in `tool-processor.ts`. Invariant 3: the model never makes an access-control decision; irreversible GUI actions (send, pay, delete) must be gated by the kernel, not by the model volunteering.
4. **Agent process holds MCP clients and calls tools directly; unknown tools auto-registered** — `multimodal/tarko/mcp-agent/src/mcp-agent.ts` L45-96. Invariants 2 and 7: hub is kernel-only; unknown tools default to `kernel-only`.
5. **Local desktop operator = agent with the operator's full session (nut.js), no isolation, no egress control; `browser_evaluate` exposed; browser allow/blocklist commented out** — `packages/ui-tars/operators/nut-js/src/index.ts`, `browser-hybrid-strategy.ts` tool list, `packages/agent-infra/mcp-servers/browser/src/index.ts` L45. Our GUI worker must run in T2/T3 (Xvfb/Chromium in Docker or a remote sandbox) with the proxy allowlist; local `nut-js` on the operator's Mac stays off the table until Phase 5, and `browser_evaluate` is `kernel-only` or disabled.
6. **Errors swallowed into a status field instead of thrown; sequential retries with fixed 30 s backoff; model can loop up to 100 turns** — `GUIAgent.ts` L420-445 (`// throw error;` commented out), `MAX_LOOP_COUNT = 100`. Our standard: throw with context, log, hard budget/wallclock; a GUI run should default to far fewer turns and surface `run.failed`.
7. **Telemetry to hosted endpoints (UTIO, report storage) on by config** — `packages/ui-tars/utio/src/index.ts` L20, `store/setting.ts` (`utioBaseUrl`, `reportStorageBaseUrl`). Local-first means no default outbound telemetry; if ever added it goes through the egress proxy and the event log.

## Conflicts with CLAUDE.md invariants

1. Inv. 2 (no agent holds MCP/provider credentials): `MCPAgent` owns clients and the key; desktop app stores the key in plaintext.
2. Inv. 3 (gate on every tool call, model never decides access): only `call_user()` exists; no default deny; no irreversible class.
3. Inv. 5 (redacted, hashed, chained log): event stream is in-memory/optional storage, no hashing or immutability; settings logger prints secrets.
4. Inv. 7 (unknown tools kernel-only): every MCP tool is auto-registered to the model.
5. Inv. 9 (container hardening, confined mounts): local operators run on the host; sandbox is a remote vendor service, not a hardened local container.
6. Change-control rule "never disable wallclock/budget caps": loop cap is 100 turns with no cost budget.

## Verdict

Take the operator interface, the bounded screenshot/act loop with explicit terminal actions and per-turn cost, the hybrid DOM+vision browser toolset with capability fallback, the single tool-call choke point + loop-termination veto, snapshot record/replay for evals, and the visible-intent overlay: these give us a `gui-operator` worker (T2 Chromium in Docker for prototyper QA, growth web ops and sales demo driving; T3 for untrusted sites) whose every action is a gated, logged tool call. Leave the credential handling, remote presets, model-chosen human gate, direct MCP ownership, host-level nut.js control, `browser_evaluate`, and hosted telemetry. Nothing here is a fleet or memory design; it is a hands-and-eyes layer we mount under our kernel, never beside it.
